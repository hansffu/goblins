exec.signal is a host-client-to-daemon notification, with no id, only during an active exec. Named {signal:I32} or positional [I32] accepts SIGHUP=1, SIGINT=2, SIGTERM=15. Outside active exec, all no-id client notifications are ignored after envelope parsing; a host request with id and method exec.signal is unknown (-32601). * Protocol behavior

- =framing= :: Content-Length; 256-byte headers; duplicate keys and depth >32 rejected. See docs/API.org transport rules.
- =request_id= :: 1–64 ASCII letters/digits/underscore/hyphen, or unsigned integer <=9007199254740991. No null/boolean/fractional IDs. Notifications omit ID.
- =notification_policy= :: Ordinary notifications are ignored; active exec and attach have their own exchanges.
- =connections= :: Host: 4096 calls including initialize. Sandbox: initialize then one call, up to 8 connections.
- =initialization= :: Parameters are checked before repeated-initialize conflict, then unsupported-version refusal. api accepts u32; supported version is 1. configuration is null on host and the configuration key on sandbox (null if unavailable).
- =server_control= :: Host only. Both remain available during shutdown. stop flushes acceptance then closes its connection and completes cleanup asynchronously.
- =parameter_forms= :: C01 methods accept named objects or positional arrays: initialize accepts {api:N} or [N], server methods accept {} or []. Omitted params default to {}. Preserve Serde refusal order.
- =result_extensions= :: Result objects, including nested limits and history variants, may gain fields. Clients ignore unknown result fields; known fields and history owner discrimination remain validated. Request parameters stay closed.
- =api1_compatibility= :: Producer result schemas describe the current daemon precisely. x-client-result-schema describes compatible API-1 replies accepted by clients: configuration/limits and newer server.status history/manifest/worktree metadata may be absent. Clients retain absence as optional data and use advertised features rather than inventing values.
- =self_reporting= :: sessions.status exposes only the caller and its policy/activity. Worktree paths are deliberately visible. Activity is independent of lifecycle; variables update atomically and empty values remove keys. Missing or null set-worktree name clears the record; names are validated before filesystem access.
- =session-records= :: Current session read producers emit complete endpoint-specific records. Host sessions include descriptor-free process identities and host paths; sandbox records exclude them, except the intentionally shared Worktree.path. API-1 reader schemas retain the defaults and omissions previously accepted by Rust snapshot clients. The controller retains domain records; explicit projections and a generated-read adapter preserve snapshot consumers until C15. Nested terminal and raid summaries are typed public data; their methods migrate in C05 and C11.
- =launch-lifecycle= :: Launch keys bind endpoint actor and decoded parameters; identical retries return the original acceptance, including during recreate after the record becomes reserved. Recreate record resolution precedes normal launch validation. Acceptance state starting is not readiness. Public DTOs contain no recorded-history capability or host-selectable member worktree. Sandbox start uses current owner/run-target policy and fixed member launch arguments. Stop acceptance is not completed cleanup; host resize uses an exact session id, and sandbox detach closes its one-shot connection after acceptance. Sandbox sessions.attach remains refusal-only (-32601), before its existing trailing-input handling.
- =positional-parameters= :: Method descriptors retain original Serde field order. Generated structs are named DTOs; decode_params<M> maps positional arrays to those names before generated decoding because Typify sorts struct fields. Optional omissions and trailing defaults remain the original ones. Schema defaults do not authorize or perform lifecycle transitions. Nullable fields without an original Serde default still require an array position; x-positional-required records this independently of named-object optionality. Member launch requires its third agent_name position (null is valid); set-worktree requires [name] or [null], while {} still clears it.
- =exec-descriptors= :: Host sessions.exec carries SCM_RIGHTS with the first byte of its frame: one PTY slave when tty=true, otherwise stdin/stdout/stderr in that order. No descriptor numbers appear in JSON. The existing host connection budget is three accumulated descriptors, including fragmented reads. The call takes and closes all received descriptors on refusal and transfers stdio only after validation.
- =exec-lifecycle= :: Host-only exec waits for process completion and then closes its connection. Parameter and command validation precede descriptor-count, target/pin, policy, 64-exec capacity and init-availability checks, in that order; the existing canonical init-spawn 64 KiB check remains after ID allocation and before stdio transfer. Disconnect cancels only execs on that connection. kill_execs resolves dots as slashes and sends best-effort KillAll; accepted does not mean all commands have ended.
- =exec-signal= :: exec.signal is a host-client-to-daemon notification, with no id, only during an active exec. Named {signal:I32} or positional [I32] accepts SIGHUP=1, SIGINT=2, SIGTERM=15. Missing, invalid or unsupported signals, an unexpected method, or any id close the active-exec connection; cleanup cancels its exec only. Outside active exec, all no-id client notifications are ignored after envelope parsing; a host request with id and method exec.signal is unknown (-32601). It is never a callable method or sandbox capability.

* Generation exceptions

- =EmptyParams= :: Typify represents empty closed objects as maps; use a handwritten deny_unknown_fields empty struct to preserve the existing Serde decoder, including [] as well as {}. Null and unknown fields remain refused.
- =required-nullable= :: Typify/Serde Option accepts absence as null. Response::decode explicitly checks required nullable result fields before deserialization. Producers emit null rather than omitting; schema response validation checks the same presence rule.
- =validation= :: Type generation is not JSON Schema validation: constraints such as byte lengths remain named handwritten validators; tests check schema agreement.
- =protocol= :: Framing, duplicate keys, request IDs, deadlines and connection state remain in libs/jsonrpc and controller; generated DTOs never authorize calls.
- =boolean-enum= :: Typify 0.7 emits bool for boolean singleton enums. Response::decode requires accepted=true. HistoryStatus uses an owner-discriminated handwritten decoder around generated record DTOs so added fields cannot select the wrong untagged variant.
- =HostPath= :: The schema string maps to std::path::PathBuf to retain existing path serialization and invalid-UTF-8 behavior. This is descriptor-free data, not runtime authority.
- =integer-representation= :: JSON Schema treats 1.0 as an integer, while existing Serde integer fields reject JSON floating-point values. x-json-integer and the Python validator preserve that representation constraint; generated Rust integer decoders enforce it naturally.
- =HistoryStatus= :: Typify does not enforce boolean singleton enums when selecting an untagged union. Select the generated OwnedHistory/UnavailableHistory record by the owner boolean, preserving unknown-field tolerance and required directory presence.
- =API-1-client-compatibility= :: Method::Produced retains the current producer DTO; Method::Result uses the generated x-client-result-schema reply DTO when older API-1 daemons omitted additive information. Optional metadata without a prior fallback stays absent. Session compatibility records explicitly preserve the defaults already used by snapshot views; direct JSON commands retain original wire presence via exchange_with_wire.
- =Variables= :: Generated parameter structs use BTreeMap<String,String>; existing SetVariables::validate enforces names/count/UTF-8 bytes/control characters in the gate and CLI, preserving diagnostics and validation order.
- =WorktreeName= :: Generated request name is String; the existing runtime worktrees::valid_name validator retains syntax checks and refusal order. Missing/null optional name still clears the record.
- =positional-parameters= :: Typify orders generated struct fields alphabetically and gives optional object fields Serde defaults. decode_params<M> maps positional arrays using generated PARAM_ORDER and MIN_POSITIONAL before generated named decoding. OpenRPC x-positional-required records nullable fields that the original sequence decoder required despite named-object optionality. Legacy reference decoders prove original field mapping, acceptance and default values. Positional array schemas stay in x-positional-schemas rather than generating tuple DTOs.
- =result-shapes= :: Serde structs accept positional arrays even for result objects. Response::decode applies validate_result_shape recursively using the checked-in schema to require object/array kinds, required field presence and union discriminants before generated deserialization. This is a structural guard, not a general JSON Schema validator: other constraints retain their generated or named validators. Optional API-1 metadata remains optional and nullable.
- =session-record-bridges= :: Controller lifecycle/domain records retain their ownership and existing types. HostSession/SandboxSession and SelfStatus explicitly project descriptor-free identity/worktree/creator/raid/terminal data and parse trusted lifecycle/origin strings into generated wire enums. The snapshot reader decodes generated HostSessionReply before converting to the legacy TUI/domain view until C15; its existing defaults and docker_scope alias/conflict rules remain unchanged. Terminal and raid method migrations retire their corresponding summary bridges in C05/C11.
- =cli-json-output= :: Generated compatibility DTOs model older omission/default rules and ignore result extensions; reserializing them would lose original null/presence/extension information. exchange_with_wire validates through the associated generated result DTO then returns the original result alongside it for the JSON list commands. Readers use the typed value; JSON output uses only the already-validated original result.
- =launch-validation= :: OperationKey, LaunchConfigurationName, LaunchAgentName, LaunchScope and LaunchManifest map to String; LaunchDimension maps to u16; option maps stay BTreeMap<String,String>. Existing controller/gate validators retain static bounds, policy checks, recreate/retry ordering and diagnostics instead of moving checks into generated deserialization. Raw decoding cases are distinct from schema-valid cases where a named semantic validator is required.
- =launch-retry-cache= :: The controller retains its serialized acceptance cache and domain Start (including private recorded history and member worktree). Generated HostLaunchParams projects into Start; HostLaunchResult produces the acceptance. Sandbox projection decodes that known cached result into the generated DTO and emits only MemberLaunchResult fields; no host paths cross the sandbox launch reply.
- =host-launch-omission= :: Typify cannot emit skip_serializing_if for a replaced BTreeMap field. Method OMIT_EMPTY_OBJECTS comes from x-client-omit-empty-objects and params_value<M> omits the empty host options object before a typed exchange. Nonempty options remain present and reach the existing host refusal; inbound decoding/defaults are unchanged. Strict pre-launch-options fake-daemon CLI tests cover run and resume.
- =client-param-presence= :: ParamPresence metadata comes from x-client-param-presence. params_value<M> retains host run null agent_name/scope/dev_shell, removes the empty name for recreate, and retains sandbox run null agent_name. It never removes a nonempty supplied name or other explicit values, so invalid combinations still reach existing validation. This is caller wire-shape compatibility around generated DTOs; inbound decoding is unchanged.
- =exec-command-validation= :: ExecText, ExecArguments and ExecDirectory map to String/Vec<String>/String; ExecEnvironment maps to Vec<(String,String)>. Existing validate_command retains UTF-8 byte, NUL, argv/env bounds and name/path diagnostics before descriptor/authority checks. The canonical init encoding validator remains after target, policy, capacity and init checks. Descriptor transport/ownership and cancellation remain handwritten.
- =exec-signal= :: ExecSignalNumber maps to i32 so the existing forwardable validator retains legal signal/state handling. Generated notification identity and ordered parameters are separate from callable Method identities. Invalid active-exec input closes instead of returning an RPC error.
- =exec-client-reply= :: ExecReply is the generated normalized client DTO, not a restriction on old wire results. The named exec-field-fallback Response adapter preserves the original CLI: code/signal are independently read as signed 64-bit JSON integers, message as a string; malformed/missing fields become None. Non-object results have no recognized fields, retaining the exit-255 fallback. x-client-wire-result-schema explicitly accepts these historical inputs; current producer schemas remain precise. Canonical JSON-RPC envelope/correlation errors are still rejected.
