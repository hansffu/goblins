* Protocol behavior

- =framing= :: Content-Length; 256-byte headers; duplicate keys and depth >32 rejected. See docs/API.org transport rules.
- =request_id= :: 1–64 ASCII letters/digits/underscore/hyphen, or unsigned integer <=9007199254740991. No null/boolean/fractional IDs. Notifications omit ID.
- =notification_policy= :: Ordinary notifications are ignored; active exec and attach have their own exchanges.
- =connections= :: Host: 4096 calls including initialize. Sandbox: initialize then one call, up to 8 connections.
- =initialization= :: Parameters are checked before repeated-initialize conflict, then unsupported-version refusal. api accepts u32; supported version is 1. configuration is null on host and the configuration key on sandbox (null if unavailable).
- =server_control= :: Host only. Both remain available during shutdown. stop flushes acceptance then closes its connection and completes cleanup asynchronously.
- =parameter_forms= :: C01 methods accept named objects or positional arrays: initialize accepts {api:N} or [N], server methods accept {} or []. Omitted params default to {}. Preserve Serde refusal order.
- =result_extensions= :: Result objects, including nested limits and history variants, may gain fields. Clients ignore unknown result fields; known fields and history owner discrimination remain validated. Request parameters stay closed.
- =api1_compatibility= :: Producer result schemas describe the current daemon precisely. x-client-result-schema describes compatible API-1 replies accepted by clients: configuration/limits and newer server.status history/manifest/worktree metadata may be absent. Clients retain absence as optional data and use advertised features rather than inventing values.
- =self_reporting= :: sessions.status exposes only the caller and its policy/activity. Worktree paths are deliberately visible. Activity is independent of lifecycle; variables update atomically and empty values remove keys. Missing or null set-worktree name clears the record; names are validated before filesystem access.
- =session-records= :: Current session read producers emit complete endpoint-specific records. Host sessions include descriptor-free process identities and host paths; sandbox records exclude them, except the intentionally shared Worktree.path. API-1 reader schemas retain the defaults and omissions previously accepted by Rust snapshot clients. The controller retains domain records; explicit projections and a generated-read adapter preserve snapshot consumers until C15. Nested terminal and raid summaries are typed public data; their methods migrate in C05 and C11.

* Generation exceptions

- =EmptyParams= :: Typify represents empty closed objects as maps; use a handwritten deny_unknown_fields empty struct to preserve the existing Serde decoder, including [] as well as {}. Null and unknown fields remain refused.
- =required-nullable= :: Typify/Serde Option accepts absence as null. Response::decode explicitly checks required nullable result fields before deserialization. Producers emit null rather than omitting; schema response validation checks the same presence rule.
- =validation= :: Type generation is not JSON Schema validation: constraints such as byte lengths remain named handwritten validators; tests check schema agreement.
- =protocol= :: Framing, duplicate keys, request IDs, deadlines and connection state remain in libs/jsonrpc and controller; generated DTOs never authorize calls.
- =boolean-enum= :: Typify 0.7 emits bool for boolean singleton enums. Response::decode requires accepted=true. HistoryStatus uses an owner-discriminated handwritten decoder around generated record DTOs so added fields cannot select the wrong untagged variant.
- =HostPath= :: The schema string maps to std::path::PathBuf to retain existing path serialization and invalid-UTF-8 behavior. This is descriptor-free data, not runtime authority.
- =integer-representation= :: JSON Schema treats 1.0 as an integer, while existing Serde integer fields reject JSON floating-point values. x-json-integer and the Python validator preserve that representation constraint; generated Rust integer decoders enforce it naturally.
- =HistoryStatus= :: Typify does not enforce boolean singleton enums when selecting an untagged union. Select the generated OwnedHistory/UnavailableHistory record by the owner boolean, preserving unknown-field tolerance and required directory presence.
- =API-1-client-compatibility= :: Method::Produced retains the current producer DTO; Method::Result uses the generated x-client-result-schema reply DTO when older API-1 daemons omitted additive information. Optional metadata without a prior fallback stays absent. Session compatibility records explicitly preserve the defaults already used by snapshot views; direct JSON commands retain original wire presence via exchange_with_wire.
- =Variables= :: Generated parameter structs use BTreeMap<String,String>; existing SetVariables::validate enforces names/count/UTF-8 bytes/control characters in the gate and CLI, preserving diagnostics and validation order.
- =WorktreeName= :: Generated request name is String; the existing runtime worktrees::valid_name validator retains syntax checks and refusal order. Missing/null optional name still clears the record.
- =positional-parameters= :: The generated named parameter struct is the Serde decoder for both named objects and positional arrays. Explicit x-positional-schemas describe those arrays and are validated against the shared parameter corpus; they are not separate Rust tuple DTOs (Typify cannot represent optional trailing tuple entries).
- =result-shapes= :: Serde structs accept positional arrays even for result objects. Response::decode applies validate_result_shape recursively using the checked-in schema to require object/array kinds, required field presence and union discriminants before generated deserialization. This is a structural guard, not a general JSON Schema validator: other constraints retain their generated or named validators. Optional API-1 metadata remains optional and nullable.
- =session-record-bridges= :: Controller lifecycle/domain records retain their ownership and existing types. HostSession/SandboxSession and SelfStatus explicitly project descriptor-free identity/worktree/creator/raid/terminal data and parse trusted lifecycle/origin strings into generated wire enums. The snapshot reader decodes generated HostSessionReply before converting to the legacy TUI/domain view until C15; its existing defaults and docker_scope alias/conflict rules remain unchanged. Terminal and raid method migrations retire their corresponding summary bridges in C05/C11.
- =cli-json-output= :: Generated compatibility DTOs model older omission/default rules and ignore result extensions; reserializing them would lose original null/presence/extension information. exchange_with_wire validates through the associated generated result DTO then returns the original result alongside it for the JSON list commands. Readers use the typed value; JSON output uses only the already-validated original result.
