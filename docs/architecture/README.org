* Purpose and reading order

This directory describes the implemented architecture, based on the supervisor cutover at commit =19ce5c4743240ce34045c01a933d8d9751406aca= (2026-10-31). It complements the design specifications and ADRs: those record intended contracts and decisions; these documents explain how the current runtime fits together. Update these documents when the corresponding code changes.

- [[file:components.org][Components and communication]]: build products, runtime processes, transport, authority boundaries, scopes and storage.
- [[file:daemon.org][Daemon internals]]: the controller event loop, process clients, state ownership, approvals, terminal handling and shutdown.
- [[file:workflows.org][Workflow sequences]]: server startup, root launches and running raid members, package permissions, Docker activation, dev shell refresh, inbox messaging, terminal attachment and stopping a goblin.

* Diagrams

Diagrams appear inline as SVG image links from [[file:diagrams/][diagrams/]]. Org opens these documents with images displayed and source blocks folded. Use =TAB= on a Mermaid block to reveal its source; =org-toggle-inline-images= toggles image display. Mermaid source is omitted from exports, which include the rendered images. Each source block has a =:file= target matching its =#+RESULTS:= image link. The documents set the shared =header-args:mermaid= property to =:results file graphics replace= and select =:theme dark=. Individual blocks set only =:file= and =:background-color=, following the working blocks in =daemon.org=. Export settings use =ob-mermaid='s defaults. Evaluating a block replaces its image result without adding a link description. =:file-desc= is deliberately omitted: the value =nil= is parsed as the literal description "nil", which prevents inline image display. The block's =:background-color "'#282c34'"= keeps Babel renders dark; the inner quotes protect the hex color from being interpreted as a shell comment by =ob-mermaid=. Evaluating a block with =ob-mermaid= writes that SVG. Labels use native SVG text rather than HTML so Emacs can display them. Flowchart and state-diagram labels use ordinary spaces and explicit line breaks. The shared configuration requests preserved CSS whitespace during Mermaid layout. The batch renderer also declares =xml:space="preserve"= on the SVG root without rewriting label text or geometry, making whitespace preservation explicit for native SVG consumers. Labels avoid nonbreaking spaces that the selected Mermaid version can emit as literal entity text. Use the batch renderer below for checked-in diagrams; direct Babel evaluation does not apply its XML whitespace declaration. The shared [[file:mermaid-config.json][Mermaid configuration]] uses Doom One's dark palette. Set =ob-mermaid-default-config-file= in your Emacs configuration to this file, or copy it to your Emacs configuration directory and use that path. The batch renderer uses this file by default; =--config PATH= selects your personal copy. Source blocks contain only the diagram definition. Sequence diagrams show logical ordering; they do not imply a synchronous call between every participant.

For example, after copying =mermaid-config.json= into =user-emacs-directory=:

#+begin_src emacs-lisp
(with-eval-after-load 'ob-mermaid
  (setq ob-mermaid-default-config-file
        (expand-file-name "mermaid-config.json" user-emacs-directory)))
#+end_src

Regenerate all SVGs after editing the Mermaid source:

#+begin_src sh
python3 docs/architecture/render.py
#+end_src

The script requires =mmdc= from =mermaid-cli= and its Chromium runtime. It runs Chromium with =--no-sandbox= for compatibility with the outer Goblins sandbox. If system fonts are unavailable, pass =--font-dir /path/to/fonts= with an installed font directory. The script rejects invalid SVG coordinates which can result from missing fonts. An Org Mermaid integration such as =ob-mermaid= can also render individual blocks.
