#+title: Plan: raids replace children
#+date: 2026-10-18

Status: proposed, under review. Nothing here is implemented. It supersedes the parent/child parts of [[file:CHILDREN-AND-RAIDS.org][CHILDREN-AND-RAIDS.org]] and [[file:CHILDREN-AND-RAIDS-TECHNICAL.org][CHILDREN-AND-RAIDS-TECHNICAL.org]] and the "ownership never moves" rule of [[file:../adr/0008-raids.md][ADR 0008]].

Labels: *[E]* existing behaviour, *[P]* proposed change, *[D]* decision taken with the user on 2026-10-18, *[?]* open for review.

* 1. Goal

Remove the parent/child ownership tree. Every goblin is a root. A goblin that owns a raid can run new goblins (=goblin run CONFIG=); each new goblin joins the owner's raid as a /created member/. The owner can stop the members created in its raid. Created members inherit what children inherit today (scope, workspace, working directory, dev shell generation, Docker attachment, package approvals as a new auto-approve state), and the =allowedChildren= restriction stays, renamed =allowedRunTargets=. Once created, a member is not a child: its owner exiting does not stop it, it is not part of anyone's subtree, and it communicates only through the raid (and with the host).

* 2. Decisions from the clarification round

- *[D]* Remove children entirely: no =--parent=, =--kill-children=, =--inherit-raid=, tree paths, subtree stop, parent/descendant messaging or the =parent= message alias. The agent name is the address.
- *[D]* When the owner exits, is stopped, fails, leaves or is kicked, the raid is /paused/ (not dissolved) while it has live members. Members keep working independently. Raid-routed sends and replies between members are rejected with a warning while paused; a sender that got the warning is notified when the raid resumes. The host is prompted to pick a new owner (any live member), dissolve the raid, or stop all members.
- *[D]* The owner can stop only created members (members that joined by =goblin run= from an owner of this raid), never host-invited ones. A newly selected owner can stop members created by any former owner.
- *[D]* A created member's configuration is resolved from the current installed manifest, not from the owner's launch-time snapshot. The run-target check uses the owner's =allowedRunTargets=.
- *[D]* New package approval state *auto-approve*: alongside approved and denied (and "not requested"), a goblin has an auto-approve set. A package in it is granted on request without asking the host. A created member's auto-approve set is the owner's approved packages plus the owner's auto-approve set, copied when the member is created.
- *[D]* =allowedChildren= is renamed =allowedRunTargets=; =goblin run CONFIG= stays the entry point.

* 3. Design

** 3.1 Configuration

- *[P]* =mkGoblin= option =allowedRunTargets ? [ ]= (list of configuration names), exported as =allowed_run_targets=. Same validation, bounds (64 names, 64 characters) and undeclared-name errors as today, with the new name in every message: "allowedRunTargets must be a list of unique goblin names", "mkGoblins: 'X' allowedRunTargets references undeclared goblin 'Y'".
- *[P]* =config.rs=: =Configuration.allowed_run_targets: Vec<String>= (=#[serde(default)]=, so a manifest without it permits nothing). The =allowed_children= field is removed, not aliased: the manifest is read by the daemon of the same build, and an older server must be restarted from the new build anyway (=deny_unknown_fields=). No =api=/=helper_api= bump, as in the earlier decision.
- *[P]* Delete =branch.rs=, =Manifest::branch=, =Manifest::children=, the per-branch GC roots and =Inheritance.branch=. Keep =Manifest::select_inherited= and =resolve= (renamed messages: "'X' requires scope 'S'; its owner has no scope", "'X' does not allow scope 'S'").
- *[P]* Demo goblins, =flake.nix= test goblins and =tests/checks.nix= switch to the new name.

** 3.2 Which manifest "current" means

*[E]* The daemon never knows the installed manifest: each host =sessions.start= / resume carries an absolute =configuration= path from the CLI's =--runtime= (the Nix wrapper passes it), and =server start= drops =--runtime=.

*[P]* The controller keeps =current_manifest: Option<PathBuf>=:
- set from =--runtime= when the server starts (pass it through =server start= and the background re-exec);
- replaced by the =configuration= of every accepted host =sessions.start= (including resume);
- GC-rooted as =<state>/manifest= (one root, replaced atomically) so a collection cannot remove it while the daemon may still launch from it;
- shown by =goblins server status=.
A sandbox =goblin run= resolves its target from =current_manifest=. Without one it fails with "no configuration is known yet; start the server with the installed goblins or run a goblin from the host". So "current" means "what the host last used"; after a rebuild, the next host launch or a server restart moves it forward. *[?]* Alternative: resolve from the owner's own =record.configuration= (its launch-time manifest, no snapshot). Simpler, but a rebuild never reaches created members until the owner is relaunched.

** 3.3 Running a created member

=goblin run CONFIG [--name NAME] [--detached]= inside a goblin sends sandbox =sessions.start {key, name, agent_name?, detached}= (=parent= and =inherit_raid= are removed).

Checks, in the event loop, before name allocation (all -32602 unless noted):
1. The caller owns a raid that is not paused: "only a raid owner can run goblins; create one with goblin raid create NAME" (-32009).
2. =CONFIG= is in the caller's =allowed_run_targets= (the list loaded with the caller's own configuration at its launch). Errors keep today's wording with "run target": "configuration 'Y' permits no run targets", "configuration 'X' is not an allowed run target of 'Y'; allowed: a, b".
3. =current_manifest= is known; on the worker, =select_inherited(CONFIG, owner's scope)= succeeds, otherwise the launch fails with "configuration 'X' cannot be launched here: …".
4. Raid capacity (16 members) and event budget as today.

The launch is a root launch (no =parent=) with a new worker source =Source::Member { owner: Inheritance, configuration: PathBuf, name: String }=. It takes from the owner's =Inheritance= exactly what =child_configuration= takes today:

| Field | Source |
|-------+--------|
| executable, args, env, packages, =/etc=, integration, editor, network policy, =allowedRunTargets= | the target configuration from the current manifest |
| =cwd=, =protected_paths= | owner's launch (pinned working-directory fd via =Plan::share_working_directory=) |
| dev shell | owner's current generation |
| scope | owner's scope, joined through the scope registry (owner is live at that moment) |
| workspace | owner's =SharedWorkspace= |
| Docker | attached at start if the owner is attached or the target sets =docker.enable= |
| auto-approve | owner's approved ∪ owner's auto-approve (3.5) |

=Session::child= and =Session::child_configuration= become one =Session::member= constructor; =Source::Child= goes away. The member joins the raid in the same event-loop step that inserts it, with =Member.created_by = Some(owner)=; it is a member while =starting=. Launch keys and retries behave as today (=current_manifest= is resolved after the retry comparison, so a rebuild between retries is not a conflict).

The sandbox result is ={session, agent_name, state}=; the relative-path stripping that would fail for a root is removed.

A created member records the owner in its =SessionRecord.created_by= (id and agent name, display only) and gets a history record like any root, so =goblins resume= recreates it as a plain root (no raid; existing TODO "Recreate raid membership").

** 3.4 Owner control over created members

- *[P]* Sandbox visibility: =sessions.list=, =sessions.get=, =sessions.attach=, =sessions.resize= and =sessions.stop= on the sandbox endpoint accept only created members of the caller's raid while the caller is its (unpaused) owner. Resolution is by ID or unique agent name. Everything else is -32004. =goblin list= shows those members; =goblin raid members= remains the full raid listing.
- *[P]* Stop reason: "stopped by raid owner NAME (ID)". No cascade: stopping a member stops only that member.
- *[?]* Recommended: a created member cannot =raid leave= on its own ("created members stay in the raid until stopped, kicked by the host or the raid dissolves"), so the owner keeps control over what it created. The host can still kick it. Alternative: allow leaving, which ends the owner's control.
- *[?]* Recommended: keep attach/resize for the owner over created members (today's parent ability, "subtree-terminal"). Alternative: stop only.

** 3.5 Auto-approve

- *[P]* =Active.auto_approve: BTreeMap<String, PathBuf>= (package name to the exact store output, preserving the "never resolve a granted attribute twice" guarantee) and =Active.auto_approve_dev_shells: BTreeSet<identity>=. Filled when a created member is inserted: owner's =granted_outputs= ∪ owner's =auto_approve=, and owner's current =dev_identity= ∪ owner's =auto_approve_dev_shells=. Host-launched goblins start empty.
- *[P]* A =permissions.request= for a package in =auto_approve= is decided automatically (actor =goblins=, as an inherited approval today), using the stored output. A dev-shell refresh to an identity in the set is approved automatically. This replaces =inherits_package= and =inherits_dev_shell= and their ancestor walks; the =initial_output= shortcut stays. Since the set is copied at creation, a grant given to the owner afterwards does not reach existing members (a change from today's live ancestor walk, accepted with the decision).
- *[P]* Reported as =SessionRecord.auto_approve: Vec<String>= (snapshot, sandbox record, TUI package table, Emacs info page).
- *[P]* History: =Packages= gains =auto_approve: Vec<String>= (=#[serde(default)]=), so a resumed member keeps it. On recreate the names are resolved against the current catalog like approved names, but *not* mounted: they go back into =auto_approve= with the freshly resolved output; a name that no longer resolves is listed in =skipped=. A granted package moves from =auto_approve= to =approved= in the record. *[?]* =deny_unknown_fields= means a daemon from an older build ignores (fails to read) records with the new field; the record =VERSION= check already skips mismatching records, so bump =VERSION= to 2 and accept 1 on read.
- Docker: unchanged rule; a member attached at start has =docker_enabled= and its later =docker= requests are automatic.

** 3.6 Paused raids and ownership transfer

State (=raid.rs=):
- *[P]* =Raid.owner: Option<String>= plus =Raid.paused: Option<Paused { former_owner, reason, since }>=. =Member= gains =created_by: Option<String>=.
- *[P]* =leave= of the owner (stop, exit, failed launch, =raid leave=, host kick): if live members remain, the raid pauses (=Change::Paused { raid, former_owner, reason }=); otherwise it dissolves as today. A paused raid whose last member leaves dissolves.
- *[P]* =Raids::set_owner(raid, session, actor)= (host only): the target must be a live member. Clears =paused= and emits =Change::Owner { raid, owner, previous }=. Allowed on an unpaused raid too (host-initiated transfer); created members keep =created_by= and are controllable by the new owner.
- *[P]* While paused: host invites and =goblins run --raid= join as members without picking an owner; =raid create= with the same name fails (=Exists=); no goblin can run members or stop created ones (only the host can).
- *[P]* Event classes: =Paused= is a removal (applied even when unrecorded, takes access away); =Owner= is an addition (authorizes nothing until logged, counts against the budget). New log kinds =raid.paused= ={raid, former_owner, reason}= and =raid.owner= ={raid, owner, previous}=, both listing every member in =sessions=. =raid.dissolved= reasons become =destroyed=, =empty= and =resolved= (prompt answered with dissolve/stop).

Messaging (=mailbox.rs=):
- *[P]* =RaidView= gains =paused: bool= and its =owner= becomes optional; =apply_raid= updates every member's view on =Paused= / =Owner=, so a later =Joined= copies the current owner.
- *[P]* =resolve=: when the only route to a target is a paused raid, fail with -32009 "raid 'R' is paused until the host selects a new owner; you will get a notice when it resumes" (instead of "absent"). The same check and message for replies; the claim stays outstanding. Messages already delivered stay with their recipient.
- *[P]* The worker keeps =warned: BTreeMap<raid_id, BTreeSet<session>>=, filled on those rejections (in =execute=, since =prepare= is =&self=), pruned on =Left=/=Dissolved=. On a logged =Owner= event it queues one notice per warned sender that is still a live member, from =goblins=, then clears the set. Text: "Raid R has resumed with owner NAME; messages to its members are allowed again." The notice uses a new optional =Message.raid= field ={id, name, owner, event: "resumed"}= (=operation= stays unset); replying to it fails like replying to an operation notice. Capacity and undelivered handling copy =record_operations=.
- *[P]* Without a tree, a goblin may message: the host (only by replying to a host message, as today) and live members of its unpaused raid. =route= in =message.accepted= becomes ="host"= or ="raid"= (="tree"= goes away). The =parent= target alias is removed.

Host prompt:
- *[P]* When a raid pauses, the controller adds a =PermissionRecord= with =kind: "raid-owner"=, =session= = former owner, =package= = raid name, =preview= = ={raid, former_owner, members: [{id, agent_name, name, role, created}]}=, state =pending=, no operation notices (there is no live requester). It is not tied to =Active.pending=.
- *[P]* Resolved by new host RPCs (and only by these; =permissions.decide= rejects this kind):
  - =raids.set_owner {raid, session}= → resume with that owner;
  - =raids.destroy {raid, stop_members?: bool}= → dissolve, optionally stopping every live member ("stopped because raid R was closed by the host").
  Either one marks the record =approved= (set owner) or =denied= (destroy) with a message; a raid that dissolves on its own (last member gone) marks it =cancelled=. The record is updated in place if the raid pauses again.
- *[P]* Host CLI: =goblins raid set-owner RAID GOBLIN=, =goblins raid destroy RAID [--stop-members]=. =goblins raid members= shows =paused= and the former owner.
- *[P]* TUI: the popup for a =raid-owner= request lists the members and offers =o= (pick owner, member list selection), =x= dissolve, =k= stop all. Emacs: a =raid-owner= popup insert with the same three actions (owner through =completing-read= over the preview's members); =goblins--decide-record= refuses plain accept/deny for this kind; =goblins-attention-mode= counts it automatically (it counts all pending records).

** 3.7 Removing the tree

- *[P]* Controller: drop =SessionRecord.parent= and =path=, =descendant=, =relative_path=, subtree =resolve_scoped= (replaced by 3.4's rule), =stop_tree=, =owner_exited_reason=, the natural-exit cascade, =Stop.kill_children=, =Start.parent=, =Start.inherit_raid=, =ChildStart.parent/inherit_raid=, "children inherit their parent's scope/dev shell", per-parent name allocation (names are unique among live goblins and reserved until the session is gone), "keep sessions that have children" in eviction, the root-only conditions in history (every goblin is recorded), the =--parent= refusal in recreate, and the sandbox =raids.invite= (no children to invite). Initialize features drop =allowed-children=, =subtree-control=, =subtree-terminal= and add =run-targets=, =raid-owner=.
- *[P]* Messaging: =mailbox::Session= loses =parent=/=path=; =sender_path=/=recipient_path= wire fields are removed (agent names stay); =communications.list --session= matches that session only (no subtree); =session.started= logs no =parent=/=path=; the offline log reader still accepts old events that carry them.
- *[P]* Raid records: =RaidMemberRecord.path= is removed; =created= (bool) and =created_by= added; =RaidRecord= gains =paused= and an optional =owner=.
- *[P]* Exec, editor and TRAMP address a goblin by agent name only (=gribble=, no =gribble.snaga=).
- *[P]* Host CLI: remove =run --parent=, =stop/kill --kill-children=, "(children inherit)" help, tree-path completion. Sandbox CLI: =run= without =--parent=/=--inherit-raid=; =attach=/=list=/=stop=/=kill= for created members; =raid invite= removed; =goblin status= shows "Run targets:" and the raid's paused state.
- *[P]* TUI: flat goblin list (no folding); Emacs overview, sidebar and info pages without trees ("Children" section, "Parent" row and descendant prompts removed; sidebar keeps grouping by raid and shows "created by" in a member's block).

* 4. Implementation steps

Each step is a commit on =replace-children-with-raid= that builds, passes =cargo test= and =nix flake check= (new files staged first), and keeps the Python suites it touches green; suites are run one at a time with output to a log.

1. *Plan and ADR.* This file, ADR 0014 "Raids replace the ownership tree" (superseding parts of ADR 0008), status notes on the two CHILDREN-AND-RAIDS specs.
2. *Rename to =allowedRunTargets=.* Nix, =config.rs=, =sessions.status= field, demo goblins, checks; behaviour still the old child rule.
3. *Paused raids and ownership transfer.* =raid.rs=, controller wiring, =raids.set_owner=, =raids.destroy --stop-members=, the =raid-owner= prompt record, mailbox paused rejection, warned senders and resume notices, events. Rust unit tests for every rule; =tests/test_raids.py= for pause/resume/notice/prompt resolution via the host CLI.
4. *Auto-approve.* Replace ancestor walks with the copied set; history field and recreate; tests in =test_ownership.py= rewritten accordingly.
5. *Created members and removal of the tree.* =current_manifest=, =Source::Member=, owner control, removal list of 3.7 in the controller, mailbox, messaging, CLIs and protocol. Delete =branch.rs=. Port tests (=test_ownership.py= becomes =test_run_targets.py=; the "USE" tests in docker, devshell, codex/claude config, network, nix, host commands, mailbox, editor, scopes, history, recreate and responsiveness switch from children to created members).
6. *TUI and Emacs.* Flat views, =raid-owner= prompt, =goblins-tests.el= and =test_emacs.py=/=test_tui.py=.
7. *Skills and docs.* =goblins-spawn= (run a raid member), =goblins-raids= (owner, created members, pause, notices), =goblins-messaging= (no =parent=/descendants), =goblins-docker=, =goblins-devshell=, =goblins-nix=; README, USAGE ("Sandbox ownership" becomes "Running raid members"), DAEMON.org, architecture workflows (child launch and subtree stop diagrams replaced), the other specs and ADR mentions listed in the inventory; TODO.org: "Recreate children with their root" closed as obsolete (DONE, CLOSED), "Recreate raid membership" kept.
8. *Full verification.* All Python suites serially; Docker and integration suites through an approved host command; a live check with a Claude owner running a Codex member on a branch build server (asking before restarting the user's server).

* 5. Risks and notes

- Large mechanical surface: tree paths and =parent= appear in the TUI, Emacs (overview, sidebar, TRAMP, messages), mailbox tests and about 20 Python test files. Steps 5 and 6 are the bulk.
- A created member outlives its owner but keeps sharing its workspace and scope; the scope stays alive while any member runs (existing scope semantics). The owner's session directory is held by the shared workspace until the last holder exits (=SessionDirectory= Arc), as with children today.
- =current_manifest= can lag behind the installed build until the next host launch or server restart; documented in USAGE.
- The 4,096 raid-event budget is cumulative; pause/resume cycles consume it. Fine at expected use; unchanged.
- Older Emacs/TUI builds against a new daemon would miss =path=; both live in this repository and ship together.
