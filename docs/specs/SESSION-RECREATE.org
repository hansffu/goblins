#+title: Recreating goblin sessions

Status: implemented, 2026-10-16. Usage is in the "Recreating goblins" section of [[file:../USAGE.org][USAGE.org]]; the decision is [[file:../adr/0010-recreate-not-restore.md][ADR 0010]].

* Goal

A goblin that has stopped, crashed, or lost its daemon (including a host reboot) can be started again with the access it had, and its agent conversation picks up where it left off (=claude --resume ID=, =codex resume ID=).

This is a *recreate*, not a restore. The daemon keeps a small JSON record per goblin and launches a new goblin from it using the *current* configuration of the same name. If the =mkGoblin= configuration has changed since, the new version is used and the recorded package grants are applied on top. Nothing that pins store paths is kept: no GC roots, no manifest snapshot, no sandbox state. Saving disk space is the point; losing exact fidelity is the accepted tradeoff.

* Decisions

- Records are written by the daemon whenever the recorded state changes. Nothing depends on a clean exit.
- Recreate is best effort: an incomplete recreation is better than none. Anything recorded that cannot be restored is skipped with a reason and the goblin starts anyway; only cancellation aborts. Recreate uses the current manifest and resolves package names against the current catalog.
- Denied packages are recorded for information only. A recreated goblin can request them again and gets the normal approval prompt.
- =mkGoblin= gets =resumeCommand=: the agent's argument list for a resumed launch, with ={key}= placeholders filled from variables the goblin recorded. It replaces =args=. =mkGoblin= makes no assumptions about the agent; each builder sets its own.
- The agent session's id *and name* are recorded, so the right session is easy to find.
- Only root goblins get records. Children are neither recorded nor recreated.
- The last 100 records are kept by default. A prune command, modelled on =nix-collect-garbage=, removes older ones by age, date or count.
- One daemon owns the history store at a time.

* Out of scope (v1)

Children, raids, inbox contents, terminal and process state, Emacs UI. Goblins launched by a daemon running with =--workspace= (snapshot mode) are not recorded; =goblins recreate= on such an id fails with an explicit error instead of starting in an empty workspace.

* Record

One file per conversation line: =$XDG_STATE_HOME/goblins/sessions/<id>.json= (default =~/.local/state/goblins/sessions=). The directory is 0700 and its files 0600.

As in Claude Code and Codex, ids are the keys and names are labels. A new root goblin starts a record with a short random id: 8 characters of lowercase Crockford base32, such as =k3f9x2ab=. Goblins session ids (=<instance>-s<n>=) share the server instance's 32-character prefix, so they make poor ids to read or type. Recreating continues that same record: the new goblin is appended to =sessions=, so the record always describes the latest goblin, and any goblin id it ran as (such as one Emacs shows for a stopped goblin) finds it. There is also one record per agent conversation: when a goblin reports a =session_id= that another record holds and no goblin runs that one, the other record is merged in (its goblin ids lead, its approved packages are added) and removed. When the agent switches conversation (=/clear=, =/new=), the record follows the goblin.

#+begin_src json
{
  "version": 1,
  "id": "k3f9x2ab",
  "configuration": "claude",
  "agent_name": "morb",
  "cwd": "/home/hansffu/code/goblins",
  "scope": "personal",
  "dev_shell": null,
  "docker_enabled": false,
  "packages": { "approved": ["ripgrep", "jq"], "denied": ["nmap"] },
  "variables": { "session_id": "c8193c93-…", "session_name": "Plan goblin session restore" },
  "sessions": ["1f6b…-s4", "9a2c…-s98"],
  "skipped": [],
  "created": 1792156012273,
  "updated": 1792159072343,
  "stopped": null
}
#+end_src

- =packages.approved= holds names whose grant reached =ready=, in grant order, so =PATH= priority is preserved.
- =packages.denied= holds names the host explicitly denied.
- A name is in the list of its latest *final* outcome: a =ready= grant moves it to =approved=, an explicit host denial moves it to =denied=. Approved-but-failed, withdrawn and cancelled requests change nothing. The two lists never overlap.
- =variables= is a small key/value map that only the goblin itself writes (see below).
- =skipped= lists what could not be restored when this record's goblin was recreated, as ={name, reason}= entries: approved packages, and =docker=. The reason is one line of at most 256 bytes, control characters escaped. Skipped packages stay in =approved=, so the next recreate tries them again.
- =sessions= lists the goblins this record ran as, oldest first, at most 256; the last is the latest goblin.
- =stopped= is informational: a goblin that died with its daemon never gets it. Only the record's latest goblin sets it.
- Size limits: at most 256 names per package list and 64 KiB per record. A grant that would exceed them is still applied but not recorded, and the record's goblin gets a =detail= saying so.

** Store and writing

- A new module =crates/controller/src/history.rs= owns the store.
- *Ownership.* The daemon takes an exclusive =flock= on =sessions/.lock= at startup and holds it for its lifetime. The owner writes its name (pid and state directory) into the lock file, so others can say who holds it. A second daemon (another =--state-dir=) that cannot get the lock runs without history and says so in =goblins server status=; a thread retries the lock every 2 seconds, so the daemon takes the store over once its holder lets go, and a short CLI prune never leaves a daemon without history. Meanwhile it keeps root goblins' variables in memory (=sessions.set-variables= still answers =recorded: false=); at takeover it writes a record for every running root goblin from its session: name, agent name, working directory, scope, dev shell, Docker, granted packages in grant order, the variables, and for a recreated goblin the record it continues and its skipped items. Denials made meanwhile are not recorded. Only the lock holder removes temporary files left by an interrupted write. With one owner, "running" is simply "running in the owning daemon".
- *Writer.* The controller sends whole-record snapshots over a channel to a writer thread, which keeps only the newest revision per id and writes it with temp file, fsync, rename and directory fsync. Disk I/O never runs on the event loop.
- *Serialisation.* Retention and prune also run on the writer thread, so they are ordered with writes. Deleting a record drops any queued revision for it. A deletion counts only once the file is unlinked and the directory fsynced; the writer reports each outcome, a record that could not be deleted stays, and =history.prune= answers only then, with what was removed and what failed. Running records are never deleted, and only running goblins produce writes, so a late write cannot resurrect a pruned record.
- *When.* The controller sends a snapshot when a root goblin reaches =running= (=Completed::Started=), on =Completed::Granted= with =ready= for a package or Docker, on a host denial in =decide=, on a variable change, and on stop.
- *Protection.* The store directory is added to =protected_paths=, so binds and working directories cannot overlap it. =scope.rs= uses =protected_paths.last()= as the daemon's realm for the scope registry, so the history path is inserted before the runtime state entry, not appended.
- *Retention.* After creating a record, the writer deletes the least recently updated records that are not running, beyond the limit (default 100, =goblins server start --keep-sessions N=). Records left without =stopped= by a crash count like any other stopped record.

* Variables

A generic, agent-agnostic way for a goblin to record values for its own record.

- Sandbox RPC =sessions.set-variables {variables: {key: value}}=, handled next to =sessions.set-state= in =sandbox_control=. All given keys change together, so an agent can switch =session_id= and =session_name= in one call. It only ever writes the calling session's record. For children it succeeds without recording, so agent hooks need no special case.
- Sandbox CLI: =goblins variable set KEY=VALUE…= in =crates/client=.
- Limits: keys match =[a-z][a-z0-9_]{0,31}=; values are UTF-8 without control characters, at most 256 bytes; at most 16 keys per record. An empty value removes the key.
- Values are display text and may contain spaces. When a value fills a =resumeCommand= placeholder it must not start with =-=; otherwise recreate falls back to plain =args= and reports why.

* =resumeCommand=

- =mkGoblin= option =resumeCommand ? null=: a list of strings, used *instead of* =args= as the agent's arguments (=Launch.shell_args=). The executable is not part of it. ={key}= is replaced by the variable =key=; ={{= and =}}= are literal braces. Each element stays one argv element; no shell is involved.
- =nix/internal/validate.nix= checks the type and placeholder syntax. =mk-goblin.nix= emits it as =resume_command= in the goblin's manifest entry; =config.rs= reads it into =Configuration= and =Launch=.
- On recreate, when the configuration has a =resume_command= and every placeholder it references has a value, it replaces =shell_args=. Otherwise the goblin starts with its normal =args=: the sandbox is recreated and the agent starts a fresh conversation.
- If the recorded agent session no longer exists, the agent's own error is what the user sees. There is no silent fallback to a fresh conversation.
- The Claude and Codex defaults below append to =args=. They suit =args= made of options only. A goblin whose =args= contain a prompt, a subcommand or =--= must set its own =resumeCommand=; the builders document this.

* Recreate

** Commands (host CLI)

- =goblins history= lists records, newest first: id, agent name, configuration, agent session name, working directory, last update, whether it is running, and skipped packages. On a terminal it goes through =$PAGER= (=less= with =LESS=FRX= by default); =--no-pager= prints it directly.
- =goblins recreate ID [--detached]= recreates one record. =ID= is a record id, any goblin session id the record ran as, the agent's conversation id (=session_id=), or a unique prefix of a record or goblin id. Agent and chat names are labels and select nothing. Shell completion offers record ids, newest first; zsh and fish show the agent name, chat name and last update beside each. It cannot be combined with =--parent=. Without =--detached= it waits for the goblin to run, prints each skipped item as =Skipped: NAME — REASON=, then attaches like =goblins run=.
- =goblins history prune [--older-than 30d] [--before 2026-10-01] [--keep N] [--dry-run]= removes records that are not running. With no option it removes nothing and prints usage, so prune is always deliberate. These go through the owning daemon (=history.list=, =history.prune=). Otherwise =goblins history= reads the files without the lock (whether they run is then unknown), and =goblins history prune= takes the store lock itself, refusing and naming the owner when another process holds it; that includes a daemon here that runs without history.

** Daemon

=goblins recreate= is =sessions.start= with a new =recreate: ID= parameter, using the caller's current manifest like =goblins run=.

1. *Checks.* Read the record. Refuse in =--workspace= mode, with =--parent=, or if the recorded =cwd= no longer exists.
2. *Reservation.* Each live goblin writes one record, its line: the record it was recreated from, otherwise its own. Before =Worker::start=, the controller refuses if a live session (=starting=, =running= or =stopping=) has this record as its line. The reservation ends when that session stops or fails to start. Since a line is one record, duplicate =goblins recreate= calls with different operation keys cannot resume the same agent session twice. (Separate records per recreate, linked by =recreated_from= and later an =origin=, were the first two designs.)
3. *Launch.* The recorded configuration name is launched with the recorded scope, dev shell reference and =cwd=. The agent name is reused if it is free, otherwise a new one is chosen. The dev shell reference is evaluated afresh, as on any launch.
4. *Packages, before the agent starts.* The worker resolves each approved name against the current catalog (=Session::realize=, which works before =start=). =Session::start= then takes these outputs as a new =recreated= list:
   - their closures join the initial closure, so they are mounted with the initial store view and no helper call is needed;
   - after the empty =generation-0=, it stages one package generation per output in recorded order with the existing =profile= logic, pointing =packages/current= at each new generation and adding the output to =Session.packages= before staging the next (=profile= reads both), so the last generation holds every command with the usual earlier-wins priority;
   - they are the session's own grants, not =Launch.initial_packages=, which same-configuration children copy.
   Any failure for one name, whether it is missing, removed, broken, unfree, or fails to download, evaluate or build, puts it in =skipped= with the final Nix error as its reason; the others are still staged. Only cancellation aborts. Skipped names stay in =approved=, so the next recreate tries them again, which matters for temporary download failures. Mount failures still fail the start. The 128-package limit covers initial packages and recreated grants together; grants beyond it are skipped.
5. *Docker.* If the record has Docker, the worker mirrors an inheriting child (=Session::child=): it adds the Docker client to the initial packages and sets =docker_inherit_enabled = Some(true)=, so =Session::start= attaches the engine before the agent starts. Without the client staged, =enable_docker= would try a live grant before the helper exists. If the configuration's scope does not enable Docker, or it runs without a scope, the goblin starts without Docker and =docker= goes to =skipped= with the reason. The new record keeps =docker_enabled=, so a later recreate tries again once the configuration allows it.
6. *Arguments.* =shell_args= is replaced by the resolved =resume_command= when possible.
7. *Hand-over.* =Completed::Started= gains the recreated names, their outputs and the skipped items with their reasons. The controller puts them into =record.packages= and =Active.granted_outputs= before marking the session =running=, so children's requests for them are approved automatically, as for ordinary grants.
8. *Record.* When the goblin reaches =running=, the record continues: the goblin is appended to =sessions=, its configuration, agent name, scope, dev shell and working directory are updated, =skipped= is replaced, =stopped= is cleared, and the package lists and variables carry on. A start that fails leaves the record as it was.

* Claude

- =nix/goblins/claude/hook.sh= keeps =session_id=, =transcript_path= and =session_title= from the hook input.
- On =SessionStart=, =UserPromptSubmit= and =Stop=, it sends =session_id= and =session_name= together with one =goblins variable set= call, only when they differ from the last *acknowledged* values (cached in the sandbox's =/tmp= after a successful call).
- The name is =session_title= when Claude provides it (custom names such as =/rename=). Otherwise it is the latest title in the transcript's last 4 MiB: a =custom-title= entry wins over an =ai-title= entry. These entry types are Claude internals, so reading them is best-effort.
- When =session_id= changes, the name is reset with it; a name that cannot be read yet is sent empty. Keeping the last known name on a read failure only applies while =session_id= is unchanged.
- Variable reporting never changes or delays the hook's inbox decision or output. The hook only stores its input as the latest in the sandbox's =/tmp= and starts the reporter in its own session (=setsid=), detached from the hook's pipes. Reporters run one at a time under a lock and always work on the latest input, so a slow one cannot overwrite newer values. The transcript is read once, its last 4 MiB, within 5 seconds. A failed call is simply retried on the next hook.
- =mkClaudeGoblin= default: =resumeCommand = args ++ [ "--resume" "{session_id}" ]=, overridable, including with =null=.

* Codex

- *Launcher fix.* Codex refuses =--sandbox= and =--ask-for-approval= when resuming a remote thread ("Permission overrides are not supported when resuming a remote task."). =nix/goblins/codex/launcher.nix= must leave those two flags off the remote terminal UI when its first positional argument is =resume=. The app-server keeps enforcing =sandbox_mode= and =approval_policy= through its own =-c= settings. If the caller passes either flag with =resume=, the launcher exits with a clear error.
- *Reporting.* =goblins-codex='s =native_proxy= (=crates/codex/src/main.rs=) already records the foreground thread id from correlated =thread/start=, =thread/resume= and =thread/fork= responses. It now also keeps the desired =session_id= and =session_name= (from =result.thread.name=) and sends them together with =sessions.set-variables=. It takes =thread/name/updated= (=params.threadName=) as the new name only when =params.threadId= is the current foreground thread. A foreground switch replaces both values at once.
- *Retries.* Reporting runs off the proxy loop. A failed report is retried with a bounded backoff, always with the latest desired values, so an obsolete retry cannot overwrite a newer thread.
- =mkCodexGoblin= default: =resumeCommand = args ++ [ "resume" "{session_id}" ]=. Options placed before =resume=, such as =-p= and =-c=, still reach the app-server; this was verified end-to-end.

* Verified so far

End-to-end, with installed Codex 0.163.0, a faithful copy of the launcher, the real adapter and a synthetic provider (2026-10-16):

- With the stock launcher, resume fails with the permission-override error above, before any request is sent.
- With only those two flags removed: the terminal UI sends =thread/resume= with an integer request id and no =threadSource=, which =foreground_thread_request= already accepts; the adapter records the resumed id; activity reporting works; the old conversation loads without a new model call; the resume response carries =thread.name=; a rename emits =thread/name/updated= on the proxied connection.

Real Claude Code transcripts (2.1.301) contain =ai-title= entries with an =aiTitle= field, repeated through the session, so reading the latest from the end of the file finds one. Not yet verified: Claude's =session_title= hook field and =custom-title= entries (assumed to carry =customTitle=); the hook reads both best-effort.

During implementation the end-to-end test in =tests/test_codex_native.py= also confirmed, with Codex 0.163.0, that =thread/name/set= emits =thread/name/updated= on the terminal's connection and that =/new= in a resumed terminal is reported as a foreground switch.

* Implementation steps

Each step is one commit with its tests. Python suites run one at a time.

1. Fix =tests/codex_wire.py=: the second payload-length check must be =elif=; a 127-byte frame is decoded twice and raises =MemoryError=.
2. =history.rs=: record type, store lock, writer thread, atomic writes, retention, prune. Rust unit tests: atomic replacement, newest revision wins, approved/denied moves, size limits, retention skipping running records and counting crash-left records, a queued write dropped by prune.
3. Controller wiring: records created and updated at the points listed above; protected path ordering; =sessions.set-variables=; =goblins variable set=. Python tests: a record follows grants, denials, Docker and variables; it survives =kill -9= of the daemon; a second daemon runs without history.
4. Nix: =resumeCommand= through =mk-goblin.nix=, =mk-goblins.nix=, =validate.nix= and =config.rs=. =tests/test_configuration.py= covers validation and the emitted manifest.
5. Recreate: =recreate= on =sessions.start=, reservation, recorded packages in =Session::start=, Docker, argument substitution, agent-name reuse, hand-over in =Completed::Started=, =goblins recreate=, =goblins history=. Python tests: the goblin's very first command sees recreated packages and Docker, including Docker attached on demand in a configuration with =docker.enable = false=; two recreated packages keep their commands and collision priority; changed configuration; a package removed from the catalog is skipped and listed; a same-configuration child does not get recreated grants mounted; a child's request for one is approved automatically; concurrent and transitive recreates are refused; a failed start releases the reservation; =--workspace= and =--parent= refused; a missing variable or a value starting with =-= falls back to =args=.
6. =goblins history prune=: =--older-than=, =--before=, =--keep=, =--dry-run=, offline use with the store lock.
7. Claude: hook reporting and the =mkClaudeGoblin= default. =tests/fake_claude.py= sends hook payloads with ids, titles and transcripts, including an id switch and a failed call.
8. Codex: launcher fix, adapter reporting with retries, =mkCodexGoblin= default. End-to-end test in =tests/test_codex_native.py= modelled on the verification above, including rename, a foreground switch, and =--sandbox= passed with =resume=.
9. Docs: a recreate section in =docs/USAGE.org=, an ADR for recreate-not-restore, and follow-ups in =docs/specs/TODO.org= (children, raids, Emacs history view).
