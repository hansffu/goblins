#+title: Open work after flake dev shells

Follow-ups from branch =feat/flake-dev-shells= ([[file:../adr/0007-flake-dev-shells.md][ADR 0007]]). Read the ADR first; it
records the trust model (only host-launched or host-approved locks are
trusted), the evaluator sandbox and the approval preview. Usage is in the
"Flake dev shells" section of [[file:../USAGE.org][USAGE.org]].

Where the code lives:

- =crates/controller/src/devshell.rs= :: snapshot, lock checks
  (=check_lock=, =validate_lock=, completeness in =snapshot=), candidate
  evaluation (=candidate=), apply (=apply=), the structured =Preview= sent to
  frontends.
- =crates/controller/src/evaluator.rs= :: Bubblewrap evaluator: store, daemon
  socket, source tree, private state; =Network= (host, none, goblin
  namespaces).
- =crates/controller/src/session.rs= :: =prepare_refresh=, =apply_refresh=,
  =mount_paths= (live mounts through the helper), =evaluation_network=.
- =crates/controller/src/worker.rs= :: =Work::Refresh=, the =devshell= case
  of =Work::Decide=, =Completed::Refresh= / =Completed::DevShell=.
- =crates/controller/src/controller.rs= :: =permissions.request= with kind
  =devshell=, =Completed::Refresh= handling, =inherits_dev_shell= (automatic
  approval), sandbox method =devshell.lock=.
- =crates/protocol/src/rpc.rs= :: =PermissionParams= (=update=, =lock=,
  =validate=, =input_name=), =DevShellDiffParams=. =plain_text= (escaping)
  in =lib.rs= and =patch_files= in =patch.rs= are shared by frontends.
- =crates/client/src/{cli,main}.rs= :: in-sandbox =goblins devshell
  refresh|diff|restore-lock=; =preview.rs= renders a diff's preview as text.
- Frontends assemble all wording and colors from the structured preview:
  =crates/controller/src/tui.rs= (=devshell_summary=, =diff_lines=, =d=
  diff view) and =emacs/goblins.el= (=goblins--insert-devshell-summary=,
  =goblins--insert-diff=).
- Tests :: =tests/test_devshell.py= (real daemon; =DevShellTests= launch,
  =DevShellRefreshTests= refresh), unit tests in =devshell.rs= and =tui.rs=,
  ERT tests in =emacs/goblins-tests.el=.

Development notes:

- Enter the Git-backed =nix develop= once; its tools do not depend on Goblins compiling. Keep it open while editing.
- =just test-feature devshell= runs the incremental Cargo controller against Nix-built fixtures. Direct unittest runs use packaged controllers. TUI and Emacs tests need =pyte=, which the dev shell provides. Avoid =path:.=, which copies ignored build artifacts into the store.
- Test Emacs rendering with =emacs -nw= or =--batch= only. The host Emacs is
  pgtk and opens windows on the user's session even under Xvfb.
- Host polling in tests: a host RPC connection allows 4096 calls; poll slowly
  on fresh connections during long evaluations (see =pending_refresh=).
- Nix silently fetches and uses inputs missing from =flake.lock= even with
  =--no-update-lock-file=; any new flake command must keep the completeness
  check in =snapshot= (=metadata.locks= must equal the file).

* DONE =goblins flake run= (the =nix run= equivalent)
CLOSED: [2026-09-28 Mon 23:15]

Done as suggested below and confirmed with the user: only the dev shell
flake, only the trusted generation (a changed workspace flake needs a refresh
first), builds allowed without IFD, and =exec= in the caller's environment. =flake.run= is a sandbox method, not a permission kind; see
"=nix run=" in ADR 0007 (=devshell::app=, =Session::run_app=,
=DevShellFlakeRunTests=).


The user asked for this right after =develop=. ADR 0007 sketches it under
"=nix run= (next)"; decide the details below and record them in the ADR.

Goal: =goblins flake run [.#APP] [-- ARGS]= inside a sandbox started with
=--dev-shell= runs a flake app, like =nix run=, with no =nix= in the sandbox.

Suggested design (confirm with the user):

- Scope it to the sandbox's dev shell flake (=DevShell::path=), so the same
  trusted-lock rules apply. Arbitrary remote flakes stay out of scope.
- Evaluate from the *trusted* generation's store source when the workspace
  flake is unchanged; running an app from an already trusted source and lock
  grants no new trust and can be approved automatically (compare
  =inherits_dev_shell=). If the workspace flake differs, either require a
  =goblins devshell refresh= first (simplest), or show the same approval
  preview as a refresh.
- Resolve like =nix run=: =apps.x86_64-linux.NAME= (its =program= must be
  a store path; reject anything else), else =packages.x86_64-linux.NAME=
  with =meta.mainProgram= (or =pname=/=name=) under =bin/=. Default =NAME=
  is =default=.
- Everything runs in the evaluator (=evaluator.rs=), with the goblin's
  network (=Session::evaluation_network=). Verify how to realize an app
  =program= string with context: for example =nix build --print-out-paths=
  on the owning derivation, or evaluate the package and derive the path.
- Mount the program's closure with =Session::mount_paths=, then the
  in-sandbox client =exec=s the program with =ARGS=, keeping stdio. The daemon
  must return only a validated store path; the client must not accept
  anything else.
- Protocol: probably a new permission kind (=flakerun=) or a sandbox method
  that waits like =permissions.request= does (the connection's =waiting=
  field). Add it to =PermissionParams::validate= and to both frontends.
- Tests in =tests/test_devshell.py=: an app from the trusted flake runs; a
  non-store =program= is rejected; a changed workspace flake needs refresh
  (or approval); the host path isolation from the evaluator still holds.

* DONE Launch must not widen access beyond the sandbox's working directory
CLOSED: [2026-09-28 Mon 20:54]

Done: launch refuses a source tree outside the working directory
(=devshell::visible_tree=, shared with refresh), and a dev shell needs a host
working directory. No flag was added.


Refresh refuses a flake whose source tree (its Git work tree) extends beyond
the sandbox's working directory (=Session::prepare_refresh=: =tree.starts_with(cwd)=).
Launch has no such check: =goblins run shell --dev-shell .= from =repo/sub=
evaluates with the whole =repo/= tree visible (=devshell::prepare=, visible
=source_tree(&path)=). Since subdirectory flakes keep their whole source tree
(=path:ROOT?dir=SUB=), a =sub/flake.nix= that an agent edited in an earlier
session can put =repo/= content into the dev shell: a value such as
=builtins.readFile ../secret=, or =${../.}=, which mounts a store copy of the
tracked files through the environment's closure. Only Git-tracked files are
affected, and the host did choose the flake, but the sandbox gets files it was
never granted.

- Apply the refresh rule at launch: refuse when the source tree is not inside
  the launch's working directory (=Launch::cwd=, known in
  =worker.rs= =Source::Host= before =devshell::prepare=), with an error that
  names both paths and says to run from the repository root.
- Or allow it only with an explicit flag (for example
  =--dev-shell-source-tree=) if running from a subdirectory is common.
- Test in =tests/test_devshell.py= with =DevShellSubdirectoryTests=' layout,
  launching from =repo/sub=.

* DONE Approving a dev shell request before its preview exists
CLOSED: [2026-09-29 Tue 02:30]

Done: the request stays visible while it evaluates, so it can be denied
(cancelling the evaluation), but =Controller::decide= refuses approval until
its preview exists ("still being evaluated; decide once its preview is
shown"). The TUI, plain TUI (daemon error) and Emacs do not send an approval
early. Root cause: an early approval cancelled the in-flight evaluation and
queued =Work::Decide= without a candidate. See ADR 0007, Refresh stage 3

Found in a manual run: a =devshell= permission request is visible to
frontends before its candidate evaluation has finished. Approving it then (for
example =approve TOKEN= in =goblins tui --plain= as soon as the line appears)
is accepted, but the refresh fails with "no prepared dev shell refresh"
(=Session::apply_refresh=, =Session::candidate= still unset). Waiting for the
preview avoids it.

- Either refuse a decision on a =devshell= request until its preview exists
  (=Controller::decide= / the =devshell= case of =Work::Decide=), or publish
  the request only once =Completed::Refresh= has produced the preview.
- Whichever is chosen, both frontends (TUI, Emacs) must not offer approval
  without a preview, and the error must be clear.
- Test in =tests/test_devshell.py=: approve immediately after the request
  appears (use a slow evaluation) and check the outcome.

* DONE Recreate children with their root

Children are neither recorded nor recreated, so a coordinator comes back without the reviewers it had launched. * TODO Opt-in notice when a detached host command starts

A detached =goblin host run= is silent until it finishes, so its agent cannot tell "waiting for approval" from "approved and running" without polling =goblin host status= ([[file:../adr/0012-host-commands.md][ADR 0012]]).
