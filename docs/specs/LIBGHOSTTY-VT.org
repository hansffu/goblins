#+title: Terminal emulation with libghostty-vt

The implementation uses the approved Git dependency =Uzaaft/libghostty-rs= at =483ea3d5247b214060da58ef6037a95f30ae89fb= and its pinned libghostty-vt 1.0.1. The first two steps cover build validation and named terminals. The main terminal, snapshot transport and Ghostel bridge are subsequent steps.

This is a handoff document. It is written so that an implementer who was not part of the planning can carry it out step by step. Read it whole before starting, and follow =AGENTS.md= for testing, review and commits.

* Context

Terminal emulation lives in the per-goblin supervisor (crate =libs/supervisor=, binary =goblins-supervisor-bwrap=), not in the daemon. =libs/supervisor/src/screen.rs= wraps the =vt100= crate and serves only the named terminals of [[file:SANDBOX-TERMINALS.org][SANDBOX-TERMINALS.org]] (=goblin terminal create=), which the code calls panes. The main agent terminal (=libs/supervisor/src/terminal.rs=) has no emulator: while detached it keeps the newest 64 KiB of raw PTY bytes (=CAP=), cut at an arbitrary byte, and replays them on attach without restoring modes, the alternate screen or the cursor.

libghostty-vt reached a stable 1.0 on 2026-11-06. It is the engine ghostel renders with. It answers terminal queries itself, formats a screen as VT text, and encodes the whole terminal state as a binary snapshot. Ghostel 0.65 can restore such a snapshot into a terminal that has no process. The Rex multiplexer works this way (snapshot on attach, then raw PTY bytes), and [[https://github.com/dakra/rexel][rexel]], by ghostel's author, is an Emacs client for it.

* Outcome

One emulator, libghostty-vt, behind both the named terminals and the main agent terminal, with two ways to bring a frontend up to date on attach.

- VT replay, the default. The supervisor writes VT text that redraws the screen, then raw bytes. It works in any terminal, and the Python suites that drive the CLI in a pty keep working unchanged.
- Snapshot replay, with =--snapshot= on the attach commands. The supervisor writes a binary snapshot, then raw bytes. It is for ghostel, which decodes the snapshot itself. A plain terminal, the Ghostty application included, cannot take one.

* Decisions already made

Do not reopen these; ask the user if one turns out to be impossible.

- The Rust binding is [[https://github.com/Uzaaft/libghostty-rs/][Uzaaft/libghostty-rs]] (crates =libghostty-vt= and =libghostty-vt-sys=), the one Ghostty's author promotes. No other crate, no in-repo binding.
- Named terminals and the main agent terminal both move to the new emulator, as separate steps and commits.
- VT replay stays the default; snapshot replay is opt-in per attach command.
- While a frontend is attached it answers the program's terminal queries, in both replays. The supervisor answers only while nobody is attached. This is today's rule and it stays.
- No backward compatibility is needed: the project is experimental. Old wire forms and their tests may be dropped when they are in the way.
- Keep it simple. Fix real defects; do not add machinery because a reviewer suggests it.

* Out of scope

- =goblins exec -t= shells (=packages/daemon/src/exec.rs=), the server-mode log (=libs/supervisor/src/server_log.rs=) and the terminals of onAttach clients (=Terminal::client=) stay unemulated.
- No =read=, =send= or =wait= for the main agent terminal.
- No in-band control messages, no reconnect or resume, no several frontends on one terminal. Rexel has all three; we need none.
- Replacing =key_bytes= (=libs/runtime/src/terminal.rs=) with libghostty's key encoder.

* Reference: the binding (as of =483ea3d=)

#+begin_src rust
use libghostty_vt::{Terminal, fmt::{Formatter, Format, Extras}, mode::Mode, point::{Point, Coordinate}};

let mut t = Terminal::new(cols, rows)?;          // NOTE: cols first. Goblins passes (rows, cols) everywhere.
t.on_pty_write(|_term, bytes: &[u8]| { /* query replies for the PTY */ })?;
t.vt_write(bytes);                               // feed program output
t.resize(cols, rows, cell_width_px, cell_height_px)?;   // reflows the primary screen
t.set_scrollback_max_lines(Some(n))?;
t.set_continuation_max_bytes(n)?;                // needed before input, for snapshots taken mid-sequence
t.rows()?; t.cols()?; t.cursor_x()?; t.cursor_y()?; t.is_cursor_pending_wrap()?;
t.active_screen()?;                              // screen::Screen::{Primary, Alternate}
t.mode(Mode::BRACKETED_PASTE)?; t.mode(Mode::DECCKM)?;
t.total_rows()?; t.scrollback_rows()?;
t.grid_ref(Point::Screen(Coordinate { x, y }))?; // .row()?.is_wrapped()?, .cell()?, .graphemes(&mut buf)?
t.encode_snapshot(&mut writer)?;                 // binary snapshot, starts with b"GHOSTSNP"

let mut f = Formatter::new(&t)?;                 // "a terminal's active screen"
f.set_format(Format::Vt)?.set_extras(extras)?;   // also Format::Plain, set_unwrap, set_trim
let bytes = f.format_alloc(None)?;

let restored = libghostty_vt::snapshot::Decoder::new_buf(&snapshot)?.decode()?;
#+end_src

- Other callbacks exist (=on_device_attributes=, =on_xtversion=, =on_title_changed=, =on_clipboard_write= and more). Register only what a step asks for.
- =Terminal= carries two lifetimes and is neither =Send= nor =Sync=. Store it as =Terminal<'static, 'static>= with callbacks that own their state (for example an =Rc<RefCell<Vec<u8>>>= for replies).
- Building: the crate's =pkg-config= feature links an installed =libghostty-vt= (static by default) instead of compiling Ghostty with Zig in the build script. Use that feature; a Nix build has no network for the default path.
- The snapshot format is versioned separately from the library's ABI: a snapshot starts with =GHOSTSNP= and a format version, 1 for libghostty-vt 1.0, and a decoder refuses any other. The decoder must read the encoder's format; the library versions may differ (see step 4).

* Reference: ghostel's bridged terminal (0.65.0)

#+begin_src elisp
(ghostel-make-terminal BUFFER-OR-NAME :size '(COLS . ROWS) :send FN :resize FN)
;; Makes a terminal without a process and returns its buffer.
;; SEND gets outbound bytes (typed input and query replies) as one unibyte string.
;; RESIZE gets (COLS . ROWS) fitting the buffer's windows, also when unchanged.
;; After creation only `ghostel-set-size' resizes the terminal.
(ghostel-restore-snapshot DATA)   ; unibyte string; call before the terminal has seen any output
(ghostel-write-output BYTES)      ; unibyte program output; replies go to SEND
(ghostel-set-size '(COLS . ROWS))
(ghostel-end-terminal)            ; the other side is gone; the buffer stays as a read-only snapshot
#+end_src

=lisp/rexel.el= in rexel shows all of these in use (=rexel--attach-block-buffer=, =rexel--restore-snapshot=, =rexel--on-live-bytes=). Rexel passes a second argument to =ghostel-write-output= to drop replies because its server answers queries; we do not pass it.

** Build spike results

The pinned bindings compiled with Rust 1.99.0 and linked the Ghostty flake's =libghostty-vt= package using =pkg-config=. With only the PTY write callback installed, the device attributes, status and cursor queries all returned replies, including the existing =CSI ? 62 ; 22 c= device attributes. Grid references enumerate scrollback oldest first. Both plain and VT formatting include primary scrollback. VT formatting restores cursor position, pending wrap and modes. The replay supplies the title and cursor shape separately and releases synchronized output. Resize accepts zero pixel dimensions.

The supervisor engine owns the emulator on its event-loop thread. The worker thread owns session operations and exchanges messages with the engine through channels. The shared Rust runtime trait permits single-threaded implementations, and the daemon keeps the =Send= bound on its own runtime objects.

Both the Rust decoder and Ghostel 0.65.0 restored a 1.0.1 snapshot captured in the middle of =CSI 31 m=. After feeding the rest of the sequence, the next character appeared red. Ghostel 0.65.0 bundles libghostty-vt 1.0.0. This verifies the tested continuation across those patch releases. The exact failed check in upstream CI run 43535091846 was unavailable from the public log. The pinned Linux x86_64 package built locally.

- With =--snapshot= the command is a byte bridge for a program, not for a person at a terminal: it does not require a tty, sends =replay: "snapshot"= and the given size in the hello instead of asking the tty, does not put the tty in raw mode, does not react to SIGWINCH and does not request the initial resize (=RESIZE.store(true)=). It copies the socket to standard output unchanged, so the first bytes it prints are the length and the snapshot, and standard input to the socket.
- The two ways it ends are different. When the socket reaches its end (the terminal completed or was detached), it does what the command does today: the outcome lookup and its exit status. When standard input ends, it closes the socket and exits with status 0 at once, without the outcome lookup, which would wait for a payload that is still running; the terminal goes on. =relay_with= reads standard input only on =POLLIN= (around line 161), and a closed empty pipe reports =POLLHUP= alone, so handle =POLLHUP= on it in this mode or the command spins. Today's tty path, where lost input is an error, stays as it is.
- Messages for people, such as "Starting…", already go to standard error; make sure nothing else is written to standard output in this mode.
- The frontend resizes with =sessions.resize= or =terminals.resize=, which exist.

* Working rules for the implementer

These are in =AGENTS.md= or were learned in this repository; they are repeated because they are easy to miss.

- Work inside =nix develop= from the Git-backed flake. New files must be staged before a Nix build sees them.
- One test runner at a time per checkout. Run suites serially and send output to a log file.
- Python suites that start sessions cannot run inside a goblin sandbox (Operation not permitted); run them on the host with =goblin host run=.
- Order tests by cost: fast Rust tests first, slow host suites only when those pass. When a slow suite finds a defect, add a fast Rust regression test for it.
- Each step: make the change, run its feature tasks, send the uncommitted diff to the reviewer of the other model with the intent and this document, fix until nothing remains, then commit. One commit per step, no amending, no pushing.
- Before merge, =just test-merge= on the final candidate.
- Documentation prose is one line per paragraph. =docs/API.org= changes in the same commit as any RPC change.
- Never fake a pass: no removed assertions, disabled cases or added retries.
- Do not edit the user's own Emacs or Nix configuration; say what needs changing there (ghostel 0.65 for the option in step 4).
- Stop and ask the user when a decision above cannot be kept, when the spike answers a question with "no", or when step 2 cannot be done without changing the daemon-visible behaviour of the main terminal.
