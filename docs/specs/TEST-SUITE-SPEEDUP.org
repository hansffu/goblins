#+title: Plan: a faster test suite
#+date: 2026-11-13

Status: proposed. Nothing in this plan is implemented. The measurements were taken on 2026-11-13 at commit =ac83ec6=.

* Goal

Cut the wall time of the merge gate (=just test-merge=), and of the Python integration stage in particular, without removing coverage or isolation.

The time is not in daemons or sandboxes; it is in Nix. Every Nix command that names the pinned nixpkgs through a =path:= flake reference re-hashes the whole 469 MB nixpkgs tree (about 2.7 s) before it evaluates anything. Package grants and dev-shell operations each run several such commands, so they dominate the suite. The plan removes that cost first (one product change, one test-fixture change), removes fixed waits and one duplicated test, and only then retunes the scheduler, because the same hashing is what makes parallel workers contend on disk I/O.

* How to work through this plan

Work through the tasks in order, one task per change. Each task is its own reviewed change and its own commit, following =AGENTS.md=: review by a goblin of the other model, commit only after the reviewer has no findings, =just test-merge= before merge. Steps are checkboxes; tick them as they are done.

Tasks 5 to 9 each start with a decision the user must make. Do not start them without that answer.

* Measured baseline

Machine: 32 cores, 30 GiB RAM, Nix 2.34. Commands ran inside =nix develop= with ~GOBLINS_TEST_CODEX=1~, as the merge gate does.

** Stage times

| Stage          | Command                                                    | Warm  | Cold (first run after a Rust change) |
|----------------+------------------------------------------------------------+-------+--------------------------------------|
| Rust           | =just test-rust=                                           | 60 s  | several minutes of compiling         |
| Python         | =python3 tests/run.py -j 2=                                | 926 s | 1115 s                               |
| Emacs ERT      | =just test-emacs=                                          | 3 s   | 3 s                                  |
| Nix checks     | =just test-nix=                                            | 7 s   | about 520 s                          |
| Packaged smoke | =tests/run.py --packaged test_server test_exec test_roots= | 14 s  | 14 s                                 |

The whole cold gate took 30 min 24 s at 29% of one CPU, and the warm gate 17 min 17 s at 33%: the machine is almost idle while the suite waits on Nix and on fixed sleeps.

** Cost of the primitives

| Operation                                                           | Time                         |

| =nix print-dev-env= on a flake with no nixpkgs input (see Task 7)   | 2.2 s first build, then 0.03 s |

Conclusions that follow from this table:

- Restarting daemons and sandboxes per test costs about 0.4 s per test. Sharing daemons between tests would save well under a minute over the whole suite and would give up isolation. *Do not do it.*
- A package grant costs 6 s because it runs =nix eval= twice and =nix build= once, each paying the 2.7 s nixpkgs hash. About 20 test modules grant packages.
- A dev-shell launch or refresh runs four or five Nix commands against a flake whose nixpkgs input is =path:<nixpkgs>=, so each costs 12–20 s. The 30 dev-shell tests account for about 355 s of group time.
- [[file:../RESULTS.org][RESULTS.org]] ("Four-worker opt-in and I/O investigation") recorded I/O pressure of 50% =full= during the suite and only a 16% gain from four workers. The nixpkgs hashing is the likely source: every hash streams 469 MB through the Nix daemon.

** DONE Task 6: Evaluate catalogue packages without re-hashing nixpkgs

*User decision needed first.* This is a product change with a security-relevant evaluation mode, so it needs the user's approval and probably an ADR. Present the following and wait.

What happens today: =libs/supervisor/src/catalog.rs= builds the installable =<flake>#legacyPackages.x86_64-linux.<name>= and runs =nix eval= on it for the preview, =nix eval= again on approval, and =nix build= (=libs/supervisor/src/session.rs=, =fn build=). The =flake= value is always =path:${pkgs.path}= (=packages/daemon/wrapper.nix:27=, =tests/fixtures.nix:15=). Nix 2.34 hashes the whole tree for a =path:= reference on every command: 2.7 s before evaluation starts, measured with =nix flake metadata=, and adding =?narHash== does not avoid it. A real user waits about 3 s for every package preview and 6 s for a grant for the same reason.

Proposed: the runtime manifest names the pinned nixpkgs source explicitly, in a new optional =nixpkgs= entry beside =flake=, and when that entry is present the daemon evaluates the same package set directly from that store path. The location of =flake= alone must not decide this: the manifest accepts any flake reference, and a store-backed flake can expose =legacyPackages= without a compatible =default.nix=, or with different packages. Without the entry, nothing changes.

The direct evaluation is:

#+begin_src sh
nix --extra-experimental-features 'nix-command flakes' eval --impure --option restrict-eval true \
    -I nixpkgs=<store path> --json \
    --expr '(import <nixpkgs> { system = "x86_64-linux"; config = {}; overlays = []; }).<name>' \
    --apply '<the existing selection function>'
#+end_src

Measured on this machine against the same nixpkgs: 0.29 s instead of 2.9 s, the same output path for =hello=, =unrar= still refused as unfree with ~NIXPKGS_ALLOW_UNFREE=1~ in the environment, =builtins.getEnv "HOME"= returns the empty string and =builtins.pathExists /etc/passwd= is false (restricted evaluation hides the environment and every path outside =-I=). =nix build ... --expr= with the same options took 0.31 s for an already-built package.

Known differences the user should weigh: =--impure= is required for =<nixpkgs>= lookup, with =restrict-eval= as the guard instead of pure flake evaluation; without =restrict-eval=, plain =--impure= does let =NIXPKGS_ALLOW_UNFREE= through; Nix's error text for a missing attribute changes (see Step 4); the nixpkgs flake adds version metadata to =lib= that a plain import lacks, which did not change any output path tested.

Interfaces:

- Produces the optional runtime-manifest entry =nixpkgs=: an absolute store path of a nixpkgs source tree. It is optional so that existing manifests stay valid; the manifest structs reject unknown fields, so the field must be added before any manifest carries it. If the manifest format is described in =docs/USAGE.org= or a spec, document the entry there in the same change.
