#+title: Goblins JSON-RPC API reference

This is the reference for the daemon's JSON-RPC API 1: every method on the host and sandbox endpoints, with its parameters and result. [[file:specs/DAEMON.org][specs/DAEMON.org]] records why the protocol is shaped this way; this file records what it is now. Keep it current when a method, parameter, result or record field changes (see =AGENTS.md=).

The handlers live in =packages/daemon/src/controller.rs= (=host=, =sandbox_control= and =dispatch=), =controller/raids.rs=, =controller/host.rs=, =controller/exec.rs=, =controller/terminals.rs=, =controller/editor.rs=, =messaging.rs= and =mailbox.rs=. Parameter types are in those files and in =libs/api/src=; shared runtime record data is in =libs/runtime/src=.

* Transport

** Endpoints

| Endpoint | Path                                     | Caller                                   |
|----------+------------------------------------------+------------------------------------------|
| Host     | =$XDG_RUNTIME_DIR/goblins/host.sock=     | The trusted host user: CLI, TUI, Emacs   |
| Sandbox  | =/run/goblins/request.sock= (in sandbox) | A goblin; the daemon knows which one     |

=goblins --state-dir DIR= moves the host socket to =DIR/host.sock=. The sandbox endpoint identifies its caller from the socket it connected through; no parameter can name another sandbox as the caller.

** Framing

Each message is a JSON-RPC 2.0 object preceded by an LSP-style header:

#+begin_example
Content-Length: 61\r\n
\r\n
{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"api":1}}
#+end_example

- The header is at most 256 bytes. A response body is at most 1 MiB.
- Request bodies: messaging methods accept up to 64 KiB. Other host methods, =sessions.set-variables= and =permissions.request= accept 16 KiB; other sandbox methods 4 KiB.
- Frame deadlines are 3 seconds. Every connection must send its complete =initialize= frame within 3 seconds of being accepted, and a sandbox connection must send its one following call within 3 seconds of initializing. On an initialized host connection the clock starts at each frame's first byte, so an idle host connection never times out.
- Parameters normally use named objects; positional-array forms are documented per method as their contracts are migrated. An omitted =params= means ={}=. Unknown named parameters and envelope fields, duplicate keys, nesting deeper than 32 and batches are rejected. Request IDs must not be null. Notifications from a client (no =id=) are ignored, except =exec.signal= on an exec connection.
- Results may gain fields, including in nested objects such as initialization limits and history status; clients should ignore fields they do not know. This tolerance does not relax validation of known fields or unknown request parameters.

** Connections

Every connection starts with =initialize=. A host connection may make up to 4096 calls including =initialize=, and hold one state subscription; the daemon accepts up to 32 host connections. A sandbox connection makes one call after =initialize= and is then closed by the daemon (up to 8 connections per sandbox).

=goblins rpc METHOD 'PARAMS'= opens a host connection, makes one call and prints the result. It cannot follow =state.subscribe=, and cannot call =sessions.exec=, which needs passed file descriptors.

** Terminal attachment

Each session has two attachment sockets beside each other in its state directory; =sessions.get= returns their paths as =terminal= and =attach=. A daemon whose host =features= include =attach-handlers= serves =attach.sock=, which frontends use for every goblin; =terminal.sock= keeps the older protocol.

- =attach.sock= :: The frontend first writes a framed notification ={"jsonrpc": "2.0", "method": "attach.hello", "params": {"version": 1, "rows", "cols"}}= within 3 seconds; the daemon reads nothing else before it. =rows= and =cols= (1 or more) size this attachment: a goblin's single terminal is resized to them once attached, and a client started by =onAttach= gets a new PTY of that size. The daemon then answers with framed notifications ={"jsonrpc": "2.0", "method": "attach.waiting", "params": {"missing": [names]}}=, at once and every second while it waits, then one framed reply with ID 0: ={"attached": true}= or an error (=-32009=). While the goblin is still starting, =missing= is empty. For a goblin with =onAttach=, =missing= names the variables its client still needs, which must be set to a value during this run (=sessions.set-variables=); a timeout fails the attachment with the names, the server log path and "restart the goblin". An attachment to a stopped or failed goblin is refused with why and, when it has one, the server log path. Raw terminal bytes follow only a successful reply. After a detach, the stream remains reserved until the frontend closes its end after reading the outcome; another frontend is refused during that handoff. One attachment at a time: a second is refused, and changes no size. With a =terminal= field in the hello (the ID or name of one of the goblin's terminals, see Terminals) the attachment is to that terminal instead of the goblin's own, independent of it and of =onAttach=: it is answered at once without =attach.waiting=, =rows= and =cols= must be 1–500, and the terminal's PTY is resized to them once attached. The reply is ={"attached": true}= or an error (=-32009=) saying why: no such terminal, already attached (one frontend per terminal), a goblin that is not running, or one whose configuration refuses exec. After the reply the stream carries the terminal's redraw, then live output; a frontend that closes its end detaches and the terminal keeps its last size. The stream ends when the terminal is detached (=terminals.detach=) or ends: the frontend then lists the terminals once, and finds the terminal listed with =attached= false when it was detached, otherwise ended.
- =terminal.sock= :: The runtime attaches an accepted connection at once and writes the same framed reply, then raw bytes. For a goblin with =onAttach= it refuses every connection with an error asking to upgrade Goblins. A connection made before the runtime has read the goblin's configuration waits until then. After the goblin stops, retained terminal output remains available through this socket until the terminal can be evicted.

A stopped goblin's retained terminal output does not reserve its agent name or recorded conversation, or retain its scope membership and storage. These are released after sandbox cleanup, independently of a frontend consuming the remaining output.

Attachment contracts are defined in =libs/api/schema/attach.openrpc.json=: =attach.hello= and =attach.waiting= are notifications, and =attach.reply= / =legacy.attach= identify fixed-ID completion exchanges. The frontend hello takes a closed object or =[version, rows, cols, terminal]= with three or four elements; version is a required unsigned 64-bit integer, dimensions are required unsigned 16-bit integers and terminal is optional/nullable. Version 1 and nonzero dimensions are checked after structural decoding; zero dimensions retain the existing unsupported-version diagnostic. Main/onAttach attachments allow 1–65535 dimensions; named terminal attachment validates 1–500 after state/policy checks. The hello body limit is 4 KiB, its frame deadline is three seconds, and at most eight pending hellos exist per goblin.

Current waiting notifications have a required string-array =missing= field and no ID; current completion frames have exactly =jsonrpc=, =id= 0 and either =result= or =error=. A success result requires boolean =attached=true= and may gain fields. Public refusal errors use =-32009=. The legacy CLI classifies waiting frames by their method alone and tests only whether =params.missing= is a nonempty array; it preserves this fallback for older peer frames without tightening their envelopes or element types. Its final completion retains strict envelope/ID checks, accepts any otherwise-valid error code, and requires =attached=true=. Each waiting frame renews the next frame's first-byte deadline; interruption ends the wait while resize signals leave it active. The host CLI performs this parsing for Emacs too; Emacs has no separate attachment JSON parser. The stream switches to raw bytes only after a successful completion frame.

A goblin with =onAttach= has no terminal of its own: each attachment runs its client, detaching (=sessions.detach= or the frontend closing) runs =onDetach= and then ends the client and everything it started, and the client exiting detaches. =terminal_detached= becomes true once the client has exited; processes it left behind are cancelled. A new attachment arriving while the exited client’s frontend is still draining receives =attach.waiting= with an empty =missing= list until the old stream closes; a client that has not exited still refuses competing attachments.

** Errors

| Code     | Meaning                                                                  |
|----------+--------------------------------------------------------------------------|
| =-32700= | Invalid JSON, duplicate keys or nesting too deep                         |
| =-32600= | Malformed frame (bad header or =Content-Length=, oversized body, missed deadline); invalid envelope (JSON-RPC version, null or invalid ID, method name over 64 bytes); or unexpected bytes after a one-shot request |
| =-32601= | Method unavailable on this endpoint                                      |
| =-32602= | Invalid parameters; the message says which                               |
| =-32001= | A method was called before =initialize=                                  |
| =-32002= | Unsupported API version                                                  |
| =-32003= | Host command limit: too many running, or too many large requests waiting for a decision |
| =-32004= | Record absent or no longer retained                                      |
| =-32009= | Stale or conflicting operation, wrong state, or the server is stopping   |
| =-32010= | Resource limit reached, or the sandbox's init cannot be reached          |

Session parameters named =session= accept a session ID or the agent name of a live goblin unless stated otherwise.

* Initialization (both endpoints)

The schema-first migration currently covers =initialize=, host =server.status= / =server.stop=, sandbox =sessions.status= / =sessions.set-state= / =sessions.set-variables= / =sessions.set-worktree=, host/sandbox =sessions.list= / =sessions.get= / =sessions.start= / =sessions.stop= / =sessions.detach=, host =sessions.resize=, and sandbox =targets.list=. Their machine-readable contracts are in =libs/api/schema/=, with the generated [[file:API-REFERENCE.org][covered-method reference]]. Other surfaces remain specified here and assigned to later chunks in =libs/api/schema/coverage.json=. Generated types supplement the existing transport, policy and lifecycle checks.

The result descriptions specify what the current daemon produces. Compatible API-1 clients also accept older replies without additive metadata: =configuration= and limits information in =initialize=, and =history=, =manifest= and =worktrees_directory= in =server.status=. The =x-client-result-schema= extension defines those generated client reply types; missing information remains optional, and clients use advertised features before relying on capabilities. Tests of the current daemon still enforce the current producer schema.

** =initialize=

Negotiates the API version and identifies the daemon.

- Input :: ={"api": 1}=
- Parameter forms :: The existing decoder also accepts =[1]=. =api= is a required unsigned 32-bit integer; unsupported versions return =-32002=. Unknown named parameters, missing/null values and extra positional values return =-32602=. Parameter validation precedes repeated-initialize =-32009= and unsupported-version checks.
- Output :: ={"api": 1, "instance", "role": "host"|"sandbox", "configuration", "features": [...], "limits": {...}}=. =instance= identifies this daemon run. =configuration= is the caller's configuration name on the sandbox endpoint, null on the host endpoint. =features= lists capability strings (for example =state-subscribe=, =raids=, =exec=, =terminals=, =host-commands=, and =attach-handlers= for =attach.sock=). =limits= has =header=, =body=, =frame_seconds=, =depth=, =response_body=, =calls=, =connections=, =sessions=, =output_queue=, =snapshot= and =terminal_buffer=.

* Host endpoint

While the server is stopping, every method except =server.status= and =server.stop= fails with =-32009=.

** Server

*** =server.status=

Reports whether the server is running and how many goblins it has.

- Input :: ={}=
- Parameter forms :: =[]= is also accepted; omitted =params= defaults to ={}=. Null, unknown fields and extra positional values return =-32602=.
- Output :: ={"instance", "state": "running"|"stopping", "sessions": N, "history", "manifest", "worktrees_directory"}=. =sessions= counts goblins with a live worker. =history= is ={"directory", "owner": true, "keep", "recording"}= when this server owns the history store, or ={"directory", "owner": false, "reason"}= when it does not. =manifest= is the current runtime manifest path or null. =worktrees_directory= is the expanded =mkGoblins.worktrees.directory= of the current configuration, or null when worktrees are off (see [[file:specs/WORKTREES.org][specs/WORKTREES.org]]); a host client creates worktrees beneath =DIRECTORY/REPO= with Git.

*** =server.stop=

Stops the server and every goblin. The connection is closed after the reply.

- Input :: ={}=
- Parameter forms :: As for =server.status=, both ={}= and =[]= are accepted, including omitted =params=.
- Output :: ={"accepted": true}=

** State

*** =state.subscribe=

Returns the current state, then pushes a complete replacement snapshot on every change. One subscription per connection.

- Input :: ={}=
- Output :: ={"subscription", "sequence", "snapshot": Snapshot}=
- Notifications :: ={"method": "state.changed", "params": {"subscription", "sequence", "snapshot": Snapshot}}=. =sequence= increases by one per published change. A subscriber whose output queue (2 MiB) overflows is disconnected and must subscribe again; no change is skipped silently.

*** =state.unsubscribe=

Ends this connection's subscription.

- Input :: ={"subscription"}=
- Output :: ={"accepted": true}=

State methods are host-only, and state.changed is a daemon-to-host notification on an active subscription, not a callable method. Named params are closed; original positional forms are =[]= and =[subscription]=. The generated parameter types retain direct Serde decoding, including original type, unknown-field and excess-length errors. Invalid params return -32602; existing or stale subscriptions and a stopping server return -32009. A request decodes before its subscription conflict check. Ordinary host calls preserve subscriptions; state.unsubscribe and server.stop clear them.

A new subscription first publishes earlier dirty mutations, then assigns its ID and returns the global sequence with a full current snapshot. The sequence is an unsigned 64-bit JSON integer and can initially be zero. A dirty publication reconciles raid state, increments the global sequence once and sends every subscriber ={"jsonrpc":"2.0","method":"state.changed","params":{"subscription","sequence","snapshot"}}= with no request ID. No dirty state means no publication. Unsubscribe replies accepted:true, requires the exact active ID and emits no later updates for that subscription; repeated or stale IDs conflict.

Rust initial readers independently project string subscription, u64 sequence and raw snapshot, set the stream nonblocking, then retain the original missing-subscription/missing-sequence/snapshot errors. They accept an initial snapshot instance different from initialize, as before. Update readers preserve additional outer fields (including id), enforce jsonrpc/method/subscription/next sequence, then decode a compatible snapshot and check its instance before replacing cached state. A good frame preceding a bad frame remains committed even when the same tick returns an error. Each tick reads and consumes at most 16384 bytes, retains partial frames/no-data behavior, and checks EOF before buffered input; dropping the subscription closes its stream without an unsubscribe RPC. Decoder/queue bounds and cleanup ownership remain unchanged.

Emacs uses generated lazy field views and method/notification identities while retaining its separate compatibility policy: initial and update boundaries can accept a partial snapshot containing instance, and sequences use integerp, including signed and arbitrarily large integers. Existing callback order, failed-stream cleanup, snapshot replacement and rendering remain unchanged. These client policies do not weaken the strict current-producer schema and are not replaced by full snapshot validation at a new point.

** Sessions

*** =sessions.list=

Lists retained session records, including starting and stopped ones. The host and sandbox read methods have separate generated record projections; the host carries process identities and host paths, while the sandbox projection below carries only its documented subset. Their OpenRPC contracts also describe positional forms: =[]= for list and =[session]= for get. Requests reject unknown fields; result records and nested records permit new fields. Rust readers keep the omissions and defaults already supported by API-1 snapshot clients, including the legacy =docker_scope= alias for =scope=. Direct host reads also accept the original API-1 records without =agent_name=, retaining that omission; snapshot views keep their existing requirement for a name. Compatibility replies preserve lifecycle and terminal-origin strings accepted by earlier readers, while current producers use the documented enums; snapshot views still validate activity with their prior =AgentState= enum. A snapshot containing both =scope= and =docker_scope= is refused. The JSON list commands validate the generated result contract and print the original result JSON, retaining nulls, old omissions and extension fields. Public projections follow the documented tolerance for new result fields, including nested worktree and skipped-item summaries; the runtime's stricter validators for local persisted records stay separate.

- Input :: ={}=
- Output :: =[Session]=

*** =sessions.get=

Returns one session record by immutable ID, including a retained stopped record, or by a live goblin's unique agent name. An absent record is =-32004=.

- Input :: ={"session"}=
- Output :: =Session=

*** =sessions.start=

Launches a goblin from a configuration, or recreates a recorded one. Returns once the launch is accepted; follow its state through =sessions.get= or the subscription.

The positional form is =[key, configuration, name, agent_name, cwd, scope, dev_shell, rows, cols, detached?, raid?, recreate?, options?]=. All first nine slots through =cols= are required. Use null for unset nullable slots; =name= is an empty string for recreate. This order is the original decoder order and is independent of generated Rust field order.

- Input :: ={"key", "configuration", "name", "agent_name", "cwd", "scope", "dev_shell", "rows", "cols", "detached", "raid", "recreate", "options"}=
  - =key= (required): a retry key, 1–64 of =[A-Za-z0-9_-]=. Repeating a start with the same key and parameters returns the original acceptance; different parameters conflict.
  - =configuration= (required): absolute path of the runtime manifest file.
  - =name=: the configuration key (for example =shell=), 1–64 of =[A-Za-z0-9_-]=. Omitted or empty for a recreate.
  - =agent_name= (optional, may be null): the goblin's name, matching =[a-z][a-z0-9-]{0,31}= and unique among live goblins; omitted or null picks one from the name list.
  - =cwd=, =scope=, =dev_shell= (optional): absolute launch directory; scope to join, matching =[A-Za-z_][A-Za-z0-9_-]{0,63}=; absolute =PATH[#ATTR]= of a host flake dev shell.
  - =rows=, =cols= (required): initial terminal size, 1–1000 each.
  - =detached= (optional): start without a terminal consumer.
  - =raid= (optional): join this raid, creating it with the new goblin as owner. Raid names match =[a-z][a-z0-9-]{0,31}=.
  - =recreate= (optional): history record ID, unique prefix or unique agent name to recreate.
  - =options= (optional): typed host clients omit an empty map, retaining compatibility with API-1 daemons predating this field. Host run retains explicit null =agent_name=, =scope= and =dev_shell= fields when unset; host resume omits =name= and those unset fields. Launch options are only for members a raid owner runs; a non-empty map is refused with =-32602= =launch options are only for raid members=.
- Output :: ={"session", "agent_name", "state": "starting", "terminal", "attach"}=. =terminal= and =attach= are the paths of the session's attachment sockets (see Terminal attachment).

*** =sessions.stop=

Requests teardown. Acceptance does not mean cleanup has finished.

- Input :: ={"session"}= or =[session]=
- Output :: ={"accepted": true}=

*** =sessions.detach=

Detaches the current terminal consumer; the goblin keeps running. For a goblin with =onAttach= this runs =onDetach= and ends the attached client.

- Input :: ={"session"}= or =[session]=
- Output :: ={"accepted": true}=

*** =sessions.resize=

Resizes the session's PTY, or for a goblin with =onAttach= the attached client's PTY (=-32009= when none is attached). Parameters decode directly as the original =Resize= record, in =session=, =rows=, =cols= order, preserving Serde errors for malformed objects and positional arrays. Decoding precedes dimension validation (1–1000), which precedes session lookup; invalid dimensions therefore do not depend on whether the session exists.

- Input :: ={"session", "rows", "cols"}= or =[session, rows, cols]= (=session= is an exact session ID; rows and cols 1–1000)
- Output :: ={"accepted": true}=

*** =sessions.exec=

Runs a command inside a running goblin. The request must carry file descriptors (=SCM_RIGHTS=) with its first byte: one PTY slave with =tty=, otherwise stdin, stdout and stderr. The reply arrives when the command exits, and the connection then closes. While it runs, the client may send =exec.signal= notifications (={"signal": N}=) to forward a signal.

- Input :: ={"session", "pin", "argv", "cwd", "env", "tty", "interactive"}=. Only =session= is required. The positional form follows that exact order, with one through seven elements. Missing or null =pin=, =argv= and =cwd= mean no pin, the sandbox's =$SHELL= and its working directory respectively. Otherwise =argv= has 1–1024 arguments of at most 64 KiB each, without NUL; =cwd= is absolute, without NUL and at most 4096 UTF-8 bytes. =env= defaults to =[]= and is a list of at most 256 =[name, value]= pairs: names match =[A-Za-z_][A-Za-z0-9_]{0,255}= and values have at most 64 KiB without NUL. =tty= and =interactive= default to false; an explicit =-t= shell is counted in =shells= only when both are true. Unknown named parameters, null =env= and invalid element types are refused.
- Output :: ={"code", "signal"}= when it exited, with both fields present and independently nullable signed 32-bit integers, or ={"code", "message"}= when it could not be started, with a signed 32-bit shell code and a diagnostic string. If init could not be asked, the call returns =-32010= instead of a result. Added result fields are ignored by readers; the CLI independently treats malformed or missing code/signal/message fields as absent, retaining valid fields alongside them. A non-object legacy result has no recognized fields; the CLI uses exit 255 when neither code nor signal is usable. The named =exec-field-fallback= adapter normalizes those historical inputs into generated client fields; it does not relax current producer schemas.

The host-only =exec.signal= notification has no =id= and takes ={"signal": N}= or =[N]=, where =N= is a signed 32-bit integer and one of =SIGHUP= (1), =SIGINT= (2) or =SIGTERM= (15). While an exec is active, invalid parameters, unsupported signals, any request ID or a different method close that connection; cleanup cancels only its exec. Outside active exec, a no-ID notification is ignored after envelope parsing; a host request with an ID and method =exec.signal= is unknown (=-32601=). The notification never enters a callable-method or sandbox allowlist.

The host connection accepts at most three accumulated descriptors (=goblins_protocol::HOST_MAX_FDS=), including across fragmented reads; this is separate from the private supervisor transport's 240-descriptor frame limit. Exec validation also checks the canonical serialized init =spawn= command against 64 KiB, counting the allocated exec ID and JSON escaping; only a larger encoding returns =-32602= with =command too long=. This check remains after target/policy/capacity/init-availability checks and before stdio transfer or exec registration. The shared validator changes neither public framing limits nor refusal order.

*** =sessions.kill_execs=

Kills every exec running in a goblin. The kill is best effort: the answer means it was handed to the goblin's runtime, not that every exec has ended; each exec's own call ends when it does. A goblin whose sandbox init has gone answers =conflict=.

- Input :: ={"session"}= or =[session]=. Dots in this selector are replaced with slashes before resolution; unknown fields are refused.
- Output :: ={"accepted": true}=

** Terminals

A terminal is a named, long-lived program on a PTY that the goblin's supervisor owns, so it keeps running with nobody attached. It belongs to one goblin; the host endpoint can use any goblin's terminals. Host methods take =session=, an agent name or session ID. Operations on a running program fail with =-32009= when the goblin is not running; =terminals.list= also reads retained stopped records. =terminals= in =features= says the daemon has these methods. A goblin whose configuration refuses exec refuses terminals. A terminal runs through goblins-init as an exec does, with an exec's environment, in =cwd= or the goblin's working directory; it counts toward neither =shells= nor =execs=.

A terminal has an ID, =t1=, =t2=, …, counting up for the goblin's run and never reused in it, and optionally a name: a lowercase letter, then lowercase letters, digits, =-= and =_=, at most 32 characters in all, not of the form of an ID, and unique among the goblin's live terminals. =terminal= parameters take the ID or the name. At most 16 terminals exist per goblin. Sizes are 1–500 rows and columns. A terminal ends when its program exits, when it is closed, or when the goblin stops; detaching never ends it. It then leaves the list: the supervisor first keeps reading its PTY for up to a second after the exit, so the output the program left is read, settles the waits on it, ends everything the program started, and gives an attached frontend up to one more second to read what is queued before closing its stream. Terminals are not restored when a goblin is recreated.

The supervisor feeds each terminal's output through a terminal emulator with 5,000 lines of scrollback and keeps reading while nobody is attached, answering meanwhile the queries a shell asks at startup, as a plain VT220-class terminal: the device attributes (=CSI c=, =CSI 0 c=) with =CSI ? 62 ; 22 c=, the status report (=CSI 5 n=) with =CSI 0 n= and the cursor position (=CSI 6 n=) with the emulator's =CSI row ; col R=, and nothing else; an attached frontend answers for itself. It tracks the alternate screen and the input modes the program sets (cursor keys, bracketed paste, mouse reporting). A frontend that attaches first gets a redraw: on the normal screen the scrollback as lines, then the screen's lines down to the cursor; on the alternate screen, entering it and drawing it, with no normal-screen history; then the input modes. The redraw is best effort. The supervisor then resizes the PTY to the frontend and signals its foreground process group with SIGWINCH even when the size did not change, so full-screen programs repaint.

*** =terminals.create=

Starts a program on a new terminal. The reply arrives once the program has started.

- Input :: ={"session", "argv", "cwd", "env", "name", "rows", "cols", "notify"}=, or a positional array in exactly that order with one through eight elements. Only =session= is required. =argv=, =cwd= and =env= are checked as for =sessions.exec=; missing/null =argv= runs the sandbox's =$SHELL=, missing/null =cwd= uses its working directory and =env= defaults to =[]=. Missing/null =name= means unnamed; otherwise it is 1–32 lowercase ASCII letters, digits, =-= or =_=, starts with a letter and is not =t= followed by digits. Missing/null =rows= and =cols= independently default to 40 and 120; supplied sizes are 1–500. =notify= defaults to false; true is refused on the host before command/name/size validation. Unknown fields are refused. The CLI retains its existing field omission, including absent false =notify=.
- Output :: a =Terminal= record.
- Errors :: =-32602= for an invalid name, size or program; =-32009= when the name is in use, the goblin refuses exec or has no init channel, or the program could not be started (the message is init's); =-32010= when the goblin has 16 terminals or the supervisor is busy.

The record has =id= (never reused within this goblin's run), nullable =name=, display =label=, =origin= (=host= or =agent=), =started_at= (Unix milliseconds), =rows=, =cols= and boolean =attached=. Every current producer field is present; readers ignore additions. The create CLI reads a string =id= independently and prints =?= if it is missing or malformed, including a non-object legacy result.

*** =terminals.list=

- Input :: ={"session"}= or =[session]=, with no unknown fields.
- Output :: ={"terminals": [Terminal]}=, oldest first. An exact retained session ID can read the published records after stop; the list is empty once terminal cleanup has completed. Agent names resolve only while their runtime remains live: a released name returns =-32004=, and a reused name selects its new live session. An unknown or no-longer-retained ID also returns =-32004=.

The CLI retains its legacy display fallbacks through generated normalized fields: it iterates only a =terminals= array (otherwise empty), reads string identity/display fields or prints =-=, displays attachment only for boolean true, and renders =rows= and =cols= as their JSON values, with missing values displayed as =null=. The attachment completion reader distinguishes explicit boolean false from missing attachment information.

*** =terminals.read=

Reads what a terminal shows.

- Input :: ={"session", "terminal", "source", "lines"}=. =source= is =visible= (the default), the screen's rows, or =recent=, the last =lines= lines of scrollback and screen with soft-wrapped rows joined into one line; on the alternate screen =recent= is the alternate screen like =visible=. =lines= defaults to 100 and is 1–5,000 when supplied. Missing/null =source= selects visible, and missing/null =lines= uses the default. The host positional form is =[session, terminal, source, lines]= with two through four elements. Unknown named fields are refused. Trailing blank lines are dropped.
- Output :: ={"text", "alternate_screen", "rows", "cols"}=, and ={"truncated": true}= when =text= was cut. =text= keeps the newest lines up to 256 KiB.

*** =terminals.send=

Types into a terminal: =text=, then =keys=. The host positional form is =[session, terminal, text, keys]= with two through four elements. Missing/null =text= means no text; even an empty string is supplied text. =keys= defaults to =[]=; null is refused. A string text or a nonempty keys list is required, and every key is validated before sending anything. Named fields are closed.

- Input :: ={"session", "terminal", "text", "keys"}=. At least one of them is required. =text= is at most 64 KiB (and the request frame at most 64 KiB, so the longest text that fits is shorter), wrapped in bracketed-paste markers when the program enabled bracketed paste. =keys= has at most 64 names: =enter=, =tab=, =esc=, =backspace=, =space=, =up=, =down=, =left=, =right=, =home=, =end=, =pageup=, =pagedown=, =insert=, =delete=, =f1=–=f12=, =shift+tab=, =ctrl+X= (a letter) and =alt+X= (an ASCII graphic character, =!= through =~=; space is excluded), or an entry of exactly one character that is not a control character (=g=, =A=, =:=; a Unicode scalar value other than C0, DEL and C1 controls), which is typed as that keystroke, never wrapped in bracketed-paste markers, with its case kept; cursor keys follow the cursor mode the program set. An unknown name, such as a longer entry that is not a key name (=gg=), refuses the whole call with =-32602=. Multi-character names are ASCII-lowercased before modifier processing, so =alt+X= emits ESC followed by lowercase =x=. A single-character =X= retains uppercase.
- Output :: ={"accepted": true}=. =-32009= when the program has ended or its input is full.

*** =terminals.wait=

Waits until a line matches, or the terminal's program exits. The reply arrives when it does; the connection serves no other call meanwhile, and a connection that closes cancels its wait. At most 16 waits are in progress per goblin (=-32010=).

- Input :: ={"session", "terminal", "match", "regex", "exit", "timeout", "lines"}=. Exactly one of =match= (a literal substring), =regex= (a Rust =regex= pattern; a pattern that compiles past a size limit is refused with =-32602=) and =exit= (=true=). =match= and =regex= test each line of the visible screen and of the last =lines= recent lines (default 100), at once and again after each output, so output already there matches; the newest matching line is reported. =timeout= is milliseconds, default 30,000, from zero through 3,600,000. Missing/null =timeout= uses the default, and missing/null =lines= uses 100 for matching or 50 for exit output; supplied =lines= is 1–5,000. Missing/null condition fields are absent; =exit=false= is compatible with match/regex. The host positional form is =[session, terminal, match, regex, exit, timeout, lines]= with two through seven elements; unknown fields are refused.
- Output :: ={"status": "matched", "line"}= (=line= cut to 4 KiB, with ={"truncated": true}= when cut), ={"status": "timeout"}=, or, when the terminal exits first, ={"status": "exited", "code", "signal", "text"}= with =code= and =signal= null when unknown and =text= the last =lines= recent lines (default 50, newest up to 256 KiB, with =truncated=). A wait whose condition matches in the terminal's final state when it exits reports the match.

The CLI independently reads string text/status/line and signed 64-bit code/signal fields, preserving valid fields beside malformed or missing ones. A read with no usable text prints an empty line. A wait with unknown/missing status reports timeout and exits 1; matched/exited statuses exit 0 and retain their old text/status defaults. Non-object legacy results use the same fallbacks. Send, detach and resize clients ignore successful result bodies; current producers still follow their precise schemas.

- Input :: ={"session", "terminal"}=
- Output :: ={"accepted": true}=

*** Terminals on the sandbox endpoint

A goblin reaches its own terminals with =terminals.create=, =terminals.list=, =terminals.read=, =terminals.send=, =terminals.wait= and =terminals.close= on the sandbox endpoint (=terminals= is in the sandbox's =features=). They are the host endpoint's methods with the same parameters, results and limits, except that no call names a goblin: a call with a =session= is refused with =-32602=, and the goblin is the caller's, so another goblin's terminals cannot be reached or even told apart from missing ones (=-32004=). =terminals.attach=, =terminals.detach= and =terminals.resize= do not exist there (=-32601=). A request is at most 4 KiB, except =terminals.create= (16 KiB) and =terminals.send= (64 KiB, the request body limit). As for =sessions.exec=, a configuration that refuses exec refuses =terminals.create=. A wait holds its connection, which serves no other call meanwhile; a connection that closes cancels its wait, and a goblin has at most 16 waits in all, the host's included.

All six sandbox =terminals.*= methods take named objects only; =null= is treated as ={}=, and arrays are refused even when empty. Create has no required fields, list takes none, and close requires =terminal=. Their generated endpoint contracts retain this distinction from host positional forms and the caller-derived session authority.

- Authority :: the goblin can list, read, send to and wait on all of its terminals, those the human created (origin =host=) included, and create new ones, whose origin is =agent=. It can close only terminals with origin =agent=: closing a =host= terminal is refused with =-32009= and a message saying that only the human can close it.
- =terminals.create= also takes =notify= (a boolean, default false; refused on the host endpoint). With it, the daemon puts one operation notice from =goblins= in the goblin's inbox when the terminal's program exits, whether or not the goblin's configuration has an agent integration. A program that was ended by =terminals.close=, or by the goblin stopping, sends none. The notice is the operation notice of an outcome with =message.operation= ={"request": "SESSION-tN", "kind": "terminal", "subject": LABEL, "status": "exited", "message"}= (=request= is the goblin's session ID and the terminal's ID joined by =-=, which names it for good as an ID is not reused in a goblin's run), where =message= is =exit code N= or =killed by signal N=, then the last 20 lines of the terminal's screen at the end, cut to 4 KiB with the newest lines kept (a cut starts with =…=). The notice body says =terminal LABEL exited=, then =message=. The daemon asks the supervisor to report the exit when it starts the terminal, as a wait that exists from the start and counts toward no limit, so a program that exits at once still sends its notice.

*** =history.prune=

Removes records that are not running. Every given criterion must match; at least one is required.

- Input :: ={"older_than"?, "before"?, "keep"?, "dry_run"?}=. =older_than= is milliseconds since the last update; =before= is a Unix millisecond; =keep= keeps the N most recently updated.

Display fields retain independent dash/unknown fallbacks. CLI wording uses requested dry_run rather than result dry_run. The original no-session-history error-text fallback to the offline store remains. * Sandbox endpoint

A sandbox sees only itself and the goblins it controls. Results omit process identities and terminal sockets. The shared =Worktree.path= identifies the worktree in the host repository folder; sandbox session records omit other host paths.

** Editor

*** =editor.open=

** Event

A communications log entry: ={"instance", "sequence", "timestamp", "kind", "actor", "sessions", "data"}=. =kind= names the event (for example =message.accepted=, =message.claimed=, =operation.completed=, =raid.joined=, =session.exited=); =actor= is a session ID, =host= or =goblins=; =sessions= lists the goblins it concerns; =data= is kind-specific.

Raid event payloads are now explicit: created =raid/name/owner=, joined =raid/session/role/created_by= (nullable role/creator), role =raid/session/role=, left =raid/session/reason=, paused =raid/former_owner/reason=, owner =raid/owner/previous= (nullable previous), and dissolved =raid/reason=. Leave reasons are left, stopped, launch-failed or kicked; dissolution reasons are destroyed or empty. Envelope sessions still carry affected members; those private domain vectors are not duplicated into payloads. Raid notices contain raid and nullable notice; a missing notice has an undelivered explanation, while a delivered notice omits that field.

Operation payloads are requested =request/kind/subject/reason/automatic=, decided =request/approved=, completed =request/kind/subject/status/message/notice= with optional undelivered, and duplicate =request/status=. Completion message is nullable. Delivered completions have a Message notice and omit undelivered; undelivered completions emit notice:null plus an explanation. Kind/status strings remain open, including host-command/finished and terminal/exited. Audit acceptance, event capacity/reservation, operation completion ownership and notice publication ordering remain in the existing state machine. Delivered raid and operation notices require sender =goblins=, state =queued= and claim_generation =0=. A delivered raid notice includes its structured =raid= record and its =raid.id= equals the outer payload's =raid=. A delivered operation notice includes its structured =operation= record; request, kind, subject, status and nullable message match the corresponding outer payload fields. The canonical schemas express these correlations with =x-equal-fields= (the repository validator compares the declared object pointers because Draft 7 cannot compare instance values directly). Delivered payloads omit undelivered; a null notice requires the undelivered explanation. Canonical event schemas check each known kind/data pairing; retained envelopes keep open legacy reading until consumer closure.

Mailbox mutation events contain =key/method/change=. The method is messages.send for message.accepted, inbox.next for message.claimed and inbox.empty, messages.reply for message.replied, inbox.complete for message.completed and inbox.requeue for message.requeued. Accepted change contains the complete Message, route (host or raid), and nullable raid; claimed/completed change contains message ID and positive claim_generation; empty change is an empty object; replied change contains the complete reply Message and completed ID; requeued change contains message ID, positive claim_generation and reason. Maximum u64 generations remain valid and overflow remains a refusal before publication. Nullable raid is emitted explicitly. Accepted host routes emit raid:null and raid routes emit a raid ID. Accepted and replied messages are newly created: state queued, claim_generation zero and failure null. Accepted in_reply_to is null; replied in_reply_to equals the completed ID (canonical x-equal-fields correlation). Requeue reason is nonempty and at most 512 UTF-8 bytes. These are current-producer constraints; compatible historical readers remain open.

Operation.retried contains key, the original mutation method and nullable message. Message is selected from the cached result's id, reply.id, message.id, or completed in that order; complete/requeue results contain a string message rather than message.id and therefore emit null here, as does an empty inbox result. Retries return the original cached result without repeating transitions and remain recoverable after audit failure. Recipient.stopped contains recipient and the ordered nonempty list of unresolved message IDs failed by the transition; envelope sessions retain sender/recipient entries and their existing duplicates/order. Session.started contains agent_name; session.exited contains an explicitly nullable reason, including null for sessions removed from the controller directory. These schemas describe existing producer data; logging, authority, receipt lookup, reservations and audit-before-publication order stay in the existing state machines. Compatible readers remain covered by C13b3.

Retained-log readers validate the Event envelope, not the current-producer payload schema. Unknown kinds and additive, malformed or partial known data remain raw and round-trip unchanged. Offline session selection independently reads string agent_name, then the final segment of a string legacy path, then the empty string; a present empty agent_name wins over path. Missing, null and non-string fields do not prevent that fallback. Regular-file, 128-MiB, final-newline, sequence and instance checks remain unchanged. The generated CommunicationSessionStartedRead record describes that normalized projection; it does not replace stored data.

Emacs message-cache consumers use generated lazy record views from the canonical field catalog, preserving plist field lookup rather than validating complete current payloads. They retain legacy sender_path/recipient_path fallbacks, existing message-ID checks, per-field malformed values and errors, conversation and reply/raid inheritance, duplicate replacement, update ordering and unknown-kind notices. The generated views leave values raw and read each field only where the previous consumer read it. They add no authority and do not tighten older log acceptance. All 22 current event kinds have generated producer bindings; raw publication is private behind the typed record helper. The producer and reader catalogs are checked alongside the schemas and generated reference. Producer checks inspect actual constructor calls in publication functions, resolve marker aliases, exclude comments/literals/tests and retain the private raw-record boundary. Compatible session reader dispatch uses the catalog-bound generated kind; its kind and marker must agree.

** DevShellPreview

* Private init channel (same build)

The supervisor and sandbox init exchange one JSON message per inherited =SOCK_SEQPACKET= datagram with =SCM_RIGHTS= descriptors. The canonical data lives in =goblins_protocol::init= and is re-exported unchanged by =goblins_init=; this module is a private same-build contract, not a public JSON-RPC method or a grant of host authority. The daemon uses the pure =goblins_runtime::exec::validate_spawn= helper rather than constructing init messages. This helper uses the same =Command::Spawn= serializer as the supervisor and returns the original serialization diagnostic or =command too long= when the encoded message exceeds =MAX_MESSAGE= (65536 bytes); exactly 65536 bytes fits.

Commands use ={"method":NAME,"params":OBJECT}= with these variants:
- =spawn=: =id:U64= (daemon-allocated, never reused), =argv:[STRING,...]_OR_NULL= (null selects the sandbox shell), =cwd:STRING_OR_NULL=, =env:[[NAME,VALUE],...]= and =tty:BOOL=. All fields are serialized, including nulls; field order is unchanged. A tty spawn carries one PTY slave, otherwise stdin, stdout and stderr. Each command gets its own session and process group.
- =signal=: =id:U64= and =signal:I32=, forwarding a signal to that exec's process group. The host forwarding policy remains SIGHUP, SIGINT and SIGTERM.
- =cancel=: =id:U64= and =everything:BOOL= (default false when omitted), cancelling that exec group or every process its keeper holds, with existing graceful signals followed by SIGKILL.
- =kill-all=: empty params, cancelling all execs while leaving the agent unaffected.

Events use the same envelope:
- =spawned=: =id:U64= and =pid:I32=.
- =failed=: =id:U64=, =code:I32= (127 for a missing command, 126 otherwise) and =message:STRING=.
- =exited=: =id:U64=, =code:I32_OR_NULL= and =signal:I32_OR_NULL=.

The init sender's =MAX_FDS= aliases the host stdio budget of three; the unrelated supervisor frame budget remains 240. Generic =goblins_unix::ancillary= I/O has no init-message knowledge: callers supply their send limit and the helper additionally bounds its fixed ancillary storage before writing headers. Sending is nonblocking with SIGPIPE suppressed, borrows descriptors, and retains =too many descriptors= and =short message= errors. Receiving retains the existing larger fixed ancillary capacity, makes received descriptors close-on-exec, and closes every installed descriptor on data or ancillary truncation before returning =truncated message=. Host aggregate descriptor enforcement and error order remain in the controller; the Unix helper does not impose an earlier receive limit of three or mutate shared socket flags. =goblins_init= retains its transport wrappers and connected close-on-exec seqpacket pair.

* Private scope channel (API 1)

This channel is internal to the daemon and its pinned =goblins-supervisor-bwrap= executable; host and sandbox endpoints do not accept these methods. The types live in =libs/runtime/src/scope.rs= and the transport in =libs/runtime/src/channel.rs=. The scope executable accepts only inherited descriptor 3, establishes parent-death handling, verifies its daemon parent through the socket's =SO_PEERCRED= and closes other inherited descriptors before reading setup.

Each message is a JSON-RPC 2.0 notification, ={"jsonrpc":"2.0","method":METHOD,"params":OBJECT}=. A member connection performs one request/reply exchange at a time. The stream has =Content-Length= and =Descriptor-Count= headers, at most 256 header bytes and an 8 MiB body; the whole-frame deadline is 3 seconds from the first byte. JSON nesting is at most 32, and duplicate keys and unknown message fields fail the channel. A frame carries at most 240 descriptors, independently of the sandbox endpoint's three-descriptor limit. A descriptor reference is ={"$fd":INDEX}=, with exactly one reference for each attached descriptor. Descriptors are attached to the first successful =sendmsg= for their frame, received close-on-exec, and closed on malformed, truncated or abandoned input. Reads stop at each frame boundary; ancillary data is accepted only at the frame's first byte and must exactly match that frame's declared count. A subsequent frame cannot consume an earlier frame's attachment. Output queues hold at most 64 frames, 16 MiB of unsent bytes and 480 unsent descriptors; a full queue returns capacity to its caller.

** Private Docker guardian channel

The scope creates a separate socketpair for the trusted Docker guardian. It uses the same private framing and descriptor budgets as the scope channel. The helper receives the channel and initial lock descriptors only through its trusted bootstrap arguments, validates them, marks them close-on-exec and closes the engine child's copies before starting Docker. The raw socket crosses fork without a Channel destructor; only the guardian parent constructs Channel, so dropping the child copy cannot shut down the shared endpoint. Docker and containers never receive the channel or lease capabilities.

| Direction | Method | Parameters | Effect |
|-----------+--------+------------+--------|
| Scope to guardian | =Retain= | ={"leases":[{"directory":ABSOLUTE_PATH,"lock":DESCRIPTOR},...]}= | Transfers fresh copies of every later attaching or extending donor's full lease chain, in batches of at most 240 descriptors. Initial engine startup retains locks through the inherited bootstrap descriptors instead. The guardian holds the received descriptors until its container and disk cleanup has completed. |
| Guardian to scope | =Retained= | ={}= | Confirms the batch is retained. The scope waits for this acknowledgement before publishing new grants. |

The private trusted invocation is =HELPER --docker-init STORAGE_NAME POLICY LOCK_FD READY_FD GUARDIAN_FD BOOTSTRAP_FDS DOCKERD ARGS...=, after the existing scope namespace entry and Bubblewrap setup. =POLICY= is =keep= or =delete=; =LOCK_FD= protects Docker data storage, =READY_FD= reports the nested child PID, =GUARDIAN_FD= carries Retain/Retained, and =BOOTSTRAP_FDS= is a comma-separated list of distinct inherited regular-file descriptors at least 3, excluding those other descriptors. It contains freshly opened shared locks on the initial full donor chain and the scope runtime directory, created before spawn and included in the exec allowlist, with no path inference. These are raw cleanup capabilities without ResourceLease removal semantics. They retain the backing resources from fork/exec onward, including death before readiness or the first channel exchange. The private argument addition changes no host or sandbox RPC.

After engine fork, channel-setup and readiness-write errors also run the existing namespace kill/reap and disk cleanup while the initial capabilities remain held. A failed Channel constructor leaves them in Bootstrap; success moves them to Retainer, and either owner survives through cleanup.

Startup failure reports both the engine process exit status and the tail of =STATE/scopes/NAME/docker.log=, including failures before readiness.

The bootstrap runtime lock keeps the scope-owned store skeleton protected from stale collection while the guardian outlives the scope. It is a raw lock capability, with no resource-directory removal on drop. The guardian cannot resolve host donor paths inside its confined filesystem; directory metadata identifies the transferred locks while the descriptor itself retains authority. EOF or a malformed guardian request starts existing engine teardown without releasing accepted leases early. This keeps all donor resources protected from GC after scope or daemon death, through the guardian's final cleanup. The first donor's directory is never inferred from scope runtime paths.

* Private supervisor channel (API 1)

This same-build protocol is defined in =goblins_runtime::supervisor=. The process and library ownership decisions are recorded in [[file:adr/0018-per-goblin-supervisors.md][ADR 0018]]. The daemon uses the process dispatcher exclusively; the temporary in-process Local adapter and debug selection were removed in phase 6 commit 9. It reuses the private scope =Channel= framing, deadlines, descriptor accounting and queue budgets above without changing that transport or the public three-descriptor limit. Every message is a JSON-RPC 2.0 notification with exactly =jsonrpc=, =method= and object =params=; there are no JSON-RPC request IDs or JSON-RPC result/error envelopes. All parameter fields listed below are emitted, including nullable fields. Unknown methods, extra envelope or parameter fields, missing required fields, invalid typed values, descriptor aliases, unused descriptors, malformed ownership and incompatible versions fail the channel; the implementation reports the diagnostic locally and drops pending ownership guards.

=DESCRIPTOR= means ={"$fd":INDEX}=, indexing exactly one attached descriptor in that frame. =Result<T,String>= means ={"Ok":T}= or ={"Err":TEXT}=; an optional value is its normal value or =null=. String/path pairs and environment entries are two-element JSON arrays. An opaque field contains a JSON /string/ whose contents are a serialized JSON value; it is decoded once by the vocabulary codec, after the transport has checked descriptors. Raw calls, replies and trusted lock-file JSON use this form so literal =$fd= keys in data neither forge capabilities nor collide with the descriptor scanner.

The executable reads one inherited control socket on descriptor 3. Before choosing a mode it installs =PDEATHSIG=, checks =SO_PEERCRED= against its current daemon parent, closes inherited descriptors other than 3, replaces stdio with close-on-exec =/dev/null= handles and makes descriptor 3 close-on-exec. The first complete message must be scope =Setup=, =SupervisorStart=, =Preflight= or =Maintenance=; any other direction, method or incomplete/invalid startup is rejected before creating the runtime. A member's complete typed handoff is adopted before the engine starts; it is then acknowledged with =Adopted=. Preflight performs one startup-only validation/root operation without starting an engine; Maintenance performs one CLI GC or scope-clear operation without an engine.

The Nix wrapper exports =GOBLINS_SUPERVISOR_RUNTIME= as the absolute path of its pinned =goblins-supervisor-bwrap=. A controller captures this once and uses it for every scope start; the same selection is used for supervisor, preflight and maintenance modes. There is no PATH search or per-configuration =scope_runtime= field. An unset or empty pin reports =supervisor executable not configured (GOBLINS_SUPERVISOR_RUNTIME)= when a process is needed; a relative pin reports =supervisor executable must be an absolute path (GOBLINS_SUPERVISOR_RUNTIME)=. Help and other operations needing no process do not require it. Local Cargo tests set the same variable to the executable reported by Cargo, while packaged tests use the wrapper's immutable pin.

The daemon uses Supervised exclusively for real runtimes and starts a member process only after its accepted placeholder receives the complete handoff. Stop before that drops the placeholder without spawning and reports Stopped with no exit code; an unexpected scope failure also drops it without spawning and preserves the existing nonzero exit code 1. Each controller captures the executable once for both supervisor and scope starts. Runtime release is explicit and monotonic, independently of a process retaining terminal output. Its local failure/shutdown abort operation kills a remaining child after orderly Stop has been requested from every runtime; this operation adds no wire method.

The client reads bounded event rounds independently of blocked command writes. Ownership acknowledgements are coalesced by transfer and prioritized at a free frame boundary; outbound typed transfer guards survive channel failure until the child's exit notification and reap. Before Stopped, supervisor loss fails only that goblin, ends outstanding calls and fails pending member exports naming the owner. After Stopped it preserves the lifecycle record and released name/history authority and reports interrupted terminal outcomes with attached, connected and detached false. Supervisor loss does not run onDetach. A normal drained supervisor exits successfully and is reaped without changing terminal completion to interruption.

The stop clock begins when the daemon records the first Stop, including time spent waiting to write it. Stopping must arrive within 2 seconds; cleanup must reach Stopped within 15 seconds of that first acknowledgement, for at most 17 seconds overall. Stopped disables this kill deadline while terminal/log output remains. Server shutdown pumps all children concurrently within that common 2+15-second budget; the CLI waits up to 20 seconds for cleanup and server lock release.

A transport write failure after valid Stopped and Released, with every retained terminal outcome already complete, interrupted or detached and no earlier nontransport failure, allows the child to finish returning naturally for at most 2 seconds from that first eligible failure. The first deadline never resets. Final control teardown precedes engine destruction and process return, so socket closure alone is not an unsuccessful exit. Sender transfer owners remain held until confirmed reap. A successful natural exit preserves the already delivered terminal outcomes, including any existing interruption. Nonzero exit, encoding/protocol errors, unresolved terminal outcomes or grace expiry use the loss path. Expiry is checked even after storing the write failure; an exit notification already observed at a later poll is reaped rather than killed. Historical per-handle Stop deadlines stay disabled after Stopped and do not shorten this grace or retained output service. The unchanged daemon-wide shutdown abort may terminate it earlier. This is local client behavior and adds no wire method, worker or protocol field.

Exec event logging uses a separate lowest-priority FIFO in each daemon/supervisor command planner: at most 16 uncommitted records and 1 MiB total of event-name UTF-8 bytes plus the single serialized JSON representation of fields. These limits exclude at most one already committed indivisible frame, which retains the existing transport limits and atomicity. Logging never occupies the four ordinary request slots. A record exceeding either queue limit, received after admission closes, or failing encoding before commitment is dropped without failing the runtime. A saturating u64 =dropped_record_events()= counter belongs to that planner instance and remains through its teardown; daemon and engine counters are separate internal accounting, not a public metric, delivery acknowledgement or end-to-end drop count. File I/O remains best-effort and has no write acknowledgement.

Cancellation and ordinary commands precede log records. Stop retains its existing order after earlier semantic work, closes log admission and drops/counts queued uncommitted records; a committed frame still finishes first. Engine logging drains at most one record at the end of each bounded collection round independently of full semantic output, and log backlog cannot consume worker admission or delay release. Resource teardown permanently disables the engine's log path and drops/closes its log lane. Later commands never open or recreate =events.jsonl= or its resource directory, even when another lease retains that directory. The supervisor privately owns the existing writer and Session logging; daemon exec-start/exit handling only sends typed commands. The writer preserves the existing pre-append 1 MiB threshold (an admitted append may overshoot it) and ignores file I/O errors; it never creates the parent directory. =fields= is opaque JSON on the control channel, so literal =$fd= objects remain data. These diagnostic commands are separate from semantic runtime Events, whose backpressure and no-loss contract is unchanged.

Preflight is called only during foreground daemon startup, before server readiness and the event pump. Success returns exactly one existing =Event.Manifest= whose =path= and =sequence= match the request, followed by the daemon's matching =Adopted= even when the manifest is unrooted. The child flushes its result, accepts that acknowledgement and returns with status zero; it does not wait for parent EOF. Before logical decoding in the child's acknowledgement phase, only scalar =Adopted= is accepted; a wrong-direction multipart frame is rejected and its raw descriptors close before control closure. At its terminal boundary it performs one nonblocking, nonconsuming byte peek: already queued extra or partial input is rejected, without claiming to detect bytes arriving after that check. Ordinary failure returns only =PreflightFailed= and requires no acknowledgement. The daemon stages the full typed result and publishes a lease, or reports the original operation error, only after acknowledgement flush where required, strict EOF with no extra/malformed result, and confirmed successful child reap. Before general logical decoding, the client accepts only the single-frame =Event.Manifest= or =PreflightFailed= method, so a wrong-direction multipart handoff is rejected immediately instead of waiting for continuations under the unlimited Nix operation rule. Invalid direction, wrong sequence/path, absent result, duplicate/trailing result, incomplete ownership transfer or nonzero exit rejects the attempt and preserves the previous current manifest.

Normal Nix work before a complete result has no additional timeout. A single fixed two-second deadline starts when the complete logical result is decoded, covering acknowledgement flush, EOF validation and successful reap; it is never reset. On earlier local failure or abandonment, the daemon disposes partial/raw receive descriptors and closes control to cancel the existing Nix process group, allowing at most two seconds for cleanup before kill/reap. After a result it uses only the remaining fixed deadline, with no second grace after expiry. Full received typed owners survive until confirmed child exit/reap. Control EOF or unexpected input during Nix cancels through the existing descriptor-readable cancellation path; there is no Cancel message, monitor thread or acknowledgement of acknowledgement. Protocol/child failures report diagnostics such as =invalid preflight result method=, =incomplete preflight result=, =invalid preflight result=, =extra preflight result=, =preflight closed without a result=, =preflight closed before acknowledgement flushed=, =preflight supervisor exited unsuccessfully= or =preflight did not finish within 2 seconds after its result=. Invalid request API/directory is rejected before rooting as =incompatible supervisor API= or =invalid preflight directory=. The child rejects invalid/missing acknowledgement or queued trailing input with =preflight expected Adopted=, =incomplete Adopted=, =preflight closed before Adopted= or =trailing preflight input= and an unsuccessful protocol exit.

Before Nix runs, the attempt takes a nonblocking exclusive lock on the stable =ROOT.ownership= inode and checks =symlink_metadata(ROOT)= is absent, including dangling symlinks as existing collisions. A busy owner reports =manifest root is already owned: PATH=; an existing root reports =manifest root already exists: PATH= without ever creating a root-removing guard. The guard keeps exclusive construction ownership through command/process-group cleanup. After success it verifies an actual symlink exists (=manifest root must be a symlink= otherwise), then downgrades to shared ownership before the existing independent shared descriptor transfer. Conversion failures propagate and do not publish. A competitor during a non-atomic conversion must reject the now-existing root. Failed or cancelled creators clean only their own attempt root after command cleanup, using the existing single nonblocking exclusive cleanup attempt and normal GC fallback when contended; prior current roots and colliding roots remain protected.

Manifest data parsing, editor/scope/run-target checks, selection and injected-environment bind expansion live in =goblins-runtime=; frontend reads do not invoke or require the executable pin. =read= only parses bounded data, while full validation also checks versions/catalog/handlers/run-targets/editor. Pure scope-name validation remains before process/pin access. Maintenance shares preflight's synchronous private one-shot loop outside daemon event pumps. Normal work/output has no new operation timeout; existing helper readiness remains ten seconds. A single fixed two-second deadline from complete result decoding covers EOF and reap, never resets and adds no second grace. Earlier protocol/local failure or cancellation disposes raw/partial descriptors before closing control, then allows at most two seconds of existing cancellation cleanup before killing/reaping the direct supervisor. Ordinary supervisor/scope/preflight start behavior is unchanged. Full typed one-shot result/extra owners stay held through confirmed child reap as for preflight.

Deletion policy remains private and unchanged: scope clearing holds the storage gate and preflights every selected scope/Docker lock and path before any deletion, retains stable persistent lock inodes, and respects live leases. GC separates its exclusive temporary-store gate from server-control/daemon lock protection, keeps live/guardian-owned resources and preserves history/logs. Cancellation is checked during enumeration/preflight and before deletion/unlink/helper phases. =SupervisorStart.payload_nofile= is required and nullable. At construction the foreground daemon snapshots its process-local original soft =RLIMIT_NOFILE= value if it successfully raised its own soft limit; null means no original value was recorded. The supervisor retains its inherited ambient soft and hard limits through exec and bootstrap. After complete logical startup validation, including any multipart handoff, and before creating an engine or worker or sending =Adopted=, it installs this value as process-local payload restoration metadata only. A non-null value must be a positive finite unsigned integer representable as =rlim_t= and no greater than either actual ambient soft or hard limit. Zero, infinity, conversion failure and out-of-bounds values fail startup with =invalid payload descriptor limit=; a failed =getrlimit= also fails startup with its OS error. Rejection leaves existing metadata and kernel limits unchanged and releases received capabilities and leases without an acknowledgement or engine side effects. Null clears restoration metadata without changing kernel limits. Payload launch restores the recorded soft value while retaining the ambient hard limit, so controller and supervisor capacity remains raised. The separate background =server start= self-exec path still loses process-local original-limit metadata; this preexisting limitation is outside this propagation mechanism.

Generated =WireDirectory=, =WireLease= and =WireHandoff= retain their original record names, field order, closed fields, usize/u64 representations and nullable working-directory behavior. =Leases= continuations bind a generated notification identity and parameter record in both directions. Canonical named record schemas are distinct from positional Serde forms accepted by the original logical decoder. Structural schemas leave transfer/count/more correlations, cumulative byte budgets, descriptor ownership and the inner JSON parse at their existing runtime points. Full handoff adoption waits for the final frame; overlap, abandonment and cleanup behavior are unchanged. =SupervisorStart.legacy_listener= optionally transfers the already bound legacy =DIRECTORY/../terminal.sock= Unix listening socket. The daemon binds it synchronously before accepting a launch, makes it nonblocking and mode 0600, and never accepts or performs terminal I/O. A pending member retains the descriptor until its complete handoff arrives. The engine verifies the inherited descriptor is listening at the expected path and adopts it into its existing terminal handshake; null or omitted uses the standalone binding path. The descriptor precedes handoff encoding and counts against the unchanged first-frame 240-descriptor allowance alongside the optional member scope, workspace, working directory and lease descriptors. A stopped or abandoned placeholder closes and unlinks it without spawning. Failed bootstrap, EOF, protocol error and shutdown retain sender ownership through confirmed child death before daemon unlink; graceful terminal disposal also unlinks the socket. Typed handoff adoption and partial-transfer cleanup include this descriptor.

=Handoff= has =transfer:NONZERO_U64=, =count:USIZE=, =workspace:DESCRIPTOR=, =working_directory:WorkingDirectory_OR_NULL=, =dev_shell:OPAQUE_OPTIONAL_DEV_SHELL=, =docker:BOOL=, =leases:[ResourceLease,...]= and =more:BOOL=. =count= is the total number of leases, including following =Leases= notifications. =ResourceLease= is ={"directory":ABSOLUTE_PATH,"lock":DESCRIPTOR}=; adoption verifies that the regular, user-owned lock descriptor matches that directory's =.gc-lease= inode. =WorkingDirectory= is ={"fd":DESCRIPTOR,"source":PATH,"destination":PATH}=. Its descriptor pins the host working directory. The workspace and directory descriptors precede lease descriptors in the first frame; subsequent batches have frame-local indices. Every frame has at most 240 descriptors. The combined serialized bodies of one handoff have at most 8 MiB, so batching increases descriptor capacity without increasing the logical byte budget or imposing a smaller public ancestry limit.

The sender retains the original typed message through actual transmission, then keeps the complete typed leases in a =PendingTransfer= (or retains =Prepared=) until =Adopted= or channel teardown. Transmission alone never disarms cleanup ownership. The receiver adopts resource leases batch by batch, retaining cleanup ownership while the handoff is incomplete. Partial EOF, invalid continuation, failed adoption and abandoned complete messages drop these guards; unsent descriptors are closed before the sender releases its original message. Every complete Handoff and =Event.Manifest= yields an adoption token; acknowledge only after typed ownership is adopted, before subsequently publishing or discarding a logical result. Rooted manifest sender and receiver use independent shared ownership locks on a stable private sibling =ROOT.ownership= inode. Either live peer protects the root across lost acknowledgement; the last graceful owner removes it. The lock inode remains stable as with other GC leases. An unrooted manifest carries neither root nor owner descriptor. Ownership decode/adoption failure is a protocol error, with no =Rejected= notification. Dispose raw Frame descriptors and =Decoder.pending= before explicitly closing =Channel=; the channel disposes its received/unsent descriptors before socket shutdown. The sender then drops pending typed leases on teardown. The supervisor receive path treats =ECONNRESET= from a peer closing with unread data/SCM_RIGHTS as the same closed-channel outcome as EOF, including incomplete-handoff disposal. Normal Drop makes one nonblocking exclusive-lock attempt; a racing/half-dead peer retaining a copy, raw framing-error auto-close before external decoder disposal, or actual process death uses existing stopped-server GC/startup cleanup. There is no new wait, cleanup service or process-wide owner. Actors in phase 6 commits 3/4 keep pending transfers by ID through acknowledgement, closure, errors and retirement; supervisor-death release waits for pidfd exit. A stale logical result can be adopted and dropped without publication. Failed bootstrap, undelivered output and shutdown preserve this same ownership ordering.

** Supervisor events

The engine runs only inside the inherited-socket supervisor; the daemon links contract/helper libraries and owns the control client, without linking the supervisor implementation or init transport library. The actor retains full typed outbound owners until =Adopted=. The logical sender planner has four unsent request slots, independent of receiver admission. Removing an unsent spawn/host request emits its existing local cancellation outcome rather than stranding its caller; each synthesized outcome occupies the removed request's original slot until reported, sharing the same four-slot limit with unsent requests.
