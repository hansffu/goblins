* Build and run from a checkout

The root flake provides the builders (=lib=) and a development shell for x86_64-linux, with nixpkgs, agent-sandbox.nix and llm-agents.nix pinned in =flake.lock=. Its =dev-goblins= package is a =goblins= with demo configurations for trying and testing the checkout; users build theirs with =mkGoblins= and their own configurations.

#+begin_src sh
nix shell path:.#dev-goblins
goblins server start
goblins tui
# In another terminal, also in that shell:
goblins run shell
#+end_src

=nix shell path:.#dev-goblins= puts a =goblins= built from the checkout on =PATH=. The development shell (=nix develop=) has only the build tools: inside a goblin, a =goblins= there would shadow the sandbox's own CLI. The package's configurations are the demo goblins in =nix/demo-goblins/=, which exist only for development: =shell= (Fish, with Docker enabled in a temporary =dev= scope), =claude= and =codex= (with Fish among their tools, for =goblins-shell-program=), and =goblins-dev=, a Claude Code goblin with =allowNix= and host commands for developing Goblins itself, which may start =claude= and =codex= children; =editor.emacs.enable= is set. The agents come from [[https://github.com/numtide/llm-agents.nix][numtide/llm-agents.nix]] (=nix flake update llm-agents=), whose prebuilt packages are on =https://cache.numtide.com=. The Python tests' daemon uses the same demo goblins without Docker or the editor, built as =checks.x86_64-linux.demo-goblins=. The explicit =path:.= also includes uncommitted source files. Restart a server started from an older build before using a new one: an already-running daemon keeps its old executable.

=just emacs= opens Emacs from the dev shell with this checkout's =emacs/= on the load path and =goblins-executable= set to the =dev-goblins= package.

* Test

#+begin_src sh
nix develop path:.
cargo test --workspace --locked
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
nix flake check path:.
python3 -m unittest discover -s tests -p 'test_*.py' -v
#+end_src

The development shell includes pyte for fullscreen terminal regression tests. Tests need host Nix, Unix sockets and ordinary-user namespace access. Run one Python suite at a time; concurrent runs interfere. The Codex tests run the real Codex and are skipped unless =GOBLINS_TEST_CODEX=1= is set. The Emacs checks are described in [[file:../emacs/README.org::*Checks][emacs/README.org]]; the Docker tests in [[file:USAGE.org::*Docker in a scope][USAGE.org]].

* Implementation notes

The controller accepts explicit frontend decisions; its library never opens =/dev/tty=. Each session has a cancellable worker for startup and sequential grants while the daemon continues serving other sessions and frontends. The internal client depends only on shared protocol code, with no host policy or mount API. There is no production Python executable or mandatory Python interpreter; Python is a test driver only.

The Rust rewrite preserves PoC commit =c2a9d42= as its behavioral reference. It does not implement terminal multiplexing, live file/network grants or daemon restart recovery. Closing frontends leaves sessions alive; daemon death stops every helper and sandbox; abrupt death may leave host session directories and GC roots for manual cleanup.
