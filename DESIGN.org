#+title: Goblins daemon, protocol and sandbox boundary

* Ownership and concurrency

The ordinary-user Rust daemon owns session records, permission identities,
decisions, grant outcomes, PTYs and lifecycle. =goblins daemon= has no terminal
frontend dependency. =serve= and =serve --plain= are host API clients; =run NAME=
starts a session through that same API and consumes its separate raw terminal
stream. Closing any or all frontends leaves sessions alive. Reconnecting to the
same daemon obtains current state; restarting the daemon never recovers sessions.

One event loop serializes authority and snapshot/event ordering. Each session
has its own cancellable worker and separate single-threaded namespace helper.
Startup, manifest reads, snapshots, Nix and helper acknowledgements run on the
worker. A slow session, human decision, output consumer or subscriber cannot
hold another session's worker or control path. Worker command/result channels
are bounded; cancellation bypasses the command queue. Finished workers are
joined only after completion; explicit stop acceptance does not wait for cleanup.
Normal daemon shutdown first cancels every worker, then joins and cleans them.

All daemon session directories, including future sessions, are children of its
private protected state directory. Bind validation checks that whole tree and
canonical sources, rather than only a requesting session's own directory.
A sandbox gets only its own request socket at =/run/goblins/request.sock=.
Neither a shared host UID nor an agent-supplied field selects session authority.

* Structured communication

Both host and per-session sandbox endpoints are pathname Unix STREAM sockets,
mode 0600 within mode-0700 host directories. JSON-RPC 2.0 messages use
Content-Length framing with CRLF headers; terminal bytes never enter JSON.
Shared protocol code uses Serde typed data plus duplicate-key and nesting
validation. The inner client has no dependency on host policy, Ratatui, Nix or
the helper. The helper still accepts only narrow private pipe commands.

[[file:DAEMON.org::*Implementation contract (2026-09-13)][The API 1 implementation contract]] specifies the methods, schemas, errors,
identity and retry rules, limits and deadlines. =initialize= negotiates the
Goblins version independently of JSON-RPC's version and reports a random daemon
instance ID. Host connections support repeated calls. Sandbox connections
initialize, make one permission request, receive one terminal outcome and close.
Notifications never mutate state; batches are rejected. Unknown fields,
duplicate JSON keys at every depth, invalid IDs and unsupported methods fail.

Every incomplete frame has one monotonic three-second budget. Initialization
starts at accept, the sandbox request at initialization completion, and later
host frames at their first byte. Idle initialized host connections and human or
build waits have no frame timeout. Any byte or EOF after the sandbox permission
frame disconnects that caller. Before approval this withdraws the record and
cancels the preview; after approval the grant can finish with an undelivered
reply and an unknown caller outcome. No disconnect path uses MSG_PEEK.

A daemon-issued session/request/approval triple names every decision. Only the
first pending transition wins. A public RPC ID is only correlation data.
Launch mutations additionally require a host-generated retry key: identical
parameters return the original acceptance, differing parameters conflict.
Keys remain reserved for that daemon lifetime; capacity exhaustion refuses new
keys. No automatic client retry is inferred from a lost response.

=state.subscribe= atomically returns a snapshot at global sequence N. Later
=state.changed= messages contain ordered complete replacement snapshots, including
record evictions. Bounded session/permission records make this simple schema
sufficient without pagination or a durable log. Queue overflow disconnects the
subscriber, requiring a fresh subscription; it cannot silently skip an event.
The frontend uses a subscription connection and a separate host call connection.

* Approval presentation

The minimal Ratatui frontend shows sessions and startup/live package names,
with a separate request panel and advisory preview. Arrow keys select a session
or scroll package details; Page Up/Down scroll request text. Terminal defaults
and ANSI blue borders are used, with =NO_COLOR= honored. The plain fallback
prints escaped state and request records. Neither frontend owns sandbox state.

The fullscreen view restores Yes/No buttons, mouse clicks and =y=/=n= shortcuts.
Tab switches between sandbox and request lists; Up/Down selects in the focused
list. The selected request popup reserves bottom rows rather than overlaying
other content. Its identity remains selected after withdrawal or completion;
it is never automatically replaced by the next pending request. Escape hides
the popup, and accepted decisions close it automatically. The list remains;
navigation or Enter reopens details. Hidden popups cannot receive decisions.

Input batches target the last rendered request before applying new snapshots.
Navigation within a batch cannot approve a selection that has not been drawn.
Mouse press/release retains the pressed request identity. Bracketed paste is
ignored. The plain fallback retains complete =approve APPROVAL=/=deny APPROVAL=
commands whose text survives state replacement unchanged. In both cases the
daemon validates the immutable triple against current state. Agent text is
escaped to ASCII JSON data before host-terminal presentation.

* Terminal lifetime and completion

Start acceptance returns a private terminal stream pathname immediately. It
accepts one lifetime consumer, even while startup is still in progress. The
daemon retains the PTY master and relays raw bytes with separate bounded
64-KiB input/output buffers. =sessions.resize= performs the PTY size ioctl in
the daemon; it carries no namespace or attachment authority.

Before the first consumer connects, buffered output backpressures that session
at the limit. After consumer disconnect, the daemon discards output and keeps
draining the PTY so the session survives; delivery is marked interrupted.
There is no terminal reattachment, replay, observer or multiplexing contract.
A slow connected consumer backpressures its own session only.

The helper observes natural Bubblewrap/payload exit while polling its private
command pipe and returns the exit code. The worker's stopped result follows
resource cleanup. The daemon tracks that exit separately from PTY EOF/EIO,
buffer drain, and raw-stream completion. It sends stream EOF only after queued
bytes have been written. The host client then drains its own stdout buffer and
checks the retained exit and delivery fields. A control disconnect, daemon
crash, stdout failure or interrupted relay cannot report successful completion.

* Namespace topology

#+begin_example
host daemon (ordinary host UID; Nix access; independent frontend lifetime)
  private pipes -> Rust helper
    user namespace A: UID 0 maps only to the invoking host UID
    mount namespace S owned by A: private copy of source mounts
    final helper capabilities: CAP_SYS_ADMIN | CAP_SYS_CHROOT in A
      Bubblewrap monitor
        user namespace B (child of A)
        mount namespace M owned by B
        private PID / network / IPC / UTS / cgroup namespaces
          PID 1: Bubblewrap reaper
          PID 2: original Fish (Bash in the gate), zero capabilities, no_new_privs
            descendants inherit the same restrictions
#+end_example

There is no host-root process. The Rust helper refuses host UID 0, creates A,
maps only the invoking UID/GID, denies setgroups, and creates S. It marks S's
mount propagation recursively private. S retains trusted source access; the
payload does not inherit S's descriptors or root.

Bubblewrap creates B and M with =--unshare-all --cap-drop ALL=. Its private
=--info-fd= reports the child PID. Its =--block-fd= holds the payload until the
helper observes the final root and verifies namespace ownership. The helper
uses =NS_GET_USERNS= and =NS_GET_PARENT= to verify that M's owner is a direct
child of A, and independently verifies S's owner is A. It never accepts a PID
or namespace from the agent.

The helper stays outside the sandbox PID namespace, is nondumpable, and drops
all capabilities except =CAP_SYS_ADMIN= and =CAP_SYS_CHROOT= after setup. Its
authority applies to A and descendant namespaces, not the host user namespace.
Both its source and target mount namespaces are per-session namespaces. The
agent has no namespace descriptors or mount-control pipe. Its only inherited
descriptors are payload stdio; Bubblewrap's reaper also holds its eventfd.

* Why retaining source and target namespaces matters

The first kernel trial successfully entered M but failed =open_tree= with
=EINVAL=: the source descriptor referred to a mount outside the helper's
current mount namespace. This is a concrete failure of that first mechanism,
not a blocker for live mounts. The working helper switches to S to clone the
source, hardens the detached mount, switches to M, and attaches it. It retains
no descriptor for entering the host's mount namespace.

Each grant operation:

1. The host controller validates a nixpkgs attribute name and obtains its pinned
   output from host Nix. It creates GC roots before enumerating requisites.
2. The controller enumerates the transitive closure through host Nix, validates
   canonical store names, checks executable-name collisions, and prepares a
   profile generation. It creates empty destination placeholders in a
   host-owned directory already bound read-only at =/nix/store=.
3. The private helper protocol carries only one bounded canonical store
   basename per operation. No source prefix, destination, PID, or flags are
   accepted. Agent requests never reach this protocol directly.
4. In S, the helper opens the source relative to its retained store descriptor.
   =openat2= uses =RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS |
   RESOLVE_NO_MAGICLINKS=. Only regular files and directories are supported.
5. It resolves the destination relative to the retained sandbox root with the
   same lookup restrictions. The agent cannot modify the read-only parent
   hierarchy or create placeholders; fault injection also tests rejection of
   a host-inserted destination symlink.
6. =open_tree(OPEN_TREE_CLONE)= clones the single source object into a detached
   mount. =mount_setattr= sets =RDONLY | NOSUID | NODEV= *before* visibility.
   No recursive import of host submounts is performed.
7. In M, =move_mount= attaches the hardened clone by source/destination FDs.
   The helper acknowledges success; errors exit and kill the disposable tree.
8. Only after every acknowledgement does the controller atomically rename the
   =current= symlink under the read-only mounted profile parent.

The empty host =store/= directory contains mountpoint placeholders, not copied
package contents. Absolute =/nix/store/= identities and package symlinks remain
intact. A grant is not an atomic set of mounts; direct paths may be readable
before =current= changes. Partial failure ends the session, not a rollback.

* Payload policy and socket exception

The launch specification follows upstream's selective read-only closure mounts,
private HOME/tmp, and Bubblewrap boundary. Goblins uses an explicit adapter
because the upstream wrapper has no retained live-mount helper/control channel.
The pinned upstream wrapper is separately evaluable/buildable as
=upstream-baseline=; it is not the executable used for the live experiment.

The upstream default denies =socket(AF_UNIX)=. This adapter intentionally allows
Unix sockets so the one pathname request socket works. It mounts the socket
itself at =/run/goblins/request.sock=, not its parent directory. Other session
sockets, the Nix daemon, and socket inodes in workspace snapshots are absent.
Explicit startup host directory grants expose their contents, including any
socket inodes there; the launcher refuses grants covering its private control
and session directories. A separate network namespace isolates abstract Unix
sockets and host IP services. There is no pasta forwarding or host networking.

An x86_64 seccomp filter rejects mount APIs, =setns=, =unshare=, namespace-creating
=clone= flags, ptrace, and open-by-handle. It rejects alternate syscall ABIs.
=clone3= returns =ENOSYS= to permit libc's ordinary-process =clone= fallback.
Normal child execution succeeds; all capabilities and the capability bounding
set remain zero in the payload. This supplements filesystem, PID, and network
isolation; it is not a comprehensive syscall allowlist.

* Nix configuration and live grants

=mkGoblin=/=mkGoblins=, named presets, public flake outputs, literal environment
values/entry arguments and the upstream initial closure remain supported.
Each trusted launch supplies its own absolute manifest path and name, allowing
configuration-only rebuilds to start changed/new definitions on the same daemon.
Running sessions retain their selected configuration. Manifests declare API 1
and private helper API 1; mismatches fail only that launch. Manifest/build-spec
reads require bounded regular files. Launch configuration never comes from a
sandbox request. The daemon inherits bind-variable expansion values from its
own host environment; literal =env= values do not use that expansion path.

The daemon's =--workspace= selects the source for each independent disposable
snapshot. Source symlinks are not followed, .git entries and special files are
omitted, and no host hooks are executed. Explicit startup binds retain the
upstream four read/write file/directory options and exact store-target handling.
Host replacement races or an unresponsive filesystem/kernel are not made
transactional or cancellable by this milestone.

A validated request starts a cancellable advisory preview with IFD disabled.
Approval cancels that preview, then performs pinned host Nix realization,
closure rooting, collision checks, helper-acknowledged mounts and atomic profile
publication. Permission records distinguish realizing, mounting, publishing,
ready and failed. Host commands are read through bounded nonblocking pipes;
stdout is capped at 8 MiB and stderr retains at most 1 MiB. This bounds diagnostic
capture without imposing a file-size limit on Nix's own caches or store work.

The stable profile path is inherited at startup. Successful additive grants
become usable in the same payload process/mount namespace. Realization and
collision failures preserve the running session. Failure from mount preparation
through publication terminates that session; direct store paths may already be
visible, so there is no rollback or revocation claim.

Cancellation kills and reaps owned Nix client process groups, never the host Nix
daemon or its shared builds. Parent-death handling and PID namespace teardown
kill sandboxes on daemon death. Normal cleanup removes roots and resources;
SIGKILL can leave host files/roots for manual cleanup. Durable recovery, terminal
multiplexing, projects, Emacs integration and live file/network grants remain
outside this milestone. [[file:RESULTS.org][RESULTS.org]] records verification and its limits.
