#+title: Goblins for Emacs

A small Magit-style status buffer for the Goblins daemon. Requires Emacs 28.1+
and =magit-section= (included with Magit). Uses Emacs' built-in =jsonrpc= and
connects directly to the local host socket.

* Load and use

With your existing Emacs/Nix packages available, evaluate:

#+begin_src emacs-lisp
(add-to-list 'load-path "/path/to/goblins/emacs")
(require 'goblins)
#+end_src

Run =M-x goblins-status= and use =M-x goblins-start-server= if the server is not running.
You can invoke any Goblins command from any buffer; opening status first is
unnecessary. Server start/stop and refresh create or reuse their own status
buffer and leave the calling buffer's text and mode unchanged.
Startup runs asynchronously and connects the buffer automatically when ready.
Use =M-x goblins-stop-server= to stop the server and all its agents asynchronously;
the buffer reports when it has finished. These server commands have no default keybindings.
=M-x goblins-ensure-server= starts the server only if it is not already running
and connects, without displaying the status buffer; it reports in the echo
area, so it suits an init file: =(goblins-ensure-server)=.
The server uses this buffer's state directory and starts from its
=default-directory=, just like running the CLI from that directory.
Set =goblins-executable= to the packaged binary's absolute path if =goblins=
is not on Emacs' =exec-path=.
Use =M-x goblins-run= (or =R= in status) to choose from your Nix-configured
goblins with completion and launch one in a new Ghostel buffer.
Pressing Enter without typing selects the default shown in the prompt.
Requires your installed Ghostel package with =ghostel-exec= and its native module; Goblins
never downloads the module. Rebuild the Goblins CLI from this checkout first,
since this uses the new =configurations= and =attach= commands.

The buffer updates automatically
and includes agents, pending requests, and collapsible recent request history.
Agents form a tree rooted at =host=, with children nested beneath their owners.
Branches start expanded; =TAB= collapses or expands children only. The overview
contains headings only, with no detail rows. =RET= opens a separate details view
for the selected sandbox or request. Sandbox details show session IDs and
startup/granted packages; request details show the reason and preview. Details
update live and stay tied to the selected identity. Use =b= or =q= to return to
the tree with selection and branch folds preserved. Request labels use the
sandbox's full tree path to distinguish matching names in different branches.

Stopped children remain under their parent while any session in that root branch
is active. Entire stopped or failed trees move intact to “Stopped agents”. That
section and recent request history start collapsed. Live updates preserve section
identity, selection and your folding choices.

| Key | Action |
|-----+--------|
| =R= | Choose and launch a goblin in Ghostel |
| =n= / =p= | Next / previous section |
| =TAB= | Expand / collapse tree children |
| =RET= | Open sandbox or request details |
| =t= | Open the selected sandbox's Ghostel terminal |
| =b= | Return from details to the tree |
| =a= | Accept the pending request at point |
| =d= | Deny the pending request at point |
| =g= or =r= | Reconnect and refresh |
| =q= | Return from details, or close the overview; agents keep running |

When Evil is enabled, the buffer starts in normal state with dedicated bindings:

| Evil key | Action |
|----------+--------|
| =R= | Choose and launch a goblin in Ghostel |
| =j= / =k= | Next / previous section |
| =h= / =l= | Collapse / expand section |
| =TAB= or =za= | Expand / collapse tree children |
| =RET= | Open sandbox or request details |
| =t= | Open the selected sandbox's Ghostel terminal |
| =b= | Return from details to the tree |
| =a= / =d= | Accept / deny the pending request at point |
| =gr= or =r= | Reconnect and refresh |
| =gg= / =G= | Beginning / end of buffer |
| =q= | Return from details, or close the overview |

Evil support works with either package load order and changes only this mode's
bindings. Evil is optional and is never installed or enabled globally by Goblins.

Outside status, =goblins-accept= and =goblins-deny= offer completion over pending
requests, showing the agent, package, reason and request ID. =goblins-visit=
offers your locally launched terminal buffers, including retained exited ones.
=goblins-quit= closes only the relevant status view, never the calling file or
terminal buffer. Commands use the current Goblins buffer's server when available,
otherwise =goblins-state-directory= or the default server directory.

Launches start in the root of the calling buffer's project.el project, or in
its =default-directory= outside a project. When the project root has a
=flake.nix=, =goblins-run= asks whether to use it as the sandbox's dev shell
(like =--dev-shell .=). Each launch gets a new agent name from the daemon and a separate Ghostel buffer, even for the same
configuration. Status marks linked agents with =[t: terminal]=. Links use
the daemon instance and immutable session ID and live only in this Emacs
process. Closing/reopening status preserves them; killing the terminal buffer
removes the link. Terminal buffers stay available after process exit until you
close them. Agents started outside =goblins-run= have no terminal link, and
there is no adoption or terminal replay after a buffer is killed.
Goblins terminals keep their local launch directory in Emacs; namespace-local
shell directory reports are not interpreted as SSH hosts or host paths.

Acceptance starts provisioning; the request moves to recent history and its
state continues updating until ready or failed. Decisions always use the exact
displayed session/request/approval identity. If a selected request disappears or
moves to history, point returns to the top instead of selecting another request.
Disconnects, sequence gaps and errors disable decisions until =r= reconnects.
A timed-out decision is not automatically retried; refresh to inspect its outcome.

For a daemon launched with =--state-dir=, use =C-u M-x goblins-status= to select
that directory, or set =goblins-state-directory=. Otherwise the directory follows
the CLI's =$XDG_RUNTIME_DIR/goblins=, =/run/user/UID/goblins=, or
=/tmp/goblins-control-UID= fallback. Each directory gets its own status buffer.

This package starts a daemon only when you run =goblins-start-server=. It does not install
dependencies, run a package manager, or alter your Emacs configuration.
Nix-managed Emacs packages can be used
directly; there is no need to download another copy of Magit.

* Workspace

=M-x goblins-workspace= opens a sidebar listing the running goblins, grouped by raid and then by project directory.  Stopped and failed goblins are hidden (the status buffer still lists them; set =goblins-sidebar-show-finished= to show them, one dimmed line each).

Each goblin is a block: its name and type, then what its agent is doing and for how long (=◐ working · 4m=, =◆ needs input=, =◆ needs approval=, =○ idle=; no line while that is unknown), each pending permission request (=! jq (package)=), its queued inbox messages (=✉ 2 messages=), its shell terminals, and the shells and TRAMP connections opened elsewhere (=⇄ 1 shell · tramp=).  A rule parts the goblins of a directory, starting at each goblin's indent and fainter before a child; a blank line parts the groups.  =!N= on a heading counts the pending permission requests below it.

The sidebar has no cursor: the goblin or line at point is highlighted like the region (=goblins-sidebar-selected=).  =j= and =k= move by goblin, shell and heading, so a goblin's detail lines take a single step, like one line.  The goblin or shell shown beside the sidebar has a bar down its block, in the column before its text (=goblins-sidebar-active-marker=, whose foreground is the bar's colour); give =goblins-sidebar-active= a background to tint the block as well.  Neither highlight covers the indentation left of the bar's column.  The other faces are =goblins-sidebar-name=, =goblins-activity-working=, =goblins-activity-waiting=, =goblins-activity-idle=, =goblins-sidebar-permission=, =goblins-inbox=, =goblins-sidebar-separator= and =goblins-sidebar-child-separator=.

In Evil's motion state the sidebar's own keys take precedence over every minor
mode (evil-snipe's =t=, for example); other keys, such as a leader on =SPC=,
work as usual.  Shell
terminals opened with =t= are listed in their goblin's block (=› shell=, =› shell
2=, marked =· exited= once their shell ends) until you kill their buffer;
Eshell and Dired buffers are not listed.  Folds last for the Emacs session.

| Key (also Evil motion state) | Action                                                   |
|------------------------------+----------------------------------------------------------|
| =j= / =k=                    | next / previous goblin, shell or group                   |
| =n=                          | next goblin waiting for a decision (unfolds groups)      |
| =RET=                        | goblin: show or attach; shell: show it; raid: open its page; directory: fold |
| =TAB=                        | fold the group                                           |
| =p=                          | permissions of the goblin: current request, history      |
| =I=                          | info: everything the daemon knows about the goblin       |
| =K=                          | stop the goblin (and its running descendants)            |
| =t=                          | a new shell terminal inside the goblin, listed below it  |
| =e=                          | Eshell inside the goblin, in its directory               |
| =d=                          | Dired inside the goblin, in its directory                |
| =f=                          | visit a file inside the goblin (=goblins-find-file=)     |
| =X=                          | kill the goblin's shells and commands                    |
| =r=                          | create a raid around the goblin at point or on the left, or add it to one, and open the raid page |
| =i=                          | invite the goblin into a raid you pick; on a raid, invite a goblin into it |
| =D=                          | on a raid: dissolve it (its goblins keep running)        |
| =c= / =C=                    | run a goblin in the project at point / a project you choose |
| =g= / =gr=                   | reconnect                                                |
| =?=                          | key help                                                 |
| =q=                          | leave the workspace                                      |

The raid page lists the members (role, directory, =[term]= when an Emacs
terminal is open) and the running goblins that could join.  =i= invites the
goblin at point or one you choose, =x= kicks the member at point (kicking the
owner dissolves the raid), =R= sets a member's role, =D= dissolves the raid,
=RET= opens a goblin and =?= lists the keys.  Invitations join at once; there
is no acceptance step.

In the permissions view the current request is focused: =a= accepts, =d= denies,
=RET= folds a request, =q= goes back.  Add sections to the info view with
=goblins-info-section-functions=.

** Windows

Beside the sidebar:

- *Left: the agent window.* It belongs to the selected goblin's agent
  terminal; before any agent exists the status buffer stands in.  It is
  dedicated: other buffers are shown elsewhere, deleting the other windows
  keeps it, and deleting it is refused.
- *Right: everything else.* What Goblins opens for the goblin (shells =t=,
  Eshell =e=, Dired =d=, =C-c g f= files, files its =goblins-editor= opens) goes
  into the right window used last, and you show, split and arrange anything
  you like there.

Only windows Goblins split off the agent belong to the goblin: a window
another package splits below everything (shackle or popper showing
=*Messages*=, say) is never used for a goblin's buffers, saved, or closed on a
switch.

Each goblin keeps its windows.  Leaving it (selecting another goblin with =RET=,
=goblins-switch=, =t=/=e=/=d=, an approved edit or a new agent, or quitting the
workspace) saves them: splits, sizes, buffers and positions.  Selecting it
again, or =M-x goblins-workspace=, brings them back beside its agent.  Windows
whose buffer was killed are dropped; a goblin's windows are forgotten when it
stops, and never kept across Emacs sessions.

The info, permissions and raid views open on the right too, but are never
saved, as they are shared between goblins: =q= puts back what their window
showed before, and leaving the goblin saves that instead.

The first window on the right goes beside the agent when the agent window is
at least =split-width-threshold= wide, else below it (=split-height-threshold=,
or below anyway when it fits).  In a frame too small for two windows a buffer
you open takes the agent's place until you select a goblin again.

A pending permission request of the selected goblin pops up in a small
window at the bottom: what it asks for, the reason and a one-line preview.  It
opens when you select a goblin that is waiting and when the goblin on the left
asks for something, never takes the focus, isn't remembered, and closes once
nothing is waiting.  In it =a= accepts, =d= denies, =p= (or =RET=) shows all of
the goblin's requests and =q= closes it.  =M-x goblins-request-popup= opens it
for the goblin at hand; set =goblins-request-popups= to nil to turn it off.  The
=p= permissions view is unchanged.

Bring your own workspace package by setting
=goblins-workspace-switch-or-create-function= (called with the name
=goblins-workspace-name=).  The default saves the window configuration and uses
the whole frame; =goblins-workspace-quit-function= restores it.

#+begin_src emacs-lisp
(setq goblins-workspace-switch-or-create-function
      #'tabspaces-switch-or-create-workspace)
#+end_src

** Anywhere

- =M-x goblins-switch= completes over the running goblins, annotated with type,
  raid, directory and pending requests, and shows (or attaches) the chosen one.
- =M-x goblins-raid= is the sidebar's =r= from any goblin terminal.
- =goblins-attention-mode= shows =Goblins!N= in the mode line while requests are
  pending (click it to open the workspace) and announces new ones through
  =goblins-attention-notify-function= (an echo-area message by default).  For
  your own reaction, add a function to =goblins-request-hook=; it receives each
  request record once, when it becomes pending.
- A lost connection is retried after =goblins-reconnect-delays= (1, 2, 5, 10,
  then every 30 seconds); =r= in the status buffer or =g= in the sidebar
  reconnects at once.

** Goblin terminals

Every Ghostel buffer attached to a goblin turns on the minor mode =goblin-mode=,
so you can give those buffers keys of your own:

#+begin_src emacs-lisp
(define-key goblin-mode-map (kbd "C-c C-w") #'goblins-workspace)
(with-eval-after-load 'evil
  (evil-define-key 'normal goblin-mode-map (kbd "g i") #'goblin-info))
#+end_src

Its own keys are under =C-c g=: =w= workspace, =s= switch, =i= info, =p=
permissions, =r= raid, =K= stop, =v= paste image.  It is a minor mode rather than a mode derived
from =ghostel-mode= because =ghostel-exec= always puts the buffer in
=ghostel-mode= itself and Ghostel refuses major-mode changes while the terminal
runs; a minor mode composes with Ghostel and with evil-ghostel (also a minor
mode), and =C-c= is one of Ghostel's =ghostel-keymap-exceptions=, so =C-c= keys
reach Emacs in every input mode.

Also under =C-c g=: =t= opens a shell terminal inside the goblin, =e= Eshell,
=d= Dired, and =f= visits a file inside it (=goblins-find-file=).

=C-c g v= (=goblin-paste-image=, or =M-x yank-media=) pastes the image on the clipboard into the agent. The agents' own =Ctrl+V= can't work in a goblin: Claude Code and Codex read the clipboard themselves, through X11 or Wayland, and the sandbox has no display. Instead Emacs writes the image to =/tmp/goblins-clipboard/= inside the goblin and pastes its path, which both agents attach as an image. The goblin only ever sees the images you paste, never the clipboard, and they go away with it. Bind it to =C-v= in =goblin-mode-map= if you want the agents' usual key.

An agent terminal's =default-directory= is its goblin's working directory on
the host, the project bound at the same path inside the sandbox, so
=project-find-file=, magit and the like work from it on the host; it doesn't
follow the agent's =cd=.  A goblin without a project (its own =/workspace=) gets
=/goblins:HOST:/workspace/= instead.

Agent terminals draw no-break spaces without an underline, which fixes
Claude's thinking indicator; set =goblins-remove-nobreak-underline= to nil to
disable.

* Inside goblins: TRAMP, shells and the editor

=goblins-tramp.el= loads with TRAMP and adds the =/goblins:= method:

#+begin_example
C-x C-f /goblins:gribble:/tmp/diagram.svg
C-x C-f /goblins:gribble.snaga:/workspace/     ; a child: its tree path, with . for /
#+end_example

The host is an agent name, a tree path or a session ID, and running goblins
complete after =/goblins:=. The method's login program is =goblins exec=, so
dired, saving, eshell, =shell-command=, compile, grep, magit and eglot work
inside the sandbox, with its live =PATH=; asynchronous processes each run as
their own exec (=tramp-direct-async-process=). Killing a compilation or
deleting a process ends its remote process group too. =/goblins:= always means
the daemon of =goblins-state-directory=.

- *Pinning.* Names are reused, so the first connection to a host pins it to
  that goblin's (state directory, daemon instance, session ID), and every later
  command of the connection passes the pin to =goblins exec=. A command for a
  stopped goblin fails rather than reach a new goblin with the same name, even
  if Emacs missed the stop, and changing =goblins-state-directory= does not move
  existing connections. Shells and goblin terminals pin their goblin when they
  open; editor requests pin the requesting goblin first and are refused when
  the name is pinned to another one. =M-x goblins-tramp-release= releases a pin
  by hand, for a goblin of a daemon this Emacs does not follow.
- *VC stays out of goblins.* =/goblins:= is added to =vc-ignore-dir-regexp=, so
  VC (and with it diff-hl and dirvish's git status, and VC's branch in the
  mode line) never looks inside a goblin; magit, which doesn't use VC, works.
  VC ran git from process sentinels while TRAMP was waiting on its shell
  connection, which TRAMP refuses and answers by dropping the connection.
- *Commands while TRAMP is busy.* A =process-file= command that arrives while
  TRAMP is waiting for a reply (from a timer or a process sentinel) runs as
  its own =goblins exec= instead of failing as a reentrant call. Otherwise
  commands use TRAMP's connection, which is several times faster.
- *Connections close when unused.* TRAMP keeps a shell open in the goblin for
  each connection (=⇄ tramp= in the sidebar). It is closed when you kill the
  last buffer that works in that goblin; terminals don't count, as they have
  their own exec. The pin stays, so the next use reconnects to the same goblin.
- *When a goblin stops*, its =/goblins:= buffers and processes are killed
  (unsaved changes are discarded), then the pin is released. Goblin terminals
  are kept and return to your home directory. =/goblins:= buffers are never
  saved in desktops, and no connection data is persisted.
- *Files a goblin wrote* get only safe file-local variables and no =eval:=,
  also when emacsclient visits them. Their major mode still comes from the
  file name, and your own mode hooks still run on their contents.
- *Shells.* =M-x goblins-shell= opens the goblin's own =$SHELL=, or
  =goblins-shell-program= (a program name such as ="fish"=, or a list with
  arguments, found on the sandbox's =PATH=), with its dev shell, in a Ghostel buffer next to the agent's terminal (in a goblin terminal
  or =/goblins:= buffer it uses that goblin; with a prefix argument it asks). Shells
  track their directory (OSC 7) as =/goblins:= paths.
  =M-x goblins-eshell= and =M-x goblins-dired= open Eshell (one per goblin,
  reused) and Dired in the goblin's working directory, the same way. All three
  pin the goblin before any TRAMP use. =M-x goblins-find-file= visits any file
  inside a goblin, starting in its working directory. In the sidebar, =t=, =e=, =d= and =f= open
  them for the goblin at point and =X= kills its shells and commands; goblins
  show =· 1 shell · tramp= in the status buffer, and =⇄ tramp= in the sidebar, while they are in use.
- *The sandbox's =EDITOR=.* With =editor.emacs.enable= on =mkGoblins=,
  =goblins-editor= inside a sandbox opens files here through emacsclient,
  always as =/goblins:= paths; it needs a running Emacs server
  (=M-x server-start=) with goblins.el loaded. Finish each file with =C-x #=.
  Emacs asks first: the request pops up at the bottom, ahead of any
  permission request, naming the goblin and its files; =a= opens them, =d=
  refuses (the goblin's editor then fails with an explanation) and =q= leaves
  it waiting (=M-x goblins-request-popup= brings it back).  Set
  =goblins-editor-approval= to =approve= or =deny= to decide every time
  without asking; the default is =ask=.  In the workspace the files open
  right of the goblin's agent.

* Checks

Run with an Emacs that already has =magit-section= on its load path:

#+begin_src sh
emacs --batch -Q -L emacs --eval '(setq byte-compile-error-on-warn t)' \
  -f batch-byte-compile emacs/goblins.el emacs/goblins-views.el \
  emacs/goblins-raids.el emacs/goblins-terminal.el emacs/goblins-workspace.el \
  emacs/goblins-tramp.el
emacs --batch -Q -L emacs -l goblins-tests -f ert-run-tests-batch-and-exit
python3 -m unittest discover -s tests -p test_emacs.py
#+end_src

The Python integration tests exercise server start/stop/restart, real approvals,
two simultaneous Ghostel launches with working-directory input and status
links, and the whole workspace (sidebar, permissions, raids, stopping,
reconnecting, switching) in a real =emacs -nw= running in a pseudo terminal, as
well as =/goblins:= TRAMP, eshell, cancellation, pinning, =goblins-shell= and a
blocking =goblins-editor= against daemons built with =editor.emacs.enable=.
Each starts its own daemon on a temporary state directory and socket, so a
daemon you are running is never touched. They skip when Emacs or =magit-section= is unavailable; the Ghostel test
also requires its installed native module. These commands use =-Q= and do not
load your init file or install Emacs packages.
