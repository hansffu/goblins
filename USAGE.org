#+title: Goblins daemon and live package grants

* Start the daemon and frontends

Build from the repository root:

#+begin_src sh
nix build --out-link result-goblins path:.#goblins
export PATH="$PWD/result-goblins/bin:$PATH"
goblins server start
#+end_src

The ordinary-user server starts in the background and survives closing this
terminal. Repeating =server start= leaves the existing server and its environment
unchanged. Open the approval view:

#+begin_src sh
goblins tui
# Or: goblins tui --plain
#+end_src

In one or more other terminals:

#+begin_src sh
goblins run shell
#+end_src

Each run creates an independent interactive Fish sandbox, with commonTools from
the pinned agent-sandbox input. Use =run shell= to select the shell configuration.
Inside Fish:

#+begin_src fish
echo $fish_pid
goblins request-package hello --reason "Try a live package grant"
hello
echo $fish_pid
#+end_src

The fullscreen approval view keeps a request list above a popup containing the
selected permission's sandbox, package, reason, cost preview and Yes/No buttons.
The popup reserves space below the lists and pushes them upward. Tab switches
focus between sandboxes and requests; Up/Down selects in the focused list.
With requests focused, =y= approves and =n= denies. Left/Right selects No/Yes and
Enter activates the button (No by default); mouse clicks also work. Fullscreen
bracketed paste is ignored. A finished or withdrawn selection stays selected
until you choose another request, so queued input cannot approve its successor.
Escape closes the popup without cancelling the request; accepted approval or
denial closes it automatically. The request list remains visible. Up/Down or
Enter on a request reopens its details; opening a hidden popup does not decide it.

The plain fallback uses =approve TOKEN= or =deny TOKEN= with the complete
immutable displayed token. Its queued/partial commands keep their original
identity across request replacement.

The request exits 0 only after the approved package and its complete runtime
closure have been mounted read-only and the profile published. Denial or failure
exits 1. Missing/invalid/interrupted communication is an unknown outcome (exit 2),
without automatic retry. The same Fish PID and namespace remain in use after a
successful grant. Package names are bounded nixpkgs attributes, including
=cowsay= and =python3Packages.black=; paths, URLs, expressions and output selectors
are rejected. Host Nix chooses the bin output when available, otherwise default.
Development setup hooks and unrecorded plugins/data are not activated.

* Server commands, help and completion

#+begin_src sh
goblins server start                    # background; returns once ready
goblins server start --workspace /path/to/repository
goblins server status                   # state, instance ID and live agent count
goblins server logs                     # print captured stdout/stderr
goblins server stop                     # stop all agents and wait for cleanup
goblins server start --foreground       # optional terminal/supervisor mode

goblins                                 # help menu
goblins --help
goblins help run
goblins server start --help
#+end_src

=server start= inherits this process's environment and working directory. Startup
bind variables use that environment; =--workspace= chooses the per-agent snapshot
source. Options on a repeated start do not change an existing server. Stop and
start again to change its environment/workspace. There is no service installation,
automatic restart or session recovery. =goblins shell= and =goblins daemon= are
not commands; use =goblins run shell= and =goblins server start=.

The background server writes stdout/stderr to the private =STATE/server.log=,
appending across starts. =server logs= prints that output once; it does not follow
the file, summarize permissions or show sandbox terminal output. Foreground mode
writes to its terminal/supervisor instead. Logs currently contain startup and
shutdown messages and errors. No log rotation is provided yet.

Start waits up to ten seconds for readiness and reports startup failures with a
pointer to logs. Stop uses the private host API, stops all agents, and waits up
to fifteen seconds for the daemon lock to be released. If cleanup takes longer,
it reports that the stop was accepted but remains incomplete; it does not force
kill an unrelated process. Start/stop operations are serialized by a private
management lock; competing operations may report that the lock is held. There
are no PID files. Repeating stop after shutdown succeeds. =server status= exits
0 for a responsive server and 1 when stopped, starting/stopping without a
responsive endpoint, or on an error. Missing-server status/logs do not start it.

Nix packages install completion scripts in the standard Fish, Bash and Zsh
locations under =share/=. Your shell/profile needs its usual completion loading
enabled. Scripts complete commands, options, paths and this Nix package's =run=
configuration keys. =attach=, =detatch= and =detach= also complete live agent
names by querying the current server, respecting =--state-dir=. No names are
offered when the server is stopped; completion never starts a server. Editor
attachments using =--instance= require exact IDs and do not offer name candidates.
For manual installation or one shell session:

#+begin_src fish
# Fish
goblins completions fish | source
#+end_src
#+begin_src bash
# Bash
source <(goblins completions bash)
#+end_src
#+begin_src zsh
# Zsh (after compinit)
source <(goblins completions zsh)
#+end_src

Completions come from the same command tree as help and argument validation.
Generating them reads the selected runtime manifest and does not connect to or
start the server. Regenerate manually installed scripts after changing Nix
configuration names. Live session names are not included in these static scripts.

* Agent names

Configuration/preset names and agent names are separate. =run CONFIG= selects a
reusable Nix definition; =--name NAME= labels that single sandbox session:

#+begin_src sh
goblins run shell --name snikk
goblins run shell --name scout-2
goblins run shell                  # daemon chooses an available goblin name
goblins list
goblins stop snikk
#+end_src

Agent names are case-sensitive, 1..32 ASCII lowercase letters, digits or hyphens,
starting with a letter. Invalid names and explicit live-name collisions return
clear errors. No normalization or automatic suffix is applied to explicit names.
Names are unique within a daemon, including starting and stopping sessions, and
remain reserved until the worker finishes cleanup. Once released, a name may be
reused, even while the previous session's terminal output is still draining.
There is no renaming operation.

The daemon randomly chooses among the available names in
[[file:crates/controller/src/goblin-names.txt][the checked-in list of 128 fantasy goblin names]]. The runtime still permits
16 live sessions; the larger pool adds variety without changing that limit. If
none is available, launch fails immediately with a resource-limit error;
allocation never spins or silently collides. Custom names do not consume list
entries unless they match a list name. The live-session limit still
applies. All host API launches use this same allocator. Selection uses OS
randomness with unbiased sampling; randomness failures return a resource-limit
error without accepting a launch. A retry of an accepted launch keeps its name.

The list, fullscreen overview and plain =status= show the allocated agent name
and the reusable configuration identity. Permission records and events retain
the agent name even if the corresponding session record is later evicted.
Historical sessions and permissions may share a name, but always have distinct
immutable IDs. =stop ID_OR_NAME= and host =sessions.get/stop {session}= accept
an exact session ID or a live agent name. After completion, inspect/stop retained
history by ID. A reused name targets its current live session; use IDs in
scripts that must keep targeting the original launch. Approval decisions,
permission filters and resize still require IDs, never agent names.

For host API 1, =sessions.start= keeps =name= as the configuration key and
=configuration= as the absolute manifest path. Optional =agent_name= requests a
session name; omitted or null means automatic allocation. For example:

#+begin_src json
{"key":"my-launch-1","configuration":"/absolute/manifest.json","name":"shell","agent_name":"snikk","rows":24,"cols":100}
#+end_src

The start result adds =agent_name= alongside =session,state,terminal=.
Session records add =agent_name= while preserving =name,configuration=;
permission records also add =agent_name=. Host initialization advertises
=agent-names=. Existing launch requests remain valid; clients should tolerate
additive result fields. An older daemon must be upgraded to supply naming.
An identical launch key and parameters (including the requested name) return
the original acceptance result and allocated name, even after completion,
name reuse or record eviction. Retries never allocate a new name. Omitting
=agent_name= and passing null are equivalent; changing it to the allocated name
is a parameter change and conflicts. Retry the original request exactly.

* Closing, stopping and inspecting

Closing =tui=, pressing =q= in fullscreen or typing =quit= in plain mode, or closing a terminal
client leaves sessions owned by the daemon. A fresh =tui= discovers current
sessions, pending approvals and retained outcomes from a new atomic snapshot.
From inside a sandbox, =goblins detatch= (also spelled =goblins detach=) returns
to the host terminal with exit status 0. The shell, its working directory,
variables, processes and pending approvals stay alive. From the host:

#+begin_src sh
goblins detatch snikk                   # detach its current terminal from the host
# goblins detach snikk                  # equivalent spelling
goblins attach snikk                    # reconnect to the same sandbox
goblins kill snikk                      # stop it, including when detached
#+end_src

Host detach accepts a live name or immutable session ID, including while a
foreground command is running. It leaves the sandbox running and makes its
terminal client exit 0. An unknown or already unattached session returns an error.

Only one terminal can attach at a time; a competing attachment fails. Closing
a terminal unexpectedly also leaves the sandbox available for attachment.
Detached output retains a tail of up to 64 KiB; older bytes can be discarded so
background writers keep running. This is raw output, not full terminal screen
restoration or durable scrollback. An attached slow reader still backpressures
its sandbox. Reconnect is to the same daemon only; restarting it loses sessions.
=kill= and the existing =stop= command use the same session shutdown path.

To inspect or explicitly stop a session from a trusted host terminal:

#+begin_src sh
goblins list
goblins kill ID_OR_NAME
goblins rpc permissions.list '{}'
goblins rpc sessions.get '{"session":"SESSION_ID"}'
#+end_src

Typing =exit= in Fish naturally ends its session. Connected terminal output is
drained before =run= returns the payload exit code. Broken output delivery or
daemon death reports failure. Use =goblins server stop= to stop the server and all its sessions. Frontend quit does not stop it.

The fullscreen sandbox overview supports Enter to open package details.
Escape returns; Up/Down scroll packages when sandboxes have focus.
Page Up/Down scroll request details; Ctrl-C also closes the frontend. Preview estimates are advisory and
may be Unknown. Colors use the terminal palette; =NO_COLOR= suppresses colors.
The plain view additionally accepts =status= to print current state.

* Nix API

The root flake exports =lib.x86_64-linux.{mkGoblin,mkGoblins,commonTools,goblins}=. The
=packages.x86_64-linux.goblins= and default package are built with these helpers.
See [[file:README.org::*Configure named goblins with Nix][the configuration example]].

Use =lib.x86_64-linux.goblins.shell= for the predefined interactive Fish
configuration in =nix/goblins/shell.nix=. The host and inner binary definitions
live separately under =nix/packages/=. The preset uses commonTools and is the
default =goblins run shell= configuration; custom entries still use =mkGoblin=.

=mkGoblins { goblins = { NAME = mkGoblin { ... }; }; }= returns a Nix derivation
providing the host =bin/goblins= executable, with =config= and =goblins=
attributes for inspection. Names select entries through =goblins run NAME=.
Each =run NAME= supplies its Nix-generated manifest to the same live daemon.
Changed definitions and new names can launch concurrently without restarting
the daemon; existing sessions keep their configuration. Manifests/helper builds
must implement API 1. Installing an incompatible daemon protocol requires a
restart, which ends existing sandboxes.

=mkGoblin= calls upstream =mkSandbox= with the inner request executable added
to =allowedPackages=. Its result carries upstream's =buildSpec= plus a =goblin=
configuration consumed by =mkGoblins=. Launch it with =goblins run= to receive
the session request socket and retained mount helper. Directly invoking the
upstream wrapper is a separate static sandbox and has no approval connection.

| Option | Meaning / default |
|--------+-------------------|
| =pkg= | Required Nix package providing the entry executable |
| =binName= | Required executable name under =pkg/bin= |
| =outName= | Upstream wrapper name; defaults to =goblin-${binName}= |
| =allowedPackages= | Initially available packages; defaults to upstream =commonTools= |
| =args= | Literal entry argument list; defaults to =[]= |
| =env= | Literal string environment values; defaults to ={}= |
| =allowNix= | Must be =false=; host daemon stays hidden |
| =allowUnixSockets= | Must be =true= for the request transport |
| =allowedDomains=, =allowedHostPorts=, =publishedPorts= | Currently must be =[]= |
| =rwDirs=, =rwFiles=, =roDirs=, =roFiles= | Forwarded startup host bind paths; defaults to =[]= |

Unsupported network settings and malformed option types fail at Nix evaluation. Unlike upstream's
environment fragments, Goblin =env= values are literal: =$HOME= and =$(...)=
are not expanded or executed on the host. =PATH=, =HOME=, =SHELL=, =USER=,
=LOGNAME=, and =PYTHONNOUSERSITE= are reserved. Store paths used in =env= must
also be included through an allowed package's closure to be visible inside.

The four bind options use the upstream names and string-list format. Paths
expand =$VAR=, =${VAR}= and leading =~/= using the host =daemon= environment;
no shell command is evaluated. Bind sources must exist, match the declared
file/directory kind, and have absolute paths without =..=. The private sandbox
HOME uses the host HOME pathname, so a =$HOME/.config/fish= bind is also where
Fish looks. The rest of HOME remains private. Writable binds modify host data;
read-only binds reflect host changes without allowing sandbox writes.

Goblins rejects overlapping bind destinations and binds covering protected
namespace, store, workspace or controller paths. Symlinks in selected directories
do not automatically grant other host files. Links into the immutable Nix store
expose only their selected targets, including links inside config subdirectories;
those store outputs are rooted without mounting their entire closures. Symlinks
added or retargeted to previously hidden store targets require a new session.
The opened file/directory is bound, never copied. Replacing its host pathname
or an ancestor during startup does not redirect the grant to a different object;
changes within the granted object remain visible. Startup binds do not add a live
file-grant operation or change the disposable =--workspace= snapshot behavior.

The initial closure now comes from =mkSandbox=, including its implicit
packages and development outputs. Later package requests still select =bin=
or the default output and its runtime closure; they do not activate development
setup hooks. =/bin/sh= uses upstream's Bash wrapper even when Fish or another
program is the goblin entry point.

* State, workspace and authority

The host socket is =host.sock= under =$XDG_RUNTIME_DIR/goblins= (normally
=/run/user/UID/goblins=), with a private =/tmp/goblins-control-UID= fallback.
Use =--state-dir PATH= consistently on daemon and frontend commands for an
isolated instance. Keep the pathname short enough for Unix sockets, including
its session ID and =terminal.sock= suffix (about 60 additional bytes).
The directory must be owned by you, nonsymlink and mode 0700. A lock prevents
a second daemon taking over that instance. Host and terminal sockets stay
outside sandbox startup binds; all session resources are beneath this protected
tree, including sessions created later.

=goblins run= preserves the calling terminal's working directory and binds it
read/write at the same path, including its nested files and directories. Changes
are visible on the host and in the sandbox. Each launch supplies its own directory,
independently of where the daemon started. Protected controller paths cannot be
exposed this way.

To use a separate disposable copy at =/workspace= for every launch instead,
start the daemon with:

#+begin_src sh
goblins server start --workspace /path/to/repository
#+end_src

The snapshot omits .git entries, sockets, FIFOs and devices, follows no source
symlinks and executes no host hooks. Normal cleanup deletes it. Explicit startup
binds still select live host files/directories with their declared read/write
permissions. Bind variables expand from the daemon's inherited environment,
including HOME; =mkGoblin.env= values and entry arguments remain literal.

Session logs, sockets, mount placeholders, profiles and GC roots live below
=STATE/SESSION/resources=. Logs are disposable and bounded. Normal session stop
cleans resources; daemon SIGKILL kills payloads but can leave directories and
roots. Remove crash leftovers only after verifying that daemon/session is gone.
There is no startup recovery or automatic reconciliation of old directories.

The restricted executable inside the sandbox implements only package requests.
It initializes on that session's endpoint and sends JSON-RPC 2.0 with
Content-Length framing. It cannot choose a session, manifest, PID, mount target,
namespace, Nix expression or approval. Only the separate private host socket
accepts lifecycle and decision operations. The namespace helper retains narrow
private pipes; daemon threads never enter mount namespaces.

* Protocol and limits

[[file:DAEMON.org::*Implementation contract (2026-09-13)][DAEMON.org's API 1 contract]] specifies complete framing, method parameters,
error codes, snapshots, sequence numbers and duplicate-launch rules. An
uncertain =sessions.start= can be inspected/repeated with the same caller key
and identical parameters; the CLI never automatically repeats a launch.
Launch keys are retained for one daemon lifetime, up to 4096. Completed session
and permission records are bounded and can be evicted, after which get returns
an absent/evicted error. An evicted outcome must not be assumed successful.

The initial limits are 16 live sessions, 128 session records, 256 permission
records, 128 initial package entries, 64 successful package names per session,
32 host connections and 8 sandbox connections per session. Each session has
one pending approval/grant. Incomplete frames have a non-sliding three-second
deadline; human decisions and builds do not. Each host connection has a 2-MiB
output queue; a slow subscriber is disconnected and must resubscribe. Terminal
buffers are 64 KiB in each direction; a slow reader affects only its session.
These are protocol resource bounds, not payload CPU/process/memory/disk quotas.

* Reproducible checks

#+begin_src sh
nix develop path:.
cargo test --workspace --locked
cargo fmt --all --check
cargo clippy --workspace --all-targets --locked -- -D warnings
nix build path:.#goblins
nix flake check path:.
python3 -m unittest discover -s tests -p 'test_*.py' -v
#+end_src

Tests require host Nix, Unix sockets and ordinary-user namespace access. An outer
execution sandbox may require running those checks with its normal host-access
approval mechanism. No production Python is used: Python is a test driver only.
The ignored Rust Session harness supports fault-injected mount and namespace
probes; production API/terminal tests use the Nix-built executables.

* Scope and requirements

Linux x86_64, unprivileged user namespaces, Nix, and support for openat2,
open_tree, mount_setattr, move_mount, close_range and namespace ownership ioctls
are required. Grants are additive; mount/publication failure kills the affected
session without claiming rollback. Stopping owned Nix clients does not cancel
shared host Nix daemon work. Unresponsive filesystem/kernel calls may delay
cleanup. Emacs status, approvals and Ghostel launches are described in
[[file:emacs/README.org][the Emacs guide]]. The =configurations= command prints the current manifest
path and configured names as JSON without contacting a server. Editor launches
use =attach SESSION --instance INSTANCE= to consume a newly created session's
terminal stream; supplying =--instance= still requires exact IDs. Without that
option, =attach= accepts a live agent name or immutable session ID.
No terminal multiplexing, projects, live file/network
grants or daemon restart recovery is provided.
See [[file:RESULTS.org][RESULTS.org]] for measured evidence and limitations.
