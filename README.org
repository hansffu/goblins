#+title: Goblins

A Rust sandbox runtime for approved live Nix package grants. A foreground CLI
is the current frontend; Emacs integration is planned.

See [[file:PLAN.org][the project plan]] for goals, architecture, and milestones.

* Documentation convention

Use Org mode (=.org=) for repository documentation, including plans, design
notes, and experiment reports. Use native Org headings, links, lists, tables,
and source blocks.

* Rust runtime

The root flake provides the =goblins= package, default app, and development
shell for x86_64-linux, with nixpkgs and agent-sandbox.nix pinned in =flake.lock=.
From this worktree:

#+begin_src sh
nix build path:.#goblins
./result/bin/goblins serve
#+end_src

In a second terminal, run =./result/bin/goblins run shell=. Inside Fish, request
=goblins request-package cowsay=, approve in the serve terminal, then run
=cowsay hello=. Arbitrary package attributes resolve from the pinned nixpkgs
revision; package grants do not restart the shell.

Alternatively, =nix run path:. -- serve= and =nix run path:. -- run shell= run the
default app, and =nix develop path:.= puts =goblins= and build tools on PATH.
The explicit =path:.= also includes uncommitted source files.

See [[file:USAGE.org][the runnable demo]] and
[[file:RESULTS.org][the experiment results]].

* Configure named goblins with Nix

The flake exports =lib.x86_64-linux.mkGoblin= and =lib.x86_64-linux.mkGoblins=.
=mkGoblin= wraps upstream =mkSandbox= and includes the restricted inner =goblins=
command. =mkGoblins= returns a package containing the host =bin/goblins= command.
Add that package to your flake outputs:

#+begin_src nix
let
  system = "x86_64-linux";
  pkgs = nixpkgs.legacyPackages.${system};
  inherit (goblins.lib.${system}) mkGoblins mkGoblin commonTools;
in {
  packages.${system}.goblins = mkGoblins {
    goblins = {
      shell = mkGoblin {
        pkg = pkgs.fish;
        binName = "fish";
        args = [ "--interactive" ];
        roDirs = [ "$HOME/.config/fish" ];
        allowedPackages = commonTools;
        env.PAGER = "less";
      };
      bash = mkGoblin {
        pkg = pkgs.bashInteractive;
        binName = "bash";
        args = [ "--noprofile" "--norc" "-i" ];
        allowedPackages = commonTools ++ [ pkgs.tree ];
      };
    };
  };
}
#+end_src

Here =goblins= is this flake input. Build =.#goblins=, start its =goblins serve=
in one terminal, then use =goblins run shell= or =goblins run bash= in another.
The configured name selects the sandbox; =binName= selects its executable.
The server accepts one active goblin at a time, with live package requests in
each. =goblins shell= remains an alias for =goblins run shell=.

After changing a definition, rebuild and invoke the new package's =goblins run=.
Its host client sends the new manifest path to the running server, which loads
it for that session. Changed definitions and new names do not require restarting
=serve=; exit an active goblin before launching another.

See [[file:USAGE.org::*Nix API][the Nix API options and limits]].

Predefined goblins live under =nix/goblins/= and are exposed through
=lib.x86_64-linux.goblins=. The default package uses the Fish preset:

#+begin_src nix
mkGoblins {
  goblins.shell = goblins.lib.x86_64-linux.goblins.shell;
}
#+end_src

* Repository layout

The branch contains the implementation directly; there is no separate spike
flake. =flake.nix= declares inputs, configures the default goblins, and wires
package, app, check, and development-shell outputs.

| Location | Purpose |
|----------+---------|
| =nix/lib.nix= | =mkGoblin= and =mkGoblins= |
| =nix/packages/goblins.nix= | Host binary, including its Rust helper, controller, and pinned catalog |
| =nix/packages/internal-goblins.nix= | Restricted =goblins request-package= binary for the sandbox |
| =nix/goblins/shell.nix= | Predefined interactive Fish goblin with commonTools |
| =tests/fixtures.nix= | Runtime dependency fixtures and upstream baselines |
| =tests/checks.nix= | Nix API validation and named configuration test build |
| =src/main.rs= | Retained single-threaded namespace mount helper |
| =crates/protocol/= | Bounded request/reply types, validation and deadline |
| =crates/client/= | Restricted Rust sandbox request executable |
| =crates/controller/= | Rust session library, event pump, worker and serve/run frontend |
| =nix/packages/rust.nix= | Shared Rust build derivation with separate package selection |
| =tests/= | Python black-box payload and terminal tests; Nix checks |

Build and test from the repository root:

#+begin_src sh
nix develop path:.
cargo test --workspace --locked
cargo fmt --all --check
nix build path:.#goblins
nix flake check path:.
python3 -m unittest discover -s tests -p 'test_*.py'
#+end_src

The controller accepts explicit frontend decisions; its library never opens
=/dev/tty=. One cancellable worker owns startup and sequential grants while the
controller continues handling requests and attachment disconnects. The internal
client depends only on shared protocol code, with no host policy or mount API.
There is no production Python executable or mandatory Python interpreter.

This rewrite preserves PoC commit =c2a9d42= as its behavioral reference. It does
not implement a daemon, Emacs/TUI, multiplexing, file/network live grants, or
controller restart recovery. Controller death stops the helper and sandbox;
abrupt death may leave host session directories and GC roots for manual cleanup.
