*Created for me, by me (and Codex).*

This is a personal experiment, built with substantial AI-generated code. It is

* What is Goblins?

A Rust sandbox runtime for approved live Nix package grants. A fullscreen terminal app
and an Emacs status buffer provide agent status and approvals.

See [[file:docs/specs/PLAN.org][the project plan]] for goals, architecture, and milestones.
The daemon contract is recorded in [[file:docs/specs/DAEMON.org][the daemon and communication decisions]];
current usage and verified evidence are in USAGE.org and RESULTS.org.
The next agent milestone is described in
[[file:docs/specs/AGENT-INTEGRATION.org][the agent integration specification]]: daemon inboxes, sandbox-local hooks and skills,
native agent interfaces, and Codex/Claude Code communication drivers. Manual
inbox messaging, turn-boundary hooks and idle notification are implemented.
Network access is open by default, matching agent-sandbox.
The accepted architecture is recorded in
[[file:docs/adr/0001-daemon-inboxes-for-agent-communication.md][ADR 0001: daemon inboxes with notify-then-fetch]].

* Install on NixOS

Currently supported: *x86_64 Linux*, with Nix and unprivileged user namespaces.
The runtime requires modern Linux mount APIs; see [[file:USAGE.org::*Scope and requirements][runtime requirements]].
Run Goblins as your normal user, not as root.

For a NixOS configuration managed with flakes, add this input to your existing
=flake.nix=:

#+begin_src nix
inputs.goblins.url = "github:hansffu/goblins";
#+end_src

Keep your existing =nixpkgs= input and system modules. Add =goblins= to the
=outputs= arguments and install its package through =environment.systemPackages=.
For example, adapting =your-host= and the modules to your configuration:

#+begin_src nix
outputs = { nixpkgs, goblins, ... }: {
  nixosConfigurations.your-host = nixpkgs.lib.nixosSystem {
    system = "x86_64-linux";
    modules = [
      ./configuration.nix
      {
        nix.settings.experimental-features = [ "nix-command" "flakes" ];
        environment.systemPackages = [
          goblins.packages.x86_64-linux.default
        ];
      }
    ];
  };
};
#+end_src

From your NixOS configuration directory, lock the new input and rebuild:

#+begin_src sh
nix flake lock
sudo nixos-rebuild switch --flake .#your-host
#+end_src

If flakes are not enabled yet, first add
=nix.settings.experimental-features = [ "nix-command" "flakes" ];= to your
existing NixOS configuration and rebuild it with =sudo nixos-rebuild switch=.
See [[https://nix.dev/concepts/flakes.html][the Nix flakes documentation]] and
[[https://wiki.nixos.org/wiki/NixOS_system_configuration][NixOS system configuration]] for the general setup.

This installs the command and shell completions. It does not install a NixOS
service or start a server automatically. The flake keeps its own pinned
=nixpkgs= and =agent-sandbox.nix= inputs; your system's package set can stay as it is.

** Quick start

From the project directory you want to work in:

#+begin_src sh
goblins server start
goblins tui
#+end_src

In another terminal, from that project directory:

#+begin_src sh
goblins run shell --name snikk
#+end_src

Inside the sandbox, request a package, approve it in the TUI, then use it:

#+begin_src fish
goblins request-package cowsay --reason "Try a live package grant"
cowsay hello
#+end_src

Omit =--name= to get a randomly selected fantasy goblin name. The current directory is shared with the sandbox. Use
=server start --workspace DIR= for a disposable snapshot instead. Children share
their parent’s workspace. Explicit writable binds modify host files.
Closing the TUI leaves agents running. Inside a sandbox, =goblins detach=
returns to the enclosing terminal while leaving it running. Use
=goblins detach snikk= from another host terminal to detach it from outside,
=goblins attach snikk= to reconnect, =goblins kill snikk= to stop one agent,
or =goblins server stop= to stop the server and all its agents. A sandbox with
live descendants requires =kill --kill-children=. Normal sandbox exit stops its
entire subtree. See [[file:USAGE.org::*Sandbox ownership][sandbox ownership]] for nested launches,
=--parent=, =--detatched=, and inherited package approvals.

For Emacs, load [[file:emacs/goblins.el][goblins.el]] and run =M-x goblins-status= for a Magit-style
buffer with live agent/request sections and =a=/=d= accept/deny actions.
Use =M-x goblins-run= to choose a configuration and launch it in Ghostel;
=RET= on its status entry opens details; =t= opens its terminal buffer.
See [[file:emacs/README.org][Emacs setup and keys]]; it uses your existing =magit-section= package.

* Rust runtime

The root flake provides the =goblins= package, default app, and development
shell for x86_64-linux, with nixpkgs and agent-sandbox.nix pinned in =flake.lock=.
From this worktree:

#+begin_src sh
nix build path:.#goblins
./result/bin/goblins server start
#+end_src

Run =./result/bin/goblins tui= for approvals. In further
terminals run =./result/bin/goblins run shell=. Inside Fish, request
=goblins request-package cowsay=, approve the request in the tui terminal,
then run =cowsay hello=. Arbitrary package attributes resolve from the pinned nixpkgs
revision; package grants do not restart the shell.

Alternatively, =nix run path:. -- tui= and =nix run path:. -- run shell= run the
default app, and =nix develop path:.= puts =goblins= and build tools on PATH.
The explicit =path:.= also includes uncommitted source files.

=server start= runs in the background. Use =goblins server status=,
=goblins server logs= and =goblins server stop= to inspect its state/output or
stop it and its agents. =goblins --help= and =goblins help COMMAND= describe the
CLI. Nix packages install Fish, Bash and Zsh completions, including configured
=run= names; =goblins completions SHELL= prints a script for manual setup.

See [[file:USAGE.org][the runnable demo]] and
[[file:RESULTS.org][the experiment results]].

* Configure named goblins with Nix

Add the Goblins input to your NixOS flake, then construct a package with
=mkGoblins= and install it through =environment.systemPackages=. This replaces
the default package from the installation example above. Keep your existing
=nixpkgs= pin and system modules when adapting this example:

#+begin_src nix
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
    goblins.url = "github:hansffu/goblins";
  };

  outputs = inputs@{ nixpkgs, ... }: {
    nixosConfigurations.your-host = nixpkgs.lib.nixosSystem {
      system = "x86_64-linux";
      modules = [
        ./configuration.nix
        ({ pkgs, ... }:
          let
            inherit (inputs.goblins.lib.x86_64-linux)
              builders defaultGoblins commonTools;
            inherit (builders) mkClaudeGoblin mkCodexGoblin mkGoblins;

            goblins = mkGoblins {
              goblins = {
                # Reuse the premade interactive Fish sandbox.
                shell = defaultGoblins.shell;

                # Native Codex with shared auth and sandbox-only hooks/skill.
                codex = mkCodexGoblin {
                  # description = "Codex running in a Goblins sandbox"; # default
                  # Defaults to the Codex package from Goblins' pinned Nixpkgs.
                  # pkg = pkgs.codex;
                  codexConfigDir = "$HOME/.codex"; # default; runtime path string
                  allowedPackages = commonTools;
                  codexSettings.model_reasoning_effort = "high";
                };

                # Native Claude Code with the same hooks and skills.
                claude = mkClaudeGoblin {
                  # description = "Claude Code running in a Goblins sandbox"; # default
                  claudeConfigDir = "$HOME/.claude"; # default
                  allowedPackages = commonTools;
                  claudeSettings.model = "sonnet";
                };
              };
            };
          in {
            environment.systemPackages = [ goblins ];
          })
      ];
    };
  };
}
#+end_src

Here =inputs.goblins= is the flake, while the local =goblins= value is your
configured package. =mkGoblin= wraps agent-sandbox =mkSandbox= and includes the
restricted inner =goblins request-package= command; =mkGoblins= supplies the
host =bin/goblins= command with all your configurations.

Rebuild your NixOS configuration with =sudo nixos-rebuild switch --flake .#your-host=.
Start =goblins server start= and =goblins tui=, then use =goblins run shell=,
=goblins run codex --name snikk= or =goblins run claude --name snikk= in another terminal.
The default package includes all three. =mkCodexGoblin= accepts the =mkGoblin= options,
adds the Codex directory as a writable startup mount, and installs managed
hooks plus spawning, messaging and package-request skills under sandbox-only
=/etc/codex=. It never installs
those files into your host Codex configuration. The selected directory must
already exist; use a string such as ="$HOME/.codex"= or ="/path/to/codex"=,
not a Nix path that would copy credentials into the store.

=codexSettings= supplies additional sandbox system configuration, including
extra native hooks; the built-in SessionStart, UserPromptSubmit and Stop handlers are retained.
Codex uses the outer Goblins sandbox, with its nested sandbox disabled and
approvals handled by Goblins. See [[file:USAGE.org::*Codex configuration][Codex setup and current limitations]].
=mkClaudeGoblin= provides the equivalent Claude Code state mount, managed hooks
and shared skills; see [[file:USAGE.org::*Claude Code configuration][Claude Code configuration]].
The helper uses open internet access through a private network namespace.
No domain allowlist or HTTP proxy is required. Set =allowedDomains = []= for
an explicitly offline sandbox.

The configured name selects a reusable sandbox configuration; =binName= selects
its executable, while =description= tells users and agents what that named
configuration runs. Give each launch its own agent name with
=goblins run shell --name snikk=.
Without =--name=, the daemon randomly chooses an available name from the
checked-in list of 128 fantasy goblin names. =goblins list= shows both identities;
=goblins stop snikk= stops the live agent. Session IDs remain authoritative, including for history and
approvals. See [[file:USAGE.org::*Agent names][agent naming and reuse rules]].
The daemon supports simultaneous goblins with independent requests and grants.

After changing a definition, rebuild your NixOS configuration and invoke
=goblins run= from the newly installed package.
Its host client sends the new manifest path to the running server, which loads
it for that session. Changed definitions and new names do not require restarting
the server; existing sessions retain their selected configuration.

See [[file:USAGE.org::*Nix API][the Nix API options and limits]].

Builder functions live under =inputs.goblins.lib.x86_64-linux.builders=.
Premade sandboxes live under =nix/default-goblins/= and are exposed through
=inputs.goblins.lib.x86_64-linux.defaultGoblins=. The presets are =shell= (interactive Fish with =commonTools=), =codex= and =claude=.
The example above customizes the Codex preset. To install just the preset, use this =mkGoblins=
definition in the same =let= binding:

#+begin_src nix
mkGoblins {
  goblins.shell = defaultGoblins.shell;
}
#+end_src

* Repository layout

The branch contains the implementation directly; there is no separate spike
flake. =flake.nix= declares inputs, configures the default goblins, and wires
package, app, check, and development-shell outputs.

| Location | Purpose |
|----------+---------|
| =nix/lib.nix= | Public constructors and presets |
| =nix/builders/= | =mkGoblin=, =mkCodexGoblin=, =mkClaudeGoblin= and =mkGoblins= constructors |
| =nix/default-goblins/= | Default shell, Codex and Claude Code presets |
| =nix/goblins/codex/= | Codex launcher, hooks and managed config |
| =nix/goblins/claude/= | Claude Code launcher, hooks and managed config |
| =skills/= | Reusable Goblins agent skills |
| =nix/internal/= | Shared Nix argument validation |
| =nix/packages/goblins.nix= | Host binary, including its Rust helper, controller, and pinned catalog |
| =nix/packages/internal-goblins.nix= | Restricted =goblins request-package= binary for the sandbox |
| =tests/fixtures.nix= | Runtime dependency fixtures and agent-sandbox baselines |
| =tests/checks.nix= | Nix API validation and named configuration test build |
| =src/main.rs= | Retained single-threaded namespace mount helper |
| =crates/protocol/= | Bounded request/reply types, validation and deadline |
| =crates/client/= | Restricted Rust sandbox request executable |
| =crates/controller/= | Rust session library, event pump, worker and tui/run frontend |
| =nix/packages/rust.nix= | Shared Rust build derivation with separate package selection |
| =tests/= | Python black-box payload and terminal tests; Nix checks |
| =emacs/= | Magit-style agent status and approval frontend |

Build and test from the repository root:

#+begin_src sh
nix develop path:.
cargo test --workspace --locked
cargo fmt --all --check
nix build path:.#goblins
nix flake check path:.
python3 -m unittest discover -s tests -p 'test_*.py'
#+end_src

The development shell includes pyte for fullscreen terminal regression tests.

The controller accepts explicit frontend decisions; its library never opens
=/dev/tty=. Each session has a cancellable worker for startup and sequential grants while
the daemon continues serving other sessions and frontends. The internal
client depends only on shared protocol code, with no host policy or mount API.
There is no production Python executable or mandatory Python interpreter.

Use Org mode (=.org=) for repository documentation, including plans, design
notes, and experiment reports.

This rewrite preserves PoC commit =c2a9d42= as its behavioral reference. It does
not implement multiplexing, file/network live grants, or
daemon restart recovery. Closing frontends leaves sessions alive; daemon death
stops every helper and sandbox;
abrupt death may leave host session directories and GC roots for manual cleanup.
